# Vulkan Orbiting Spheres — 12-Agent Audit Findings

## Context
The vulkan-orbiting-spheres program (~1,790 lines C++/GLSL) needed a comprehensive error and issue review. A 12-agent team was deployed across 4 specialized teams (API correctness, shader/pipeline, memory/performance, application logic/build) to audit the codebase simultaneously.

## Method
- 12 agents launched in a single wave (SOP-011 compliant)
- Each agent given a focused area with specific files and checklist
- Agents ran in isolated git worktrees to prevent conflicts
- Reports collected in standardized JSON format (SOP-016)
- Post-operation deduplication reduced 149 raw findings to 42 unique issues

## Result
**42 unique findings: 0 critical, 6 high, 16 medium, 20 low**

### Top Bugs Found
1. **Fence deadlock (HIGH)**: When vkAcquireNextImageKHR returns OUT_OF_DATE, the fence is consumed but never re-signaled, hanging the app on next frame. Fix: move vkResetFences after acquire check.
2. **Wrong specular highlights (HIGH)**: Fragment shader viewDir uses normalize(-fragWorldPos) assuming camera at origin. Camera orbits at distance 6+. Camera position never passed to shader.
3. **Init failure leaks everything (HIGH)**: If initVulkan() throws, cleanup() is never called. cleanup() is also unsafe for partial initialization.
4. **10+ unchecked VkResult returns (HIGH)**: vmaCreateImage, vkCreateImageView, vmaCreateBuffer, vmaMapMemory all unchecked — any failure causes silent crash.

### Verified Correct
- Vulkan init/destroy order, UBO std140 layout, descriptor pool sizing
- Vertex attributes, render pass config, depth test, rasterization state
- Sphere geometry, camera math, model matrix composition

## Lessons Learned
1. **Synchronization bugs are subtle**: The fence deadlock was only caught by the sync specialist (A2) who traced the full signal/wait chain across the early-return path.
2. **Error checking is the #1 systemic issue**: 7 of 12 agents independently flagged missing VkResult checks.
3. **Shader math requires domain expertise**: The viewDir bug required understanding both the shader math and the camera behavior.
4. **12 agents on ~1,800 lines produces heavy duplication**: 149 raw → 42 unique (72% duplication). For this size, 6-8 agents would be more efficient.
5. **Worktree isolation worked well**: No conflicts between agents despite all reading the same files.

## Recommendations
1. **Fix HIGH findings first**: Fence deadlock (SYNC-001) and viewDir (SHADER-001) are the most impactful.
2. **Add systematic error checking**: Create a helper macro for VkResult checking.
3. **For future Vulkan audits**: Pair sync specialist with shader specialist — these found the most impactful unique bugs.
4. **Optimal agent count**: For ~2,000 line Vulkan programs, 8 agents across 3 teams is the sweet spot.
