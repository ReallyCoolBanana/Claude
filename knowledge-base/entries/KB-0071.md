# Python Filesystem Watcher Daemon with Watchdog for Knowledge Graph Processing

## Context

Research for building a daemon that watches a directory tree of ~50K-100K small JSON files
on a Linux home PC (Ubuntu/Pop!_OS) and automatically processes changes by calling a
FastAPI service. This is for a knowledge graph system where files represent nodes/edges
and changes must be reflected in an API-accessible graph.

Covers: watchdog setup, event filtering, debouncing, batch processing, FastAPI integration,
inotify limits, systemd service, error handling with retry/dead-letter, polling and SQLite
alternatives, memory at scale, testing, and a complete production-ready example.

---

## 1. Basic Watchdog Setup -- Observer + FileSystemEventHandler

```python
"""Minimal watchdog example: Observer + FileSystemEventHandler."""
from watchdog.observers import Observer
from watchdog.events import FileSystemEventHandler
import time


class JsonHandler(FileSystemEventHandler):
    def on_created(self, event):
        if event.is_directory:
            return
        print(f"Created: {event.src_path}")

    def on_modified(self, event):
        if event.is_directory:
            return
        print(f"Modified: {event.src_path}")

    def on_deleted(self, event):
        if event.is_directory:
            return
        print(f"Deleted: {event.src_path}")

    def on_moved(self, event):
        print(f"Moved: {event.src_path} -> {event.dest_path}")


if __name__ == "__main__":
    handler = JsonHandler()
    observer = Observer()
    observer.schedule(handler, path="/data/knowledge-graph", recursive=True)
    observer.start()
    try:
        while True:
            time.sleep(1)
    except KeyboardInterrupt:
        observer.stop()
    observer.join()
```

Key points:
- `Observer` uses inotify on Linux (kernel-level, no polling).
- `recursive=True` watches all subdirectories. Watchdog adds one inotify watch per
  **directory** (not per file).
- The observer runs in a daemon thread. The main thread just sleeps.
- The observer also supports context manager usage (`with observer:`) in recent versions.

## 2. Filtering Events -- Only React to .json in Specific Directories

Use `PatternMatchingEventHandler` for glob-based filtering, or filter manually:

```python
from watchdog.events import PatternMatchingEventHandler
from pathlib import Path


class JsonOnlyHandler(PatternMatchingEventHandler):
    """Only react to .json files in specific directory prefixes."""

    def __init__(self, allowed_dirs: set[str]):
        super().__init__(
            patterns=["*.json"],
            ignore_patterns=["*.tmp", "*.swp", "*~", "*.json.bak"],
            ignore_directories=True,
            case_sensitive=True,
        )
        self.allowed_dirs = allowed_dirs

    def on_any_event(self, event):
        parent = str(Path(event.src_path).parent)
        if not any(parent.startswith(d) for d in self.allowed_dirs):
            return
        super().on_any_event(event)

    def on_modified(self, event):
        print(f"JSON modified: {event.src_path}")

    def on_created(self, event):
        print(f"JSON created: {event.src_path}")

    def on_deleted(self, event):
        print(f"JSON deleted: {event.src_path}")
```

`PatternMatchingEventHandler` does fnmatch internally. The `ignore_patterns` list
prevents reacting to editor temp files and backup files. The `allowed_dirs` check
in `on_any_event` gates events before they reach the specific `on_*` methods.

## 3. Debouncing -- Handling Duplicate Events

Watchdog fires multiple events for a single file save. A typical editor save produces:
- vim: CREATED (temp), MODIFIED, MOVED_FROM, MOVED_TO (atomic rename)
- VSCode: CREATED, MODIFIED, MODIFIED (writes in chunks)
- echo "..." > file: CREATED, MODIFIED (or just MODIFIED if file exists)

Without debouncing, a single save processes the same file 2-6 times.

### Strategy A: Simple per-file cooldown (drop duplicates within window)

```python
import time
import threading
from watchdog.events import FileSystemEventHandler


class CooldownHandler(FileSystemEventHandler):
    """Drop events for the same path within cooldown_seconds."""

    def __init__(self, callback, cooldown_seconds: float = 0.5):
        super().__init__()
        self._callback = callback
        self._cooldown = cooldown_seconds
        self._last_seen: dict[str, float] = {}
        self._lock = threading.Lock()

    def on_any_event(self, event):
        if event.is_directory:
            return
        now = time.monotonic()
        with self._lock:
            last = self._last_seen.get(event.src_path, 0.0)
            if now - last < self._cooldown:
                return  # Skip duplicate
            self._last_seen[event.src_path] = now
        self._callback(event)
```

Fast but imprecise: the first event fires immediately, subsequent ones within the
window are dropped. If a CREATED event fires and the file isn't fully written yet,
your callback may read a partial file.

### Strategy B: Settle-based debounce (wait for quiet period)

Better for correctness. Accumulate events, fire only after the file has been "quiet"
for N seconds:

```python
import threading
from watchdog.events import FileSystemEventHandler


class SettleDebouncer(FileSystemEventHandler):
    """
    Wait until a file has been quiet for `settle_seconds` before firing.
    Each new event for the same path resets the timer.
    """

    def __init__(self, callback, settle_seconds: float = 1.0):
        super().__init__()
        self._callback = callback
        self._settle = settle_seconds
        self._timers: dict[str, threading.Timer] = {}
        self._last_event: dict[str, object] = {}
        self._lock = threading.Lock()

    def on_any_event(self, event):
        if event.is_directory:
            return
        path = event.src_path
        with self._lock:
            if path in self._timers:
                self._timers[path].cancel()
            self._last_event[path] = event
            timer = threading.Timer(self._settle, self._fire, args=[path])
            timer.daemon = True
            self._timers[path] = timer
            timer.start()

    def _fire(self, path: str):
        with self._lock:
            event = self._last_event.pop(path, None)
            self._timers.pop(path, None)
        if event:
            self._callback(event)

    def shutdown(self):
        with self._lock:
            for timer in self._timers.values():
                timer.cancel()
            self._timers.clear()
```

Slower to react (adds settle_seconds latency) but guarantees the file has stopped
changing. Best combined with batch processing (section 4).

### Strategy C: Batch accumulation (recommended for knowledge graphs)

Instead of debouncing individual files, collect all events into a set over a time
window. Since sets deduplicate by path, rapid CREATE+MODIFY for the same file
collapses automatically. See section 4.

## 4. Batch Processing -- Collect Changes, Flush Every N Seconds

This is the right pattern for a knowledge graph: you do not want to call the API 50
times when `git pull` touches hundreds of files at once.

```python
import threading
import logging
from dataclasses import dataclass, field
from pathlib import Path
from watchdog.events import FileSystemEventHandler

log = logging.getLogger(__name__)


@dataclass
class ChangeBatch:
    created: set[str] = field(default_factory=set)
    modified: set[str] = field(default_factory=set)
    deleted: set[str] = field(default_factory=set)

    @property
    def is_empty(self) -> bool:
        return not (self.created or self.modified or self.deleted)

    def __len__(self) -> int:
        return len(self.created) + len(self.modified) + len(self.deleted)


class BatchingHandler(FileSystemEventHandler):
    """
    Collect file changes into a ChangeBatch and flush them at a fixed interval.
    Deduplication is inherent: sets collapse rapid events for the same path.
    """

    def __init__(
        self,
        flush_callback,     # callable(ChangeBatch) -> None
        interval: float = 5.0,
        patterns: set[str] | None = None,
    ):
        super().__init__()
        self._flush_callback = flush_callback
        self._interval = interval
        self._patterns = patterns or {"*.json"}
        self._batch = ChangeBatch()
        self._lock = threading.Lock()
        self._stop_event = threading.Event()
        self._flush_thread = threading.Thread(
            target=self._flush_loop, daemon=True, name="batch-flusher"
        )
        self._flush_thread.start()

    def _matches(self, path: str) -> bool:
        p = Path(path)
        return any(p.match(pat) for pat in self._patterns)

    def on_created(self, event):
        if event.is_directory or not self._matches(event.src_path):
            return
        with self._lock:
            self._batch.created.add(event.src_path)

    def on_modified(self, event):
        if event.is_directory or not self._matches(event.src_path):
            return
        with self._lock:
            # If already in created set, don't also add to modified
            if event.src_path not in self._batch.created:
                self._batch.modified.add(event.src_path)

    def on_deleted(self, event):
        if event.is_directory or not self._matches(event.src_path):
            return
        with self._lock:
            self._batch.deleted.add(event.src_path)
            # Clean up: if file was created then deleted in same batch, cancel both
            self._batch.created.discard(event.src_path)
            self._batch.modified.discard(event.src_path)

    def on_moved(self, event):
        if event.is_directory:
            return
        # Treat move as delete(src) + create(dest)
        if self._matches(event.src_path):
            with self._lock:
                self._batch.deleted.add(event.src_path)
                self._batch.created.discard(event.src_path)
                self._batch.modified.discard(event.src_path)
        if self._matches(event.dest_path):
            with self._lock:
                self._batch.created.add(event.dest_path)

    def _flush_loop(self):
        while not self._stop_event.wait(timeout=self._interval):
            self.flush()

    def flush(self):
        with self._lock:
            if self._batch.is_empty:
                return
            batch = self._batch
            self._batch = ChangeBatch()

        log.info("Flushing batch: %d changes", len(batch))
        try:
            self._flush_callback(batch)
        except Exception:
            log.exception("Flush callback failed")

    def shutdown(self):
        self._stop_event.set()
        self._flush_thread.join(timeout=5)
        self.flush()  # Final flush of remaining events
```

Design notes:
- The flush thread uses `Event.wait(timeout=interval)` rather than `time.sleep()`.
  This allows immediate wake on shutdown instead of sleeping through the full interval.
- The lock is held only briefly (set operations). Flush callback runs outside the lock.
- `on_moved` is decomposed into delete + create. This handles atomic-rename saves
  from editors like vim.

## 5. Integration with a FastAPI Service

```python
import httpx
import logging
from tenacity import (
    retry, stop_after_attempt, wait_exponential,
    retry_if_exception_type,
)

log = logging.getLogger(__name__)

# Persistent client with connection pooling
_client = httpx.Client(
    base_url="http://127.0.0.1:8000",
    timeout=httpx.Timeout(30.0, connect=5.0),
    limits=httpx.Limits(max_connections=10, max_keepalive_connections=5),
)


@retry(
    stop=stop_after_attempt(5),
    wait=wait_exponential(multiplier=1, min=2, max=60),
    retry=retry_if_exception_type(
        (httpx.ConnectError, httpx.TimeoutException, httpx.HTTPStatusError)
    ),
    before_sleep=lambda rs: log.warning(
        "Retry %d, waiting %.1fs", rs.attempt_number, rs.next_action.sleep
    ),
)
def _send_batch_to_api(batch: ChangeBatch) -> None:
    payload = {
        "created": sorted(batch.created),
        "modified": sorted(batch.modified),
        "deleted": sorted(batch.deleted),
    }
    resp = _client.post("/graph/batch-update", json=payload)
    resp.raise_for_status()
    log.info("API accepted batch: %d changes", len(batch))
```

The `tenacity` decorator retries on connection errors and HTTP 5xx (which raise
`HTTPStatusError` after `raise_for_status()`). Exponential backoff: 2s, 4s, 8s, 16s, 32s.
Total worst-case wait: ~62 seconds before giving up.

### Corresponding FastAPI endpoint

```python
from fastapi import FastAPI
from pydantic import BaseModel
```

## 6. Recursive Watching and inotify Limits

### How watchdog uses inotify

Watchdog adds **one inotify watch per directory** (not per file). For 50K files in
1,000 directories, you need ~1,000 watches. For 50K files in 50K directories
(one file each), you need ~50K watches.

### Checking current limits

```bash
# Current max watches per user (default: 8192 or 65536 depending on distro)
cat /proc/sys/fs/inotify/max_user_watches

# Current max instances per user (default: 128)
cat /proc/sys/fs/inotify/max_user_instances
```

### Setting inotify limits

```bash
# Temporary (resets on reboot)
sudo sysctl fs.inotify.max_user_watches=524288
sudo sysctl fs.inotify.max_user_instances=1024

# Permanent: create sysctl config
cat <<'EOF' | sudo tee /etc/sysctl.d/60-inotify.conf
fs.inotify.max_user_watches=524288
fs.inotify.max_user_instances=1024
EOF
sudo sysctl --system
```

### Memory cost of inotify watches

Each inotify watch costs ~1 KB of **kernel** memory:
- 8,192 watches (default) = ~8 MB kernel memory
- 524,288 watches = ~540 MB kernel memory
- For a home PC with 16-64 GB RAM, 524,288 is fine.

### Practical estimate for 50K-100K files

If your knowledge graph has ~5,000 directories containing 50K-100K files,
you need ~5,000 inotify watches. The default limit of 8,192 is sufficient.
If you have deeply nested per-file directories (one directory per file),
raise the limit to 524,288.

## 7. Graceful Shutdown with Signal Handling

```python
import signal
import sys
import logging
from watchdog.observers import Observer

log = logging.getLogger(__name__)


class WatcherDaemon:
    def __init__(self, watch_path: str, handler):
        self.observer = Observer()
        self.observer.schedule(handler, path=watch_path, recursive=True)
        self._handler = handler

    def run(self):
        # Register signal handlers (delivered to main thread only)
        signal.signal(signal.SIGTERM, self._handle_signal)
        signal.signal(signal.SIGINT, self._handle_signal)

        self.observer.start()
        log.info("Watcher started, watching %s", self.observer)

        try:
            # observer.join(timeout) returns periodically so signals can be handled
            while self.observer.is_alive():
                self.observer.join(timeout=1)
        except SystemExit:
            pass
        finally:
            self._shutdown()

    def _handle_signal(self, signum, frame):
        signame = signal.Signals(signum).name
        log.info("Received %s, shutting down...", signame)
        raise SystemExit(0)

    def _shutdown(self):
        log.info("Stopping observer...")
        self.observer.stop()
        self.observer.join(timeout=10)

        if hasattr(self._handler, "shutdown"):
            log.info("Flushing final batch...")
            self._handler.shutdown()

        log.info("Shutdown complete.")
```

Key design points:
- `observer.join(timeout=1)` instead of `time.sleep(1)`: lets the main thread
  wake up to handle signals promptly.
- `raise SystemExit(0)` in the signal handler: unwinds the stack cleanly so
  the `finally` block runs.
- `handler.shutdown()` flushes any pending batch before exit.

## 8. Running as a systemd Service

### Unit file: `/etc/systemd/system/kg-watcher.service`

```ini
[Unit]
Description=Knowledge Graph File Watcher
After=network.target

[Service]
Type=simple
User=youruser
Group=youruser
WorkingDirectory=/opt/kg-watcher
ExecStart=/opt/kg-watcher/venv/bin/python -m kg_watcher
Restart=on-failure
RestartSec=5
# Give 30s for graceful shutdown (flush pending batches)
TimeoutStopSec=30
# Environment
Environment=WATCH_PATH=/data/knowledge-graph
Environment=API_BASE_URL=http://127.0.0.1:8000
Environment=BATCH_INTERVAL=5
# Resource limits -- cap memory to catch the known watchdog leak
MemoryMax=512M
# Logging goes to journald
StandardOutput=journal
StandardError=journal
SyslogIdentifier=kg-watcher

[Install]
WantedBy=multi-user.target
```

### Management commands

```bash
sudo systemctl daemon-reload
sudo systemctl enable kg-watcher        # start on boot
sudo systemctl start kg-watcher
sudo systemctl status kg-watcher
sudo journalctl -u kg-watcher -f        # tail logs
sudo journalctl -u kg-watcher --since "1 hour ago"
```

Design choices:
- `Type=simple` is correct because watchdog runs in the foreground.
- `Restart=on-failure` with `RestartSec=5` provides automatic restart on crashes.
- `TimeoutStopSec=30` gives the daemon time to flush its final batch after SIGTERM.
- `MemoryMax=512M` prevents runaway memory from the known inotify leak. When
  exceeded, systemd kills the process and `Restart=on-failure` restarts it.

## 9. Error Handling -- When the API is Down

Three layers of defense:

### Layer 1: tenacity retries (section 5)

Exponential backoff up to 5 attempts (~62s total). Handles transient failures like
brief network blips or API restarts.

### Layer 2: Dead-letter queue on disk

When retries exhaust, persist the failed batch to a JSON file for later replay:

```python
import json
import time
from pathlib import Path

DEAD_LETTER_DIR = Path("/var/lib/kg-watcher/dead-letter")


def flush_with_dead_letter(batch: ChangeBatch) -> None:
    try:
        _send_batch_to_api(batch)
    except Exception:
        DEAD_LETTER_DIR.mkdir(parents=True, exist_ok=True)
        dl_path = DEAD_LETTER_DIR / f"batch-{int(time.time() * 1000)}.json"
        dl_path.write_text(json.dumps({
            "timestamp": time.time(),
            "created": sorted(batch.created),
            "modified": sorted(batch.modified),
            "deleted": sorted(batch.deleted),
        }, indent=2))
        log.error("API unreachable, dead-lettered to %s", dl_path)
```

### Layer 3: Circuit breaker (optional)

If the API has been down for N consecutive batches, stop trying and only write to
disk. Resume API calls after a cooldown period:

```python
import time


class CircuitBreaker:
    def __init__(self, failure_threshold: int = 3, reset_timeout: float = 60.0):
        self.failure_threshold = failure_threshold
        self.reset_timeout = reset_timeout
        self.failures = 0
        self.last_failure_time = 0.0
        self.state = "closed"  # closed=normal, open=failing

    def record_success(self):
        self.failures = 0
        self.state = "closed"

    def record_failure(self):
        self.failures += 1
        self.last_failure_time = time.monotonic()
        if self.failures >= self.failure_threshold:
            self.state = "open"

    @property
    def allow_request(self) -> bool:
        if self.state == "closed":
            return True
        # Half-open: try again after reset_timeout
        if time.monotonic() - self.last_failure_time > self.reset_timeout:
            return True
        return False
```

### Replay dead-letter files on startup or periodically

```python
def replay_dead_letters() -> None:
    """Replay any dead-letter batches. Call on startup."""
    if not DEAD_LETTER_DIR.exists():
        return
    for dl_path in sorted(DEAD_LETTER_DIR.glob("batch-*.json")):
        data = json.loads(dl_path.read_text())
        batch = ChangeBatch(
            created=set(data["created"]),
            modified=set(data["modified"]),
            deleted=set(data["deleted"]),
        )
        try:
            _send_batch_to_api(batch)
            dl_path.unlink()  # Remove on success
            log.info("Replayed dead-letter %s", dl_path.name)
        except Exception:
            log.warning("Replay failed for %s, stopping replay", dl_path.name)
            break  # Stop on first failure, maintain ordering
```

## 10. Alternative: Polling with os.scandir() + mtime Comparison

When polling is better than watchdog:
- **Network/CIFS/NFS mounts** where inotify does not work
- **Zero-dependency deployments** where you cannot install watchdog
- **Low-frequency checks** (every 30-60s) where real-time is not needed
- **Avoiding the watchdog memory leak** for very long-running daemons

```python
import os
import time
import logging
from pathlib import Path
from dataclasses import dataclass

log = logging.getLogger(__name__)


@dataclass
class FileState:
    mtime: float
    size: int


def scan_directory(root: Path, suffix: str = ".json") -> dict[str, FileState]:
    """
    Recursively scan directory, return {path: FileState} for matching files.
    os.scandir is faster than os.listdir + os.stat because DirEntry.stat()
    avoids an extra syscall on Linux (getdents64 returns d_type, stat is cached).
    """
    result = {}
    stack = [root]
    while stack:
        current = stack.pop()
        try:
            with os.scandir(current) as entries:
                for entry in entries:
                    if entry.is_dir(follow_symlinks=False):
                        stack.append(Path(entry.path))
                    elif entry.name.endswith(suffix):
                        stat = entry.stat(follow_symlinks=False)
                        result[entry.path] = FileState(
                            mtime=stat.st_mtime, size=stat.st_size
                        )
        except PermissionError:
            log.warning("Permission denied: %s", current)
    return result


class PollingWatcher:
    """
    Poll-based file watcher using os.scandir + mtime comparison.

    Performance on SSD (ext4, warm cache):
      10,000 files:  ~30ms per scan,  ~5 MB memory
      50,000 files:  ~150ms per scan, ~25 MB memory
      100,000 files: ~300ms per scan, ~50 MB memory
    """

    def __init__(self, root: str, callback, interval: float = 30.0,
                 suffix: str = ".json"):
        self.root = Path(root)
        self.callback = callback
        self.interval = interval
        self.suffix = suffix
        self._previous: dict[str, FileState] = {}
        self._running = False

    def run(self):
        self._running = True
        self._previous = scan_directory(self.root, self.suffix)
        log.info("Initial scan: %d files", len(self._previous))

        while self._running:
            time.sleep(self.interval)
            if not self._running:
                break
            current = scan_directory(self.root, self.suffix)
            self._diff_and_notify(current)
            self._previous = current

    def stop(self):
        self._running = False

    def _diff_and_notify(self, current: dict[str, FileState]):
        prev_keys = set(self._previous)
        curr_keys = set(current)

        created = curr_keys - prev_keys
        deleted = prev_keys - curr_keys
        modified = {
            p for p in (curr_keys & prev_keys)
            if (current[p].mtime != self._previous[p].mtime
                or current[p].size != self._previous[p].size)
        }

        if created or modified or deleted:
            batch = ChangeBatch(created=created, modified=modified, deleted=deleted)
            log.info("Poll detected %d changes", len(batch))
            try:
                self.callback(batch)
            except Exception:
                log.exception("Callback failed")
```

## 11. Alternative: SQLite WAL Change Tracking

If your knowledge graph data is already in SQLite (or you can move it there), skip
filesystem watching entirely and use triggers. This is the most reliable approach.

```python
import sqlite3
import time
import logging

log = logging.getLogger(__name__)


class SQLiteChangeTracker:
    """
    Track changes via SQLite triggers + a changes table.
    More reliable than filesystem watching: no duplicate events, atomic with
    the data write, no inotify limits, ordering guaranteed.
    """

    SETUP_SQL = """
    CREATE TABLE IF NOT EXISTS kg_changes (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        table_name TEXT NOT NULL,
        row_id INTEGER NOT NULL,
        operation TEXT NOT NULL,  -- INSERT, UPDATE, DELETE
        timestamp REAL NOT NULL DEFAULT (unixepoch('subsec')),
        processed INTEGER NOT NULL DEFAULT 0
    );

    CREATE INDEX IF NOT EXISTS idx_changes_unprocessed
        ON kg_changes(processed) WHERE processed = 0;

    -- Example triggers for a 'nodes' table
    CREATE TRIGGER IF NOT EXISTS trg_nodes_insert AFTER INSERT ON nodes
    BEGIN
        INSERT INTO kg_changes(table_name, row_id, operation)
        VALUES ('nodes', NEW.id, 'INSERT');
    END;

    CREATE TRIGGER IF NOT EXISTS trg_nodes_update AFTER UPDATE ON nodes
    BEGIN
        INSERT INTO kg_changes(table_name, row_id, operation)
        VALUES ('nodes', NEW.id, 'UPDATE');
    END;

    CREATE TRIGGER IF NOT EXISTS trg_nodes_delete AFTER DELETE ON nodes
    BEGIN
        INSERT INTO kg_changes(table_name, row_id, operation)
        VALUES ('nodes', OLD.id, 'DELETE');
    END;
    """

    def __init__(self, db_path: str, callback, poll_interval: float = 2.0):
        self.db_path = db_path
        self.callback = callback
        self.poll_interval = poll_interval
        self._running = False

    def setup(self):
        with sqlite3.connect(self.db_path) as conn:
            conn.executescript(self.SETUP_SQL)

    def run(self):
        self._running = True
        while self._running:
            self._process_changes()
            time.sleep(self.poll_interval)

    def stop(self):
        self._running = False

    def _process_changes(self):
        with sqlite3.connect(self.db_path) as conn:
            conn.execute("BEGIN IMMEDIATE")
            rows = conn.execute(
                "SELECT id, table_name, row_id, operation "
                "FROM kg_changes WHERE processed = 0 ORDER BY id"
            ).fetchall()
            if not rows:
                conn.execute("COMMIT")
                return

            change_ids = [r[0] for r in rows]
            placeholders = ",".join("?" * len(change_ids))
            conn.execute(
                f"UPDATE kg_changes SET processed = 1 WHERE id IN ({placeholders})",
                change_ids,
            )
            conn.execute("COMMIT")

        try:
            self.callback(rows)
        except Exception:
            log.exception("Change callback failed for %d changes", len(rows))
```

Advantages over filesystem watching:
- **No duplicate events** -- one trigger per write, guaranteed.
- **Atomic** -- the change record is committed with the data write.
- **No inotify limits** -- works on any OS, any filesystem.
- **Batching is free** -- just query all unprocessed changes.
- **Ordering guaranteed** -- changes have sequential IDs.
- **Works with WAL mode** -- readers do not block writers.

Disadvantage: only works if you control the write path (all writes go through
your application's SQLite layer, not raw file edits by other tools).

## 12. Memory Usage of Watchdog at Scale

| Component             | 100K files, ~5K dirs | Notes                              |
|-----------------------|---------------------|------------------------------------|
| inotify watches       | ~5 MB kernel memory | ~1 KB per watch, 5K dirs           |
| Python Observer       | ~20-50 MB RSS       | Baseline Python + watchdog         |
| Event buffer leak     | +1-5 MB/hour        | Known issue #587, events not GC'd  |
| Debounce timers       | ~1 MB               | Dict of path -> Timer              |
| Batch accumulator     | ~1-5 MB             | Sets of string paths               |
| **Total steady-state**| **~30-60 MB**       | Before leak accumulation           |

### The known memory leak (watchdog issue #587)

`InotifyEvent` objects accumulate in `inotify_c.py` and are not garbage collected
until the Observer is stopped. For a daemon processing thousands of events per hour,
this can add up to hundreds of MB over days.

Mitigations:
1. **MemoryMax in systemd** (section 8): cap at 512M, let systemd restart.
2. **Periodic observer restart**: stop and recreate the observer every 6 hours.
3. **Use `watchfiles` instead**: Rust-based, no leak, lower memory overall.
4. **Use the patched fork**: `watchdog-v6-without-memory-leak-adi` on PyPI.

## 13. Testing Watchdog Handlers

Handlers are plain Python classes. Test them by constructing event objects directly
-- no Observer or filesystem needed:

```python
import pytest
from unittest.mock import MagicMock
from watchdog.events import (
    FileCreatedEvent, FileModifiedEvent,
    FileDeletedEvent, DirCreatedEvent,
)


class TestBatchingHandler:
    def setup_method(self):
        self.callback = MagicMock()
        self.handler = BatchingHandler(
            flush_callback=self.callback,
            interval=999,  # Don't auto-flush in tests
            patterns={"*.json"},
        )

    def teardown_method(self):
        self.handler.shutdown()

    def test_json_file_created(self):
        event = FileCreatedEvent(src_path="/data/nodes/abc.json")
        self.handler.on_created(event)
        self.handler.flush()
        batch = self.callback.call_args[0][0]
        assert "/data/nodes/abc.json" in batch.created

    def test_non_json_ignored(self):
        event = FileCreatedEvent(src_path="/data/nodes/abc.txt")
        self.handler.on_created(event)
        self.handler.flush()
        self.callback.assert_not_called()

    def test_directory_events_ignored(self):
        event = DirCreatedEvent(src_path="/data/nodes/subdir")
        self.handler.on_created(event)
        self.handler.flush()
        self.callback.assert_not_called()

    def test_create_then_modify_deduped(self):
        """CREATE + MODIFY for same file should only appear in created set."""
        self.handler.on_created(FileCreatedEvent("/data/a.json"))
        self.handler.on_modified(FileModifiedEvent("/data/a.json"))
        self.handler.flush()
        batch = self.callback.call_args[0][0]
        assert "/data/a.json" in batch.created
        assert "/data/a.json" not in batch.modified

    def test_create_then_delete_cancels(self):
        """CREATE + DELETE in same batch: file appears in deleted only."""
        self.handler.on_created(FileCreatedEvent("/data/a.json"))
        self.handler.on_deleted(FileDeletedEvent("/data/a.json"))
        self.handler.flush()
        batch = self.callback.call_args[0][0]
        assert "/data/a.json" not in batch.created
        assert "/data/a.json" in batch.deleted

    def test_settle_debouncer(self):
        """SettleDebouncer fires once after rapid events settle."""
        import time
        cb = MagicMock()
        debouncer = SettleDebouncer(callback=cb, settle_seconds=0.1)
        for _ in range(5):
            debouncer.on_any_event(FileModifiedEvent("/data/x.json"))
        time.sleep(0.3)
        assert cb.call_count == 1
        debouncer.shutdown()
```

```python
import tempfile
import time

def test_real_filesystem_integration():
    results = []

        results.append(batch)
```

## 14. watchfiles as a Modern Alternative

`watchfiles` (by Samuel Colvin, author of Pydantic) is written in Rust and avoids
many watchdog issues:

```python
# pip install watchfiles
from watchfiles import watch, Change

for changes in watch("/data/knowledge-graph", recursive=True):
    for change_type, path in changes:
        if not path.endswith(".json"):
            continue
        if change_type == Change.added:
            print(f"Created: {path}")
        elif change_type == Change.modified:
            print(f"Modified: {path}")
        elif change_type == Change.deleted:
            print(f"Deleted: {path}")
```

Advantages:
- **Built-in debouncing** (50ms window, configurable up to 1600ms)
- **No memory leak**
- **Significantly lower CPU usage** (Rust core)
- **Returns a set of changes** (natural batching per iteration)
- **Simpler API**

Disadvantage: smaller ecosystem, fewer examples online.

## 15. Complete Production-Ready Example

```python
#!/usr/bin/env python3
"""
kg_watcher -- Knowledge Graph File Watcher Daemon

Watches a directory tree for JSON file changes and sends batched updates
to a FastAPI knowledge graph service.

Usage:
    python -m kg_watcher

Environment:
    WATCH_PATH       Directory to watch (default: /data/knowledge-graph)
    API_BASE_URL     FastAPI base URL (default: http://127.0.0.1:8000)
    BATCH_INTERVAL   Seconds between batch flushes (default: 5)
    LOG_LEVEL        Logging level (default: INFO)
    DEAD_LETTER_DIR  Failed batch storage (default: /var/lib/kg-watcher/dead-letter)
"""

import json
import logging
import os
import signal
import sys
import threading
import time
from dataclasses import dataclass, field
from pathlib import Path

import httpx
from tenacity import (
    retry, stop_after_attempt, wait_exponential,
    retry_if_exception_type,
)
from watchdog.events import FileSystemEventHandler
from watchdog.observers import Observer

# ---------------------------------------------------------------------------
# Configuration
# ---------------------------------------------------------------------------

WATCH_PATH = os.environ.get("WATCH_PATH", "/data/knowledge-graph")
API_BASE_URL = os.environ.get("API_BASE_URL", "http://127.0.0.1:8000")
BATCH_INTERVAL = float(os.environ.get("BATCH_INTERVAL", "5"))
LOG_LEVEL = os.environ.get("LOG_LEVEL", "INFO")
DEAD_LETTER_DIR = Path(os.environ.get(
    "DEAD_LETTER_DIR", "/var/lib/kg-watcher/dead-letter"
))

logging.basicConfig(
    level=getattr(logging, LOG_LEVEL),
    format="%(asctime)s [%(levelname)s] %(name)s: %(message)s",
    datefmt="%Y-%m-%dT%H:%M:%S",
)
log = logging.getLogger("kg_watcher")


# ---------------------------------------------------------------------------
# Data structures
# ---------------------------------------------------------------------------

@dataclass
class ChangeBatch:
    created: set[str] = field(default_factory=set)
    modified: set[str] = field(default_factory=set)
    deleted: set[str] = field(default_factory=set)

    @property
    def is_empty(self) -> bool:
        return not (self.created or self.modified or self.deleted)

    def __len__(self) -> int:
        return len(self.created) + len(self.modified) + len(self.deleted)


# ---------------------------------------------------------------------------
# API client with retry + dead-letter
# ---------------------------------------------------------------------------

_http_client: httpx.Client | None = None


def _get_client() -> httpx.Client:
    global _http_client
    if _http_client is None:
        _http_client = httpx.Client(
            base_url=API_BASE_URL,
            timeout=httpx.Timeout(30.0, connect=5.0),
            limits=httpx.Limits(max_connections=10, max_keepalive_connections=5),
        )
    return _http_client


@retry(
    stop=stop_after_attempt(5),
    wait=wait_exponential(multiplier=1, min=2, max=60),
    retry=retry_if_exception_type(
        (httpx.ConnectError, httpx.TimeoutException, httpx.HTTPStatusError)
    ),
    before_sleep=lambda rs: log.warning(
        "Retry %d, waiting %.1fs", rs.attempt_number, rs.next_action.sleep
    ),
)
def _send_to_api(batch: ChangeBatch) -> None:
    payload = {
        "created": sorted(batch.created),
        "modified": sorted(batch.modified),
        "deleted": sorted(batch.deleted),
    }
    resp = _get_client().post("/graph/batch-update", json=payload)
    resp.raise_for_status()
    log.info("API accepted %d changes", len(batch))


def _save_dead_letter(batch: ChangeBatch) -> None:
    DEAD_LETTER_DIR.mkdir(parents=True, exist_ok=True)
    dl_path = DEAD_LETTER_DIR / f"batch-{int(time.time() * 1000)}.json"
    dl_path.write_text(json.dumps({
        "timestamp": time.time(),
        "created": sorted(batch.created),
        "modified": sorted(batch.modified),
        "deleted": sorted(batch.deleted),
    }, indent=2))
    log.warning("Dead-lettered to %s", dl_path)


def flush_batch(batch: ChangeBatch) -> None:
    """Send batch to API; fall back to dead-letter on total failure."""
    try:
        _send_to_api(batch)
    except Exception:
        log.exception("API unreachable after retries")
        _save_dead_letter(batch)


def replay_dead_letters() -> None:
    """Replay dead-letter batches. Call on startup."""
    if not DEAD_LETTER_DIR.exists():
        return
    for dl_path in sorted(DEAD_LETTER_DIR.glob("batch-*.json")):
        data = json.loads(dl_path.read_text())
        batch = ChangeBatch(
            created=set(data.get("created", [])),
            modified=set(data.get("modified", [])),
            deleted=set(data.get("deleted", [])),
        )
        try:
            _send_to_api(batch)
            dl_path.unlink()
            log.info("Replayed dead-letter %s", dl_path.name)
        except Exception:
            log.warning("Replay failed for %s, stopping replay", dl_path.name)
            break


# ---------------------------------------------------------------------------
# Batching event handler
# ---------------------------------------------------------------------------

class BatchingJsonHandler(FileSystemEventHandler):
    def __init__(self, flush_callback, interval: float = 5.0):
        super().__init__()
        self._flush_callback = flush_callback
        self._interval = interval
        self._batch = ChangeBatch()
        self._lock = threading.Lock()
        self._stop_event = threading.Event()
        self._flusher = threading.Thread(
            target=self._flush_loop, daemon=True, name="batch-flusher"
        )
        self._flusher.start()

    @staticmethod
    def _is_json(path: str) -> bool:
        return path.endswith(".json") and not path.endswith(".json.bak")

    def on_created(self, event):
        if event.is_directory or not self._is_json(event.src_path):
            return
        with self._lock:
            self._batch.created.add(event.src_path)

    def on_modified(self, event):
        if event.is_directory or not self._is_json(event.src_path):
            return
        with self._lock:
            if event.src_path not in self._batch.created:
                self._batch.modified.add(event.src_path)

    def on_deleted(self, event):
        if event.is_directory or not self._is_json(event.src_path):
            return
        with self._lock:
            self._batch.deleted.add(event.src_path)
            self._batch.created.discard(event.src_path)
            self._batch.modified.discard(event.src_path)

    def on_moved(self, event):
        if event.is_directory:
            return
        if self._is_json(event.src_path):
            with self._lock:
                self._batch.deleted.add(event.src_path)
                self._batch.created.discard(event.src_path)
                self._batch.modified.discard(event.src_path)
        if self._is_json(event.dest_path):
            with self._lock:
                self._batch.created.add(event.dest_path)

    def _flush_loop(self):
        while not self._stop_event.wait(timeout=self._interval):
            self._flush()

    def _flush(self):
        with self._lock:
            if self._batch.is_empty:
                return
            batch = self._batch
            self._batch = ChangeBatch()
        log.info("Flushing: +%d ~%d -%d",
                 len(batch.created), len(batch.modified), len(batch.deleted))
        try:
            self._flush_callback(batch)
        except Exception:
            log.exception("Flush callback raised unexpectedly")

    def shutdown(self):
        self._stop_event.set()
        self._flusher.join(timeout=10)
        self._flush()


# ---------------------------------------------------------------------------
# Daemon with signal handling
# ---------------------------------------------------------------------------

class WatcherDaemon:
    def __init__(self):
        self.handler = BatchingJsonHandler(
            flush_callback=flush_batch,
            interval=BATCH_INTERVAL,
        )
        self.observer = Observer()
        self.observer.schedule(self.handler, path=WATCH_PATH, recursive=True)

    def run(self):
        signal.signal(signal.SIGTERM, self._signal_handler)
        signal.signal(signal.SIGINT, self._signal_handler)

        # Replay any dead-lettered batches from previous crashes
        replay_dead_letters()

        log.info("Starting watcher: path=%s interval=%.1fs api=%s",
                 WATCH_PATH, BATCH_INTERVAL, API_BASE_URL)
        self.observer.start()

        try:
            while self.observer.is_alive():
                self.observer.join(timeout=1)
        except SystemExit:
            pass
        finally:
            self._shutdown()

    def _signal_handler(self, signum, frame):
        log.info("Received %s", signal.Signals(signum).name)
        raise SystemExit(0)

    def _shutdown(self):
        log.info("Stopping observer...")
        self.observer.stop()
        self.observer.join(timeout=10)
        log.info("Flushing final batch...")
        self.handler.shutdown()
        if _http_client is not None:
            _http_client.close()
        log.info("Shutdown complete.")


# ---------------------------------------------------------------------------
# Entry point
# ---------------------------------------------------------------------------

def main():
    if not Path(WATCH_PATH).is_dir():
        log.error("Watch path does not exist: %s", WATCH_PATH)
        sys.exit(1)
    WatcherDaemon().run()


if __name__ == "__main__":
    main()
```

## Lessons Learned

1. **Debouncing is mandatory** -- editors produce 2-6 events per save. Without it
   you process the same file multiple times per save.
2. **Batch processing is essential at scale** -- calling an API per-file is
   impractical when git operations touch hundreds of files at once.
3. **inotify watches are per-directory, not per-file** -- for typical layouts with
   reasonable directory depth, the default limit (8192) is often sufficient.
4. **watchdog has a known memory leak** (issue #587) -- for long-running daemons,
   set MemoryMax in systemd or use watchfiles instead.
5. **Dead-letter queues prevent data loss** -- when the API is down, persist failed
   batches to disk and replay them on startup.
6. **Polling is not always worse** -- for 100K files at 30s intervals, os.scandir
   uses ~300ms CPU per scan. If sub-second latency is not needed, polling is simpler.
7. **SQLite triggers are the most reliable** -- if you control the write path,
   database-level change tracking eliminates all filesystem-watching complexity.

## Recommendations

- **For a home PC knowledge graph**: start with the complete example (section 15).
  Set inotify limit to 524288 in sysctl as a safety margin.
- **If memory leak becomes an issue**: switch to `watchfiles`.
- **If real-time is not needed**: use PollingWatcher (section 10) with 30s intervals.
- **If you move data to SQLite**: use SQLiteChangeTracker (section 11).
- **Always run as a systemd service** with Restart=on-failure and MemoryMax.
- **Always implement dead-letter queuing** for API failures.
