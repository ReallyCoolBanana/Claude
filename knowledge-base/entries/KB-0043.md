# CKAN/DKAN Open Data Integration & MCP Server Catalog

## Context
The repository had 41 data sources registered but no integration with CKAN/DKAN,
the dominant open data platform powering government portals worldwide (US Data.gov,
UK data.gov.uk, Canada, Australia, EU, Brazil, openAFRICA). Additionally, the
growing MCP (Model Context Protocol) server ecosystem had not been cataloged
despite its direct relevance to extending AI agent capabilities.

## Method

### Team Alpha: CKAN/DKAN Integration
- Researched the CKAN Action API v3 (`package_search` endpoint)
- Built `method_ckan.py` (DG-0010) following the existing data-gathering method pattern
- Parallel search across 7 portals using `ThreadPoolExecutor`
- Standardized output format: title, description, organization, tags, formats, resources, license
- No API key required; no external dependencies (pure stdlib)
- Registered 5 CKAN portals as data sources (SRC-0045 through SRC-0049)

### Team Beta: MCP Server Ecosystem Crawl
- Crawled Glama.ai, Smithery.ai, and the official MCP registry
- Cataloged 55 MCP servers across 15 categories
- 20 official (from modelcontextprotocol org) + 35 community servers
- Built `search_mcp.py` for keyword/category/official filtering
- Registered 2 MCP registries as data sources (SRC-0050, SRC-0051)

### Key CKAN API Details
- Endpoint: `{base_url}/api/3/action/package_search?q={query}&rows={n}`
- Response: `{"success": true, "result": {"count": N, "results": [...]}}`
- No built-in rate limiting (infrastructure-level); no auth for read-only
- DKAN is API-compatible with CKAN (same endpoint format, different tech stack)

## Result

### CKAN Search (DG-0010)
- **3/4 default portals working** in live test: US (26,762 datasets), Canada (2,650), Australia (10,689)
- UK timed out (handled gracefully with error reporting)
- ~5 second parallel search latency across 4 portals
- Rich metadata: formats (CSV, JSON, XML, NETCDF, HTML), organizations, licenses

### MCP Server Catalog
- **55 servers cataloged** across: database (11), dev-tool (8), search (5), web (4), productivity (8), communication (4), cloud (4), monitoring (3), api (2), geospatial (1), knowledge (1), ai-ml (1), reasoning (1), utility (1), filesystem (1)
- Key categories for AI agents: databases, search, web scraping, productivity tools

### New Data Sources Registered
- SRC-0045: US Data.gov (CKAN)
- SRC-0046: Canada Open Data (CKAN)
- SRC-0047: Australia data.gov.au (CKAN)
- SRC-0048: UK data.gov.uk (CKAN)
- SRC-0049: European Data Portal (CKAN)
- SRC-0050: Glama.ai MCP Registry
- SRC-0051: Smithery.ai MCP Registry

## Lessons Learned
1. CKAN portals vary significantly in response time (some timeout at 15s).
   Always use parallel search with per-portal error handling.
2. DKAN uses the same API as CKAN — no special handling needed.
3. MCP server ecosystem is growing fast; the catalog needs periodic refresh.
4. Government CKAN portals often have thousands of datasets matching common
   queries — use `rows` parameter to limit results.

## Recommendations
1. Add CKAN to the hybrid data-gathering method (DG-0004) as a 6th source.
2. Periodically re-crawl MCP registries to keep the catalog current.
3. Consider adding CKAN `tag_list` and `organization_list` endpoints for
   browsing portal contents without keyword search.
4. For MCP servers, test install commands and verify tool schemas to build
   a validated "works with Claude Code" compatibility list.

# Tools & Capabilities Roadmap

## Context
Think Tank Beta assessed the full tool/API landscape to determine what to build, adopt, or skip. The repo has 54 scripts but only 2 API tools and zero financial data integrations usable in real-time. The gap between 44 cataloged sources and usable tools is the primary bottleneck for domain output.

## Method
Inventoried all scripts (54), API tools (2), and sources (44). Ranked missing tools by domain-enabling impact. Surveyed external ecosystem for adoptable solutions (MCP servers, LightRAG, Agent Skills). Applied SOP-023 filter: does this tool enable domain output or is it infrastructure recursion?

## Result

### Top 5 Recommendations (Prioritized)
1. **Add financial MCP servers to .mcp.json** (ADOPT, effort: hours, impact: critical) -- Alpha Vantage, Yahoo Finance/Stockflow, and Financial Datasets MCP servers provide instant stock data access. This is the single highest-leverage action.
2. **Build SEC EDGAR data-gathering tool** (BUILD, effort: 1 day, impact: critical) -- Free, no-auth access to all US public company filings. No MCP server exists. Build method_sec_edgar.py.
3. **Build pick_logger tool** (BUILD, effort: hours, impact: high) -- Structured logging of market picks with entry price, thesis, confidence. Closes the research-to-tracking loop.
4. **Build FRED data-gathering tool** (BUILD, effort: hours, impact: high) -- 820,000+ economic time series for macro analysis context. Free API key, 120 req/min.
5. **Adopt LightRAG for KB retrieval** (ADOPT, effort: 2-3 days, impact: medium-high) -- Graph-enhanced retrieval leveraging our builds_on chains. Replaces TF-IDF search with relationship-aware queries.

### Build vs Adopt Decisions
| Item | Decision | Reasoning |
|------|----------|-----------|
| Financial data (prices, fundamentals) | ADOPT (MCP servers) | Pre-built servers exist; building scripts is redundant |
| SEC EDGAR | BUILD | No MCP server available; critical data source |
| FRED economic data | BUILD | No MCP server; straightforward REST API |
| pick_logger | BUILD | Domain-specific, no external tool fits |
| Knowledge graph retrieval | ADOPT (LightRAG) | Mature library (EMNLP 2025), fits our KB structure |
| Agent Skills packaging | BUILD | Content creation task, not software development |
| sop_consolidator, trace_propagator, zombie_reclaimer | SKIP | Infrastructure recursion per SOP-023 |

### New APIs Discovered (Not Yet Cataloged)
- **SEC EDGAR** (data.sec.gov) -- free, no auth, 10 req/sec
- **Financial Modeling Prep** (FMP) -- free tier 250 req/day, financial statements + DCF
- **EODHD** -- historical EOD data, 20 req/day free
- **Twelve Data** -- intraday/historical prices, 800 req/day free

### New Techniques Worth Adopting
- **MCP Financial Data Servers** -- instant financial data via .mcp.json config (critical)
- **LightRAG** -- graph-enhanced RAG for KB retrieval (high)
- **Agent Skills** -- package domain workflows as reusable .skill.md files (high)
- **MCP Apps** -- interactive UI in conversation; future-looking, monitor only (medium)

### Anti-Recommendations
- Do NOT build Reddit tools (API now paid)
- Do NOT build custom scripts when MCP servers exist for the same API
- Do NOT build ConceptNet or Open-Meteo tools (irrelevant to mission)

## Lessons Learned
- The repo is heavily weighted toward utility/infrastructure (27 utility scripts) vs domain tools (8 analysis). Rebalancing toward domain tools is the priority.
- Adopting existing MCP servers is dramatically faster than building custom data-gathering scripts. Minutes of configuration vs days of development.
- The duplicate FRED source (SRC-0018 + SRC-0039) should be merged.

## Recommendations
1. Immediately add 2-3 financial MCP servers to .mcp.json (Alpha Vantage, Stockflow, Financial Datasets).
2. Build pick_logger.py and method_sec_edgar.py in the next focused session.
3. Evaluate LightRAG integration within 2 weeks.
4. Package the market research workflow as an Agent Skill (.skill.md).
