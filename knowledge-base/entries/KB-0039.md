# MCP Server for Knowledge Base Search

## Context
Agents needed 3+ tool calls to discover relevant KB entries — reading index.json, parsing YAML frontmatter, and resolving cross-references. KB-0034 identified MCP as the universal integration layer with under 50 lines needed via FastMCP.

## Method
Built a single-file FastMCP server (`storage/scripts/mcp_kb_server.py`, 96 lines) wrapping the existing SQLite FTS5 database. Configured via `.mcp.json` at repo root for project-wide stdio transport access.

## Result
6 working tools:
1. `kb_search` — FTS5 full-text search with BM25 ranking
2. `kb_get` — Retrieve specific entry by ID with tags and relationships
3. `kb_list` — List entries by resource type
4. `kb_tags` — Tag frequency cloud
5. `kb_related` — Recursive builds_on chain + shared tag discovery
6. `kb_semantic_search` — Vector similarity via LanceDB (integrated post-build)

All tools tested against live database. Server configured in `.mcp.json` for automatic availability to all Claude Code sessions in this repo.

## Lessons Learned
1. The official `mcp` PyPI package includes FastMCP — no need for the standalone `fastmcp` package
2. MCP servers go in `.mcp.json` (project scope), NOT `.claude/settings.json`
3. Tools are model-controlled (Claude decides when to search); resources are app-controlled (require @ mentions)
4. FTS5 match errors need try/except with phrase-quoted fallback

## Recommendations
1. Use `/mcp` command in Claude Code to verify server connection
2. Future: expose individual KB entries as MCP resources for @ mention access
3. Future: add coordination tools (v2) only if domain output justifies it
