# PNAM Training Strategy: Train Small, Scale Up

## Context
The pointer network is growing from 4,809 edges (repo) → 37,000 (home PC now) → 1,000,000+
(target). Rather than waiting until the network reaches full size, we want to start training
PNAM immediately at 37K edges and incrementally scale. This is the right instinct — but
"train small, scale up" has specific failure modes we need to plan around.

### Current Network Character (310 nodes, 4,809 edges)
| Property | Value | Scaling Risk |
|----------|-------|-------------|
| Wikipedia nodes | 114/310 (37%) | Will become 90%+ of nodes at 1M edges |
| Wiki avg degree | 9.2 | Will increase as more wiki-to-wiki edges form |
| Non-wiki avg degree | 19.1 | Will stay stable (core network grows slowly) |
| Cross-domain edges | 91.1% | May drop as wiki-to-wiki edges dominate |
| Weight distribution | 50% are weight-1 | Ratio will shift as semantic edges add variety |
| Degree distribution | Bimodal (peaks at 8-10, 20) | Will become heavy-tailed (power law) with hub nodes |

## The Four Risks of Train-Small-Scale-Up

### Risk 1: Distribution Shift (The Big One)

**Problem**: A model trained on a 37K-edge network where wiki nodes are 37% of the graph
and have avg degree 9.2 will learn that "wiki nodes are peripheral, low-degree, source-only."
When the network hits 1M edges and wiki nodes are 95% of the graph with avg degree 30+, the
model's assumptions are wrong.

**Concrete example**: The link prediction head learns that wiki→KB edges are the most
common cross-domain pattern. At 1M edges, wiki→wiki edges might dominate. The head keeps
predicting wiki→KB when it should predict wiki→wiki.

**Mitigation — Domain-Adaptive Batch Sampling**:
```python
class AdaptiveDomainSampler:
    """
    Instead of uniform random batches, sample to match the CURRENT
    network composition, not the initial training composition.

    Rebalances at each training epoch based on actual node/edge counts.
    """
    def __init__(self, graph_data):
        self.update_distribution(graph_data)

    def update_distribution(self, graph_data):
        """Recompute domain weights from current graph."""
        domain_counts = Counter(graph_data.domain for n in graph_data.nodes)
        total = sum(domain_counts.values())
        # Square-root balancing: not fully proportional (would drown out
        # rare domains) but not uniform either (would over-represent them)
        self.weights = {
            d: math.sqrt(c / total) for d, c in domain_counts.items()
        }
        # Normalize
        w_sum = sum(self.weights.values())
        self.weights = {d: w / w_sum for d, w in self.weights.items()}

    def sample_batch(self, batch_size):
        """Sample nodes proportional to sqrt(domain_frequency)."""
        nodes = []
        for domain, weight in self.weights.items():
            n = int(batch_size * weight)
            domain_nodes = self.graph.nodes_by_domain(domain)
            nodes.extend(random.sample(domain_nodes, min(n, len(domain_nodes))))
        return nodes
```

**Why square-root balancing**: Pure proportional sampling at 1M edges would make 95% of
batches wiki-only — the model would forget how to handle KB, SCR, SOP nodes. Pure uniform
sampling would over-represent the 310 core nodes and under-train on wiki. Square root is
the standard compromise in imbalanced learning.

### Risk 2: Catastrophic Forgetting

**Problem**: When you incrementally train on 100K new wiki edges, the model's weights shift
to accommodate wiki patterns. Performance on KB↔SCR pathfinding (which worked well at 37K)
degrades because those edge patterns haven't been seen in the new training data.

**Mitigation — Elastic Weight Consolidation (EWC) + Replay Buffer**:
```python
class EWCTrainer:
    """
    Elastic Weight Consolidation penalizes changing weights that were
    important for previous tasks. Combined with a replay buffer that
    keeps a fixed sample of old training data.
    """
    def __init__(self, model, ewc_lambda=1000):
        self.ewc_lambda = ewc_lambda
        self.fisher = {}        # Fisher information per parameter
        self.old_params = {}    # Snapshot of params after each phase
        self.replay_buffer = ReplayBuffer(max_size=50000)

    def compute_fisher(self, data_loader):
        """Estimate parameter importance from current data."""
        self.fisher = {n: torch.zeros_like(p) for n, p in model.named_parameters()}
        model.eval()
        for batch in data_loader:
            model.zero_grad()
            loss = model.compute_loss(batch)
            loss.backward()
            for n, p in model.named_parameters():
                if p.grad is not None:
                    self.fisher[n] += p.grad.data ** 2
        # Normalize
        for n in self.fisher:
            self.fisher[n] /= len(data_loader)

    def ewc_loss(self, model):
        """Penalty for deviating from old important weights."""
        loss = 0
        for n, p in model.named_parameters():
            if n in self.fisher:
                loss += (self.fisher[n] * (p - self.old_params[n]) ** 2).sum()
        return self.ewc_lambda * loss

    def train_step(self, model, new_batch):
        """Combined loss: new data + replay + EWC penalty."""
        # Loss on new data
        new_loss = model.compute_loss(new_batch)

        # Loss on replayed old data (prevents forgetting)
        replay_batch = self.replay_buffer.sample(len(new_batch))
        replay_loss = model.compute_loss(replay_batch)

        # EWC penalty (prevents important weight drift)
        ewc_penalty = self.ewc_loss(model)

        total_loss = new_loss + 0.5 * replay_loss + ewc_penalty
        return total_loss

    def end_phase(self, model, data_loader):
        """Snapshot after each scaling phase."""
        self.compute_fisher(data_loader)
        self.old_params = {n: p.clone() for n, p in model.named_parameters()}
```

**Replay buffer strategy**: Keep 50K training examples max, distributed as:
- 30% from the original 37K-edge training (the "foundation" examples)
- 40% from the most recent scaling phase
- 30% sampled uniformly from all phases

This ensures the model never completely forgets the core network patterns while
still adapting to new scale.

### Risk 3: Embedding Space Drift

**Problem**: The text encoder produces 256-dim embeddings. At 37K edges, you build a
FAISS index. At 100K edges, you fine-tune the encoder on new contrastive pairs. Now the
old embeddings in FAISS are stale — they were produced by a different encoder.

**Mitigation — Embedding Versioning + Lazy Reindex**:
```python
class VersionedEmbeddingStore:
    """
    Track which encoder version produced each embedding.
    Reindex lazily: only recompute when an embedding is accessed
    and its version is outdated.
    """
    def __init__(self, encoder, index_path):
        self.encoder = encoder
        self.encoder_version = 0
        self.embedding_versions = {}  # node_id → version
        self.embeddings = {}           # node_id → vector
        self.faiss_index = None
        self.stale_count = 0

    def update_encoder(self, new_encoder):
        """Called after fine-tuning. Bumps version, marks all embeddings stale."""
        self.encoder = new_encoder
        self.encoder_version += 1
        self.stale_count = len(self.embeddings)
        # DON'T reindex everything immediately — that's 8 hours for 6M articles
        # Instead, flag and handle lazily

    def get_embedding(self, node_id, text):
        """Returns embedding, recomputing if stale."""
        if (node_id not in self.embedding_versions or
            self.embedding_versions[node_id] < self.encoder_version):
            # Recompute on demand
            self.embeddings[node_id] = self.encoder.encode(text)
            self.embedding_versions[node_id] = self.encoder_version
            self.stale_count -= 1
        return self.embeddings[node_id]

    def background_reindex(self, priority_nodes=None):
        """
        Batch reindex in background. Priority nodes first (active network
        nodes), then remaining Wikipedia in batches.
        """
        if priority_nodes:
            # Reindex the 310 core + recent active nodes first (~minutes)
            self._reindex_batch(priority_nodes)

        # Then background reindex remaining Wikipedia (~hours)
        remaining = [nid for nid, v in self.embedding_versions.items()
                     if v < self.encoder_version]
        for batch in chunks(remaining, 1000):
            self._reindex_batch(batch)
            yield  # yield control, can be paused/resumed
```

**Key insight**: When the encoder is fine-tuned, you don't need to reindex ALL 6M
Wikipedia embeddings immediately. The core pointer network (310 nodes) can be reindexed
in seconds. Wikipedia reindexing happens in the background over hours. The model stays
usable during reindexing — slightly stale embeddings are much better than no embeddings.

**How much does fine-tuning actually shift embeddings?** When only unfreezing the last 2
transformer layers + projection, typical cosine distance between old and new embeddings
is 0.05-0.15. Nearest-neighbor rankings change for maybe 5-10% of queries. So stale
embeddings are "slightly wrong" not "completely wrong."

### Risk 4: Architectural Bottlenecks That Only Appear at Scale

**Problem**: Some architectural choices that work at 37K edges become bottlenecks at 1M.

**Bottleneck A: NeighborLoader fan-out**

At 37K edges (avg degree ~15), sampling [25, 15, 10, 5] neighbors per layer loads:
- 25 × 15 × 10 × 5 = 18,750 max nodes per target → fine

At 1M edges with some hub nodes at degree 500+:
- Same sampling: still 18,750 max per target → still fine
- BUT: hub nodes appear in MANY neighborhoods, causing redundant computation

**Fix — Cached hub embeddings**:
```python
class HubCache:
    """
    Pre-compute and cache embeddings for high-degree nodes.
    Nodes with degree > threshold are treated as "hubs" — their
    embeddings are updated once per epoch, not recomputed in every
    mini-batch they appear in.
    """
    def __init__(self, model, graph, threshold_percentile=95):
        degrees = graph.degree()
        self.threshold = np.percentile(degrees, threshold_percentile)
        self.hub_nodes = set(n for n in graph.nodes if degrees[n] > self.threshold)
        self.cache = {}

    def refresh(self, model, graph):
        """Recompute hub embeddings (once per epoch)."""
        with torch.no_grad():
            for hub in self.hub_nodes:
                self.cache[hub] = model.graph_encoder.single_node(hub, graph)

    def get(self, node_id):
        if node_id in self.cache:
            return self.cache[node_id]  # cached, no recomputation
        return None  # not a hub, compute normally
```

At 1M edges, the top 5% of nodes by degree (~3,300 hubs) might appear in 30% of all
mini-batches. Caching them saves ~25% of per-batch compute.

**Bottleneck B: Tag vocabulary growth**

At 37K edges: 31 tags. At 1M edges: could be 500+ tags as Wikipedia brings diverse topics.
The fixed 31-dim tag multi-hot vector won't work.

**Fix — Feature hashing for tags**:
```python
class TagHasher:
    """
    Feature hashing (hashing trick) for open-vocabulary tags.
    Maps any tag string to a fixed-size binary vector.
    Collisions are acceptable — empirically <5% error at dim=256.
    """
    def __init__(self, hash_dim=256):
        self.hash_dim = hash_dim

    def encode(self, tags: list[str]) -> torch.Tensor:
        vec = torch.zeros(self.hash_dim)
        for tag in tags:
            # Two hash functions to reduce collision impact
            h1 = hash(tag) % self.hash_dim
            h2 = hash(tag + "_salt") % 2  # sign bit
            vec[h1] += 1.0 if h2 == 0 else -1.0
        return vec

    # At 500 tags, expected collisions in 256-dim space: ~2-3 tags share a bin
    # At 1000 tags: ~5-6 collisions — still manageable
    # If needed, increase hash_dim to 512 (only adds 1KB per node)
```

**Bottleneck C: Community count**

The node classifier predicts into 16 communities (KB-0057). At 1M edges, Louvain might
find 200+ communities.

**Fix — Hierarchical community prediction**:
```python
class HierarchicalCommunityHead(nn.Module):
    """
    Predict at two levels:
    1. Coarse community (16 super-communities) — stable as network grows
    2. Fine community (within super-community) — grows dynamically
    """
    def __init__(self, dim=256, num_coarse=16, max_fine_per_coarse=32):
        self.coarse = nn.Linear(dim, num_coarse)
        self.fine = nn.ModuleList([
            nn.Linear(dim, max_fine_per_coarse) for _ in range(num_coarse)
        ])

    def forward(self, node_emb):
        coarse_pred = self.coarse(node_emb)
        coarse_id = coarse_pred.argmax(dim=-1)
        fine_pred = self.fine[coarse_id](node_emb)
        return coarse_pred, fine_pred
```

## The Scaling Curriculum

Rather than just "add edges, retrain," use a structured curriculum that teaches the
model progressively harder patterns:

### Phase 0: Foundation (37K edges, Day 1-2)

**Objective**: Learn the core network structure — domains, strength semantics, basic
pathfinding patterns.

```python
foundation_config = {
    'edges': 37000,
    'epochs': 30,
    'lr': 5e-4,
    'batch_size': 2048,
    'tasks': {
        'link_pred': {'weight': 1.0, 'neg_ratio': 3},
        'pathfinder': {'weight': 2.0},
        'classify': {'weight': 1.0},
    },
    'tag_dim': 64,        # small, will grow
    'community_count': 16, # small, will grow
}
```

**Validation gate**: Before proceeding, verify:
- Link prediction AUC > 0.80 on held-out edges
- Pathfinder next-hop accuracy > 60% on held-out routes
- Node classification domain accuracy > 90%

If gates fail, debug and retrain — don't scale on a broken foundation.

### Phase 1: Wiki Expansion (37K → 100K edges, Day 3-4)

**Objective**: Learn wiki-to-wiki relationships. This is where the distribution starts
shifting.

```python
expansion_config = {
    'resume_from': 'checkpoints/foundation_37k.pt',
    'new_edges': 63000,  # 100K - 37K
    'epochs': 15,
    'lr': 2e-4,          # lower LR than foundation
    'ewc_lambda': 500,   # moderate EWC penalty
    'replay_buffer': {
        'size': 20000,
        'foundation_ratio': 0.4,  # 40% foundation data
    },
    'domain_sampling': 'sqrt',    # square-root balancing
}
```

**What to watch for**:
- If wiki→wiki link prediction is good but KB→SCR degrades → increase EWC lambda
- If pathfinding on core network degrades → increase foundation_ratio in replay
- If tag F1 drops → the tag vocabulary outgrew the hash dim, increase it

### Phase 2: Scale Stress Test (100K → 250K edges, Day 5-6)

**Objective**: Validate that incremental training actually works at medium scale.

```python
stress_config = {
```

and compare to foundation performance. Acceptable degradation: <5% on core network
pathfinding. If worse, do a full retrain from scratch at 250K (takes ~10 hours but
resets any accumulated drift).

### Phase 3: Full Scale (250K → 1M edges, Day 7-10)

**Objective**: Reach target scale with validated model quality.


## Checkpoint Strategy

Every phase produces a checkpoint. Keep all of them — they're small (~600MB each)
and enable rollback if a scaling phase goes wrong:

```
storage/models/pnam/
├── foundation_37k.pt          # Phase 0 (always keep)
├── expanded_100k.pt           # Phase 1
├── stress_250k.pt             # Phase 2
├── fullscale_1m.pt            # Phase 3
├── continuous_1.05m.pt        # Phase 4 (rolling)
├── continuous_1.10m.pt
├── training_log.jsonl         # all metrics per phase
└── config.json                # current active config
```

**Rollback protocol**: If any phase's validation gates fail by more than 10% vs
the previous phase, roll back to the previous checkpoint and either:
1. Increase EWC lambda and retry
2. Increase replay buffer size and retry
3. If both fail: full retrain from scratch at the current edge count

Full retrains are expensive (~8-10 hours at 1M edges) but are a safety net. The
curriculum approach should avoid needing them — but plan for it.

## When to Give Up on Incremental and Just Retrain

Incremental training has diminishing returns when the network has changed so much
that the original model is more hindrance than help. Rules of thumb:

| Signal | Action |
|--------|--------|
| Core network pathfinding degrades >10% | Increase EWC, retry |
| Core network pathfinding degrades >20% | Full retrain |
| Link prediction AUC drops below 0.75 | Full retrain |
| Embedding space drift >0.3 cosine distance | Reindex all + full retrain |
| Network has 10x more edges than original training | Full retrain (one-time) |

The **10x rule** is the most important: when the network has 10x more edges than
what you originally trained on, the distribution has shifted enough that a clean
retrain will outperform any amount of incremental patching. At your trajectory:
- Train at 37K → full retrain at 370K (one time)
- Train at 370K → full retrain at 3.7M (if you ever get there)

Between those milestones, incremental training with EWC + replay works well.

## Result: The Full Picture

```
Day 1-2: Foundation training at 37K edges
    ↓ validation gates pass?
Day 3-4: Expand to 100K (incremental, EWC + replay)
    ↓ validation gates pass?
Day 5-6: Stress test at 250K (incremental)
    ↓ validation gates pass?
Day 7-10: Scale to 1M (incremental, large batches)
    ↓
Ongoing: Continuous learning (auto-retrain every 5K new edges)
    ↓ hit 10x original size?
One-time: Full retrain at new scale, restart the cycle
```

At each step, the model carries forward what it learned from the smaller network.
The curriculum ensures it doesn't forget the core patterns (EWC), stays calibrated
to the current distribution (adaptive sampling), and can fall back to a clean retrain
if incremental learning hits a wall (10x rule).

## Lessons Learned
- "Train small, scale up" works but ONLY with explicit anti-forgetting mechanisms (EWC + replay)
- The biggest risk is distribution shift: wiki nodes go from 37% to 95% of the graph
- Square-root domain balancing is the standard solution for imbalanced graph learning
- Validation gates between phases catch problems before they compound
- Keep all checkpoints — 600MB each is cheap insurance for rollback
- Plan for full retrains at 10x intervals; they're expensive but sometimes necessary
- Hub caching becomes important above ~100K edges when power-law degree distributions emerge
- Feature hashing for tags avoids architecture changes as vocabulary grows

## Recommendations
- Start Phase 0 (foundation training) immediately on the 37K-edge network
- Set up wandb experiment tracking from day one — you need to compare metrics across phases
- Automate the validation gates: script that runs the pathfinding benchmark and link prediction eval after each phase
- Pre-generate synthetic routes at 37K edges (run all 8 PF strategies 1000 times each) to bootstrap the pathfinder head with more training data
- Build the replay buffer infrastructure BEFORE Phase 1 — retrofitting it is harder than building it in
