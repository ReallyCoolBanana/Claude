# Multi-Agent AI Systems with Local GPU Acceleration: Comprehensive Research

## Context
Deep research into building multi-agent AI systems coordinated through a shared knowledge graph on an RTX 4070 Super (12GB VRAM). Covers agent frameworks, GPU scheduling, GraphRAG, MCP servers, small efficient models, and continuous learning.

## 1. Local LLM Agent Frameworks

### AutoGen (Microsoft) — v0.4+
- **Architecture**: Conversation-based multi-agent. v0.4 (Jan 2025) complete redesign. Oct 2025 merged with Semantic Kernel into "Microsoft Agent Framework" (GA Q1 2026).
- **Local GPU**: Via Ollama/vLLM backend. Agent orchestration is CPU-bound.
- **Multi-agent**: Magentic-One generalist team, AutoGen Studio GUI, distributed runtime.
- **RTX 4070 fit**: Good. Ollama/vLLM with 7-14B models; AutoGen orchestrates on CPU.

### CrewAI
- **Architecture**: Role-based agents with defined tools, goals, and backstories.
- **Local GPU**: Supports Ollama integration natively.
- **Strengths**: Simple API, good for defined workflows, task delegation.
- **RTX 4070 fit**: Good. Lightweight orchestration + local LLM backend.

### LangGraph
- **Architecture**: Graph-based workflow (nodes=functions, edges=transitions), built on LangChain.
- **Local GPU**: Via LangChain LLM integrations (Ollama, llama.cpp).
- **Strengths**: Cycles, branching, persistence, human-in-the-loop.
- **RTX 4070 fit**: Good. Lightweight graph runtime + local model serving.

### Agency Swarm
- **Architecture**: OpenAI Assistants API compatible, tools-first design.
- **Local GPU**: Requires OpenAI-compatible API (Ollama/LocalAI provide this).
- **RTX 4070 fit**: Moderate. Designed for cloud APIs, local compatibility varies.

## 2. GPU Sharing and Scheduling

### NVIDIA MPS (Multi-Process Service)
- Allows multiple CUDA processes to share a single GPU concurrently.
- RTX 4070 Super: **Supported.** Enables PNAM + Ollama + FAISS to share GPU without context switching.
- Reduces overhead vs. time-slicing by 50-80%.

### NVIDIA MIG (Multi-Instance GPU)
- **NOT supported** on RTX 4070 Super. MIG requires Ampere/Hopper data center GPUs (A100, H100).
- Alternative: Use MPS for process-level GPU sharing.

### Time-Slicing Strategy
```
Priority 1: PNAM inference (always loaded, ~1.3GB, microsecond responses)
Priority 2: FAISS index (always loaded, ~1.5GB, millisecond queries)
Priority 3: LLM inference (loaded on demand, ~4GB, swapped out when idle)
Priority 4: PNAM training (background, paused during LLM requests)
```

### Practical GPU Scheduling
- Use CUDA streams to overlap PNAM inference with FAISS queries
- Run LLM inference in a separate CUDA context via MPS
- PNAM training uses remaining VRAM with gradient checkpointing
- Total concurrent: PNAM + FAISS + 7B-Q4 = ~7GB, leaving 5GB headroom

## 3. Knowledge Graph-Augmented Agents

### GraphRAG (Microsoft)
- **Architecture**: Builds community summaries of a knowledge graph, uses them for retrieval.
- **Key insight**: Community-level summaries answer global queries that regular RAG can't.
- **Requirements**: Needs an LLM for summarization (can use local 7B).
- **RTX 4070 fit**: Good for building community summaries of the pointer network.
- **Integration**: Use PNAM for graph traversal → GraphRAG for LLM-readable summaries.

### KG-Enhanced Reasoning
- Neuro-symbolic: GNN embeddings as additional context for LLM prompts.
- Pattern: Query PNAM → get relevant subgraph → serialize as text → feed to LLM.
- Advantage: LLM gets structured context instead of flat document chunks.

### RAG + Knowledge Graph Pipeline
```
User Query → PNAM pathfinder (find relevant nodes)
           → FAISS (semantic search for supporting content)
           → Merge results into context
           → Local LLM generates answer with citations
```

## 4. MCP (Model Context Protocol) Servers

### Building GPU-Backed MCP Tools
- MCP allows Claude Code to call external tools via a standard protocol.
- A local MCP server can expose PNAM, FAISS, and LLM capabilities to Claude agents.

### Example MCP Server Architecture
```python
# FastAPI-based MCP server running on the home PC
@mcp_tool("search_network")
async def search_network(query: str, k: int = 10):
    """Semantic search over the pointer network."""
    embedding = pnam.encode(query)        # GPU: PNAM text encoder
    results = faiss_index.search(embedding, k)  # GPU: FAISS
    return format_results(results)

@mcp_tool("find_path")
async def find_path(source: str, target: str, strategy: str = "hybrid"):
    """Find path between two nodes using PNAM pathfinder."""
    path = pnam.pathfind(source, target, strategy)  # GPU: PNAM
    return path

@mcp_tool("predict_edges")
async def predict_edges(node_id: str, top_k: int = 20):
    """Predict missing edges for a node."""
    predictions = pnam.predict_links(node_id, top_k)  # GPU: PNAM
    return predictions

@mcp_tool("summarize")
async def summarize(node_id: str):
    """Generate a summary of a node's content."""
    content = load_node_content(node_id)
    summary = llm.generate(f"Summarize: {content}")  # GPU: LLM
    return summary
```

### Integration with Claude Code
- Claude Code connects to MCP servers via config
- The server runs locally on the home PC with GPU access
- Claude agents call tools like `search_network("transformer attention")` seamlessly
- Latency: <10ms for PNAM/FAISS, ~500ms for LLM summarization

## 5. Continuous Learning Systems

### Online Learning for GNNs
- **EWC (Elastic Weight Consolidation)**: Penalizes changing important weights. Lambda=500-2000.
- **Replay buffers**: Keep 50K representative examples, mix 30% old + 70% new.
- **Trigger**: Retrain every 5K new edges or 200 new routes.
- **Incremental**: 3-5 epochs at low LR (1e-5) on new + replayed data.

### Active Learning for Knowledge Graph Completion
- PNAM predicts uncertain edges → human/agent validates → confirmed edges become training data.
- Priority: Focus on edges with confidence 0.4-0.6 (highest uncertainty = most informative).
- Reduces labeling effort by 3-5x vs. random sampling.

### Human-in-the-Loop Feedback
- Agent routes logged to route_log.jsonl with outcomes.
- Failed routes = negative training signal for pathfinder head.
- User corrections to edge weights/strengths = direct supervision.

## 7. FastAPI Inference Server Patterns

### Multi-Model Serving Architecture
```python
class ModelRouter:
    """Route requests to appropriate model, manage GPU memory."""
    def __init__(self):
        self.always_loaded = {
            'pnam': PNAMModel('storage/models/pnam/latest.pt'),      # 1.3 GB
            'faiss': FAISSIndex('storage/embeddings/wiki_pq.index'), # 1.5 GB
            'embed': SentenceTransformer('nomic-embed-text-v1.5'),   # 0.8 GB
        }
        self.on_demand = LRUModelCache(max_vram=5.0)  # GB
        # Total always: ~3.6GB. On-demand budget: ~5GB. Headroom: ~3.4GB

    async def generate(self, prompt, model_name='qwen2.5-7b'):
        model = self.on_demand.get_or_load(model_name)
        return await model.generate(prompt)
```

### Health Monitoring
- Track VRAM usage per model, alert at 90%
- Auto-evict on-demand models when VRAM pressure is high
- Log request latency, throughput, and queue depth
- Auto-restart crashed model workers

## Lessons Learned
- NVIDIA MPS is the key enabler for concurrent GPU workloads on consumer GPUs (no MIG on 4070)
- GraphRAG's community summaries are ideal for making the pointer network LLM-queryable
- MCP servers bridge Claude Code (sandboxed) to local GPU (direct access) elegantly
- Q4_K_M is the sweet spot for most tasks — 3-5% quality loss for 3x memory savings
- Active learning on uncertain PNAM predictions is the fastest way to improve the model
- Phi-3-mini (3.8B) at Q4 is perfect for lightweight classification tasks — fast and tiny

## Recommendations
- Set up NVIDIA MPS immediately for concurrent GPU process sharing
- Build an MCP server exposing PNAM + FAISS + LLM as tools for Claude agents
- Use Ollama for model management + ExLlamaV2 for batch processing
- Keep PNAM + FAISS + embedding model always loaded (~3.6GB), swap LLMs on demand
- Start with Qwen2.5-7B-Q4 as the general-purpose local LLM
- Use Phi-3-mini-Q4 for fast classification/tagging tasks
- Implement active learning loop: PNAM predicts → agent validates → retrain
