# Security Hardening for a Local AI Hub (Ubuntu/Pop!_OS + RTX 4070 Super)

## Context
A home PC runs a local AI hub serving Claude Code sessions via MCP. The stack includes llama-server (llama.cpp) on port 8080, a FastAPI hub on port 8000, an MCP stdio server, a background watchdog daemon, and a FAISS GPU index in-process. This entry documents comprehensive security hardening research covering 14 areas, with practical commands and references to real-world incidents.

## 1. Network Isolation — Localhost Binding and Firewall

### Binding to localhost

```bash
# llama-server — defaults to 127.0.0.1, but be explicit
llama-server --host 127.0.0.1 --port 8080 --model /path/to/model.gguf

# FastAPI (uvicorn)
uvicorn hub:app --host 127.0.0.1 --port 8000
```

**Never use `--host 0.0.0.0`** unless you specifically need LAN access, and if you do, put a reverse proxy with auth in front.

### UFW firewall rules

```bash
sudo ufw reset
sudo ufw default deny incoming
sudo ufw default deny outgoing

# Allow loopback — edit /etc/ufw/before.rules, add before COMMIT:
#   -A ufw-before-output -o lo -j ACCEPT
#   -A ufw-before-input -i lo -j ACCEPT

sudo ufw allow out 53        # DNS
sudo ufw allow out 80/tcp    # apt updates
sudo ufw allow out 443/tcp   # pip, git, API calls
sudo ufw allow out 22/tcp    # git push
sudo ufw allow in 22/tcp     # SSH (if needed)

sudo ufw enable
sudo ufw status verbose
```

**Warning:** Docker published ports bypass UFW. Use `--network host` with explicit binding or `ufw-docker`.

### Verify

```bash
ss -tlnp | grep -v 127.0.0.1   # should be empty for AI services
```

## 2. Prompt Injection Risks — Knowledge Base Poisoning

**Highest-impact risk.** PoisonedRAG (USENIX Security 2025) showed 5 malicious docs among millions achieve 90% attack success.

### Attack vectors
- **Direct injection:** "Ignore all previous instructions" in a retrieved document
- **Embedding manipulation:** adversarial docs whose embeddings cluster near target queries
- **Latent payloads:** time-delayed triggers that sit dormant for years
- **Tool poisoning via MCP:** deceptive tool descriptions hijack LLM tool selection

### Mitigations

```python
import re

INJECTION_PATTERNS = [
    r"ignore\s+(all\s+)?previous\s+instructions",
    r"you\s+are\s+now\s+",
    r"system\s*prompt\s*:",
    r"<\s*system\s*>",
    r"###\s*(SYSTEM|INSTRUCTION)",
    r"do\s+not\s+follow\s+the\s+above",
    r"disregard\s+(all\s+)?(prior|previous|above)",
]

def scan_document(text: str) -> list[str]:
    findings = []
    for pattern in INJECTION_PATTERNS:
        if re.search(pattern, text, re.IGNORECASE):
            findings.append(f"Matched: {pattern}")
    return findings
```

- Tag retrieved context with provenance (filename, date, trust level)
- Delimit system prompt from retrieved content with `=== CONTEXT START/END ===`
- Maintain immutable audit log of indexed documents with SHA-256 hashes
- Consider a human review gate for new documents before indexing

## 3. FastAPI Input Validation

```python
from pydantic import BaseModel, Field, field_validator
from fastapi import FastAPI, Request, HTTPException
import re

class QueryRequest(BaseModel):
    query: str = Field(..., min_length=1, max_length=4096)
    top_k: int = Field(default=5, ge=1, le=50)
    temperature: float = Field(default=0.7, ge=0.0, le=2.0)

    @field_validator("query")
    @classmethod
    def sanitize_query(cls, v: str) -> str:
        v = v.replace("\x00", "")
        v = re.sub(r"\s{10,}", " ", v)
        if ".." in v or v.startswith("/"):
            raise ValueError("Suspicious path characters")
        return v.strip()

class DocumentIngest(BaseModel):
    title: str = Field(..., min_length=1, max_length=256)
    content: str = Field(..., min_length=1, max_length=100_000)
    source: str = Field(..., pattern=r"^[a-zA-Z0-9_\-./]+$")

    @field_validator("content")
    @classmethod
    def sanitize_content(cls, v: str) -> str:
        v = v.replace("\x00", "")
        if v.count("\n") > 5000:
            raise ValueError("Too many lines")
        return v

@app.middleware("http")
async def limit_request_size(request: Request, call_next):
    cl = request.headers.get("content-length")
    if cl and int(cl) > 10 * 1024 * 1024:
        raise HTTPException(status_code=413, detail="Request too large")
    return await call_next(request)
```

Key: Pydantic v2, whitelist characters, max lengths on all strings, separate create/update/response models.

## 4. Rate Limiting

```python
from slowapi import Limiter, _rate_limit_exceeded_handler
from slowapi.util import get_remote_address
from slowapi.errors import RateLimitExceeded

limiter = Limiter(key_func=get_remote_address)
app.state.limiter = limiter
app.add_exception_handler(RateLimitExceeded, _rate_limit_exceeded_handler)

@app.post("/v1/completions")
@limiter.limit("30/minute")
async def completions(request: Request, body: QueryRequest): ...

@app.post("/v1/embeddings")
@limiter.limit("120/minute")
async def embeddings(request: Request, body: QueryRequest): ...

@app.post("/ingest")
@limiter.limit("10/minute")
async def ingest(request: Request, body: DocumentIngest): ...
```

Session-level throttling to catch runaway Claude loops:

```python
import time
from collections import defaultdict

class SessionThrottler:
    def __init__(self, max_requests=100, window_seconds=60):
        self.counters = defaultdict(list)
        self.max, self.window = max_requests, window_seconds

    def check(self, session_id: str) -> bool:
        now = time.time()
        self.counters[session_id] = [
            t for t in self.counters[session_id] if now - t < self.window
        ]
        if len(self.counters[session_id]) >= self.max:
            return False
        self.counters[session_id].append(now)
        return True
```

llama-server concurrency: `--parallel 2 --cont-batching --timeout 120`

## 5. Authentication for Localhost Services

**Verdict: yes, use lightweight API keys even on localhost.**

- Any local process (malware, compromised npm, browser exploit) can reach 127.0.0.1
- 12,269 exposed Ollama instances (LeakIX Feb 2026) show what happens when auth is skipped
- Negligible overhead, stops drive-by access

```bash
llama-server --host 127.0.0.1 --port 8080 --api-key "$LLAMA_API_KEY"
# Note: /completion does NOT check API keys. Only /v1/* does.
```

```python
from fastapi import Depends, HTTPException, Security
from fastapi.security import HTTPBearer, HTTPAuthorizationCredentials
import secrets, os

security = HTTPBearer()
API_KEY = os.environ["HUB_API_KEY"]

async def verify_key(creds: HTTPAuthorizationCredentials = Security(security)):
    if not secrets.compare_digest(creds.credentials, API_KEY):
        raise HTTPException(status_code=401)

@app.post("/v1/completions", dependencies=[Depends(verify_key)])
async def completions(body: QueryRequest): ...
```

Do NOT use OAuth2/JWT for localhost. Static API key per service from env vars is sufficient.

## 7. NVIDIA GPU Security — VRAM Isolation

RTX 4070 Super does **not** support MIG (only A100/H100/H200).

CUDA MPS on Ada Lovelace: logically separate address spaces but **no hard VRAM isolation**, no error containment, crash propagation across clients.

**Practical approach:**
```python
# Soft VRAM limits
import torch
torch.cuda.set_per_process_memory_fraction(0.3)
```
```bash
llama-server --ctx-size 4096 --n-gpu-layers 99
# Q4_K_M 7B ~4.5GB, 13B ~8GB, RTX 4070 Super = 12GB
```

VRAM is not encrypted at rest. Use `DeviceAllow` in systemd to restrict `/dev/nvidia*` access.

## 8. Sandboxing — Bubblewrap vs. Firejail

### Bubblewrap (recommended)

```bash
sudo apt install bubblewrap

bwrap \
  --ro-bind /usr /usr --ro-bind /lib /lib --ro-bind /lib64 /lib64 \
  --symlink /usr/bin /bin --symlink /usr/sbin /sbin \
  --proc /proc --dev /dev \
  --ro-bind /data/models /data/models \
  --bind /var/log/llama /var/log/llama \
  --ro-bind /etc/llama /etc/llama \
  --ro-bind /etc/resolv.conf /etc/resolv.conf \
  --ro-bind /etc/ssl /etc/ssl \
  --unshare-pid --unshare-ipc --unshare-uts \
  --die-with-parent --new-session \
  -- /usr/local/bin/llama-server \
    --host 127.0.0.1 --port 8080 \
    --model /data/models/current.gguf
```

Hide secrets: `--ro-bind /dev/null /home/user/.ssh/id_ed25519`

### Firejail
Higher-level but setuid-root (larger attack surface). Use `--noprofile` to keep GPU access.

**Use bubblewrap for llama-server + watchdog; systemd hardening for FastAPI hub.**

## 9. Secrets Management — SOPS + Age

```bash
sudo apt install age
mkdir -p ~/.config/sops/age
age-keygen -o ~/.config/sops/age/keys.txt
chmod 600 ~/.config/sops/age/keys.txt

# .sops.yaml in project root with age public key
sops secrets/hub.yaml   # edit encrypted file

# Runtime injection (no plaintext on disk)
sops exec-env secrets/hub.yaml 'uvicorn hub:app --host 127.0.0.1 --port 8000'
```

Never: .env in git, hardcoded keys, CLI args (visible in ps aux), secrets in FAISS metadata.

## 10. Logging and Audit Trail

Log: inference requests (truncated query, tokens, latency), document ingestion (filename, SHA-256), auth failures, rate limit hits, crashes, prompt injection detections, GPU OOM.

```python
import structlog
from logging.handlers import RotatingFileHandler

structlog.configure(processors=[
    structlog.stdlib.add_log_level,
    structlog.processors.TimeStamper(fmt="iso"),
    structlog.processors.JSONRenderer(),
])
handler = RotatingFileHandler("/var/log/hub/hub.log",
    maxBytes=50*1024*1024, backupCount=10)
```

Logrotate: daily, 30 rotations, compress, delaycompress.

## 13. MCP stdio Transport Attack Surface

- Process spawning with attacker-controlled binary = RCE
- Tool poisoning: deceptive descriptions exfiltrate data (WhatsApp demo by Invariant Labs)
- Cross-tool namespace collisions across concurrent MCP servers
- MCP Inspector RCE (Anthropic's own tool, unauthenticated)
- CVE-2025-6514 (CVSS 9.6) in mcp-remote proxy
- No mandatory auth in protocol spec; no standardized audit logging

Mitigate: validate server binary hashes, review tool descriptions, sandbox each MCP server, log all tool invocations.

## 14. Real-World Vulnerabilities (2025-2026)

| Incident | Impact | Lesson |
|----------|--------|--------|
| 12,269 Ollama exposed (LeakIX Feb 2026) | Model theft, RCE as root | Bind localhost, always auth |
| Ollama RCE via malicious GGUF | Code execution from model load | Never load untrusted models |
| CVE-2025-51471 Ollama auth bypass | Token theft | Restrict model sources |
| CVE-2026-21869 llama.cpp RCE | OOB write via negative n_discard | Validate all JSON params |
| 91,403 AI honeypot attacks (GreyNoise) | SSRF, recon campaigns | AI infra is actively targeted |
| MCP Inspector RCE | RCE on dev machines | Dev tools need auth |
| PoisonedRAG (USENIX 2025) | 5 docs = 90% attack success | Validate before indexing |
