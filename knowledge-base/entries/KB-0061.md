# Phi-4 Mini (3.8B) Deployment as Hub Brain AI on RTX 4070 Super

## Context
Research into deploying Microsoft Phi-4 Mini (3.8B parameter) as a local hub/orchestrator brain AI running on an NVIDIA RTX 4070 Super (12GB VRAM). Covers GGUF quantization sources, VRAM requirements, function calling, llama.cpp compatibility, orchestrator prompt engineering, comparison with Qwen3-4B, performance benchmarks, and known failure modes.

## Method
Web research across HuggingFace repos, Microsoft documentation, llama.cpp GitHub issues, community benchmarks, and model comparison sites. Cross-referenced multiple sources for estimates where direct measurements were unavailable.

## Result
Comprehensive deployment guide assembled. Key finding: Phi-4 Mini works for orchestration but Qwen3-4B is likely the stronger choice for tool-calling/routing workloads specifically.

## Lessons Learned
1. For an orchestrator/router role, Phi-4 Mini works but requires careful prompt engineering and output validation to overcome instruction-following weaknesses.
2. Qwen3-4B appears to be the stronger choice for agentic/tool-calling workloads, while Phi-4 Mini excels at math/reasoning.
3. The 3.8B model is extremely comfortable on a 12 GB GPU -- even at Q8_0 with 16K context, only ~8 GB is used.
4. Flash attention and full GPU offload are essential for best performance.
5. Function calling works but is not as reliable as larger models. A validation/retry layer is recommended.
6. No community fine-tune specifically for improved tool calling exists yet -- this is an opportunity.

## Recommendations
1. Start with Qwen3-4B-Instruct-2507 for orchestration. Use Phi-4 Mini as a secondary option.
2. Use Q5_K_M quantization as the sweet spot for function calling reliability vs speed.
3. Enable flash attention (-fa) and full GPU offload (-ngl 99) always.
4. Keep orchestrator context short (2K-4K tokens) for maximum speed and minimum VRAM.
5. Validate all function call outputs against a whitelist of known tools before dispatching.
6. Use the bartowski GGUF from HuggingFace for the most tested quantizations.
7. Build llama.cpp from recent source (b4792+) or use Ollama 0.5.13+.
8. Consider fine-tuning a LoRA for specific tool definitions using Unsloth.
