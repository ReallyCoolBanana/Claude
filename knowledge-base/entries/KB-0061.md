# Two-Layer Knowledge Network: Hierarchical Graph Structures Research

## Context
Deep web research crawl to inform the design of a two-layer knowledge network where Layer 1 contains main articles/documents and Layer 2 contains sub-networks of citations, sections, and entities. An exponential depth penalty governs traversal cost between and within layers.

---

## 1. Hierarchical Graph Neural Networks

### Key Concepts
- **DiffPool** (Ying et al., NeurIPS 2018): Differentiable soft cluster assignment. Learns to map nodes to clusters at each GNN layer, producing coarsened graphs. Captures complex topology but has O(n^2) memory for assignment matrix.
- **SAGPool** (Self-Attention Graph Pooling): Uses GNN-computed attention scores for node selection. Lighter than DiffPool; creates sparser intermediate graphs.
- **TopKPool**: Scores nodes via learnable projection vector, selects top-k. Simplest hierarchical pooling method. Benchmarks show it remains competitive (2024 comprehensive benchmark).
- **Graph Coarsening Taxonomy**: Selection-based (SAGPool, TopKPool) preserve informative nodes. Grouping-based (DiffPool, MinCut) cluster nodes into super-nodes.

### Latest Research (2025-2026)
- **HHGT** (Hierarchical Heterogeneous Graph Transformer, WSDM 2025): Addresses over-smoothing and over-squashing in message-passing GNNs.
- **HOGT** (High-Order Graph Transformers, ICLR 2025): Three-step message passing capturing local, long-range, and higher-order relationships via learnable community sampling.
- **Hierarchical Support Graphs** (HSGs): Generalizes virtual nodes for global information exchange in MPNNs with minimal overhead. Minimizes inter-cluster edges while creating similar-sized clusters.
- **HGTS-Former**: Hierarchical hypergraph time series transformer aggregating temporal patterns.
- **HU-GNN** (April 2025): Uncertainty-aware multi-scale message control; outperforms under adversarial attacks and heterophilic graphs.
- **Multi-Hop Pooling** (IbPRIA 2025): Uses transition matrices instead of local node features for hierarchical pooling.
- **IMPO** (March 2025): Interpretable Memory-based Prototypical Pooling.

### Scalability Limits
- Exponential overhead in deep hierarchical node individualization limits practical depth to 2-3 layers (Soeteman et al., June 2025).
- Newer methods achieve near-parity with DiffPool at far lower memory cost.
- Pooling ratio and hierarchy depth affect results by several percentage points.

### Relevance to Two-Layer Network
- DiffPool/SAGPool provide proven mechanisms for learning which nodes to group into clusters (articles -> topic clusters).
- TopKPool's simplicity makes it suitable for selecting "important" nodes to surface at the main layer.
- Practical depth limit of 2-3 aligns perfectly with a two-layer architecture.
- HSGs offer a way to add inter-layer connections without full transformer overhead.

## 2. Multi-layer/Multiplex Network Theory

### Key Concepts
- **Multiplex Networks**: Same nodes appear in every layer; different edge types per layer. Inter-layer links connect a node to itself across layers only.
- **Multi-layer Networks**: Different nodes possible per layer, with arbitrary inter-layer edges. Superset of multiplex.
- **Two Regimes of Coupling**: (1) Weak inter-layer weight: layers behave as uncoupled networks. (2) Strong inter-layer weight: layers couple, producing emergent phenomena.
- **Random Walk Models**: Classical (no distinction between inter/intra-layer jumps) vs. Physical (choose to stay in layer then jump, or switch layer then jump).
- **Structural Reducibility**: Method based on quantum theory to determine minimum number of layers needed while maximizing distinguishability from aggregated graph (Nature Communications, 2015).

### Cost Models for Inter-layer Traversal
- Inter-layer link weight controls coupling strength. Too low = effectively separate networks. Too high = layers collapse to single network.
- Physical random walk model naturally penalizes layer switches by requiring a separate step.
- Multi-layer network design in OR: minimize overall cost for satisfying origin-destination demands across layers.
- An arc in one layer may be defined with respect to arc sets in another layer (hierarchical dependency).

### Knowledge Representation Applications
- Each interaction type (citation, co-authorship, shared-entity) gets its own layer.
- Multiplex embeddings capture both intra-layer and inter-layer structure.
- Dedicated embedding techniques for multiplex exist beyond standard heterogeneous graph methods.

### Relevance to Two-Layer Network
- A two-layer network with articles (Layer 1) and citations/entities (Layer 2) maps directly to a multi-layer network formalism.
- The exponential depth penalty can be modeled as inter-layer traversal cost in the physical random walk model.
- Structural reducibility theory can validate that two layers are the optimal decomposition.
- Different edge semantics per layer (citation edges vs. entity-mention edges) naturally fit multiplex framing.

## 3. Citation Network Analysis

### Key Concepts
- **Citation Graph**: Directed acyclic graph (DAG). Each document cites earlier documents. Edges are directional (citing -> cited).
- **Bibliographic Coupling (BC)**: Two documents are coupled if they cite the same third document. Retrospective measure. Second-neighbor relation in citation network.
- **Co-citation (CC)**: Two documents are co-cited if both are cited by the same third document. Forward-looking, dynamic (frequencies change over time). Also a second-neighbor relation.
- **Key Difference**: BC captures unique information not overlapping with direct citation or CC. CC is dynamic and changes as new papers cite old ones.

### Similarity Metrics
- **Co-citation strength**: Number of documents that cite both papers.
- **Bibliographic coupling strength**: Number of shared references between two papers.
- **Personalized PageRank on node-split network**: Can imitate both BC (from citing nodes) and CC (from cited nodes).
- **Lattice characterization**: Formal mathematical framework connecting BC/CC to directed acyclic graph theory.

### Tools
- **VOSviewer**: Constructs and visualizes bibliometric networks (citation, BC, CC). Widely used in scientometrics.
- **CitNetExplorer**: Interactive citation network visualization with clustering and drill-down.
- **Connected Papers**: Visualizes co-citation network from a seed paper.
- **Research Rabbit**: Generates recommendations from citation relationships.
- **CITREC**: Evaluation framework for citation-based similarity measures.

### Wikipedia/Knowledge Base Citation Extraction
- **WikiTextGraph** (2025): Python SAX-based parser for multilingual Wikipedia XML dumps. Processes 10,000 articles/batch, extracts core content and inter-article links.
- **KGGen**: LLM-based knowledge graph extraction from text (pip install kg-gen). Extracts subject-predicate-object triples.
- **CaLiGraph**: 1.3M classes, 13.7M entities from Wikipedia categories/lists via DBpedia.
- **Wikinformetrics**: Full Wikipedia knowledge graph using kwnlp_sql_parser and MediaWiki XML parser.

### Relevance to Two-Layer Network
- Citation edges form the canonical inter-article edges in Layer 1.
- BC and CC provide derived similarity edges (second-neighbor relations) without direct citation.
- WikiTextGraph and KGGen can extract both citation links and entities for populating both layers.
- The DAG property of citation graphs ensures no cycles in Layer 1 traversal.

## 4. Exponential Cost Models in Graph Traversal

### Key Concepts
- **Exponential Blowup**: Reachable entities grow as O(b^d) where b = branching factor, d = depth. In large KGs (e.g., UMLS: 407K nodes, 3.4M edges), 2-hop expansion from a high-degree node can reach >10^9 edges.
- **Exponential Decay for Relevance**: Frontloads the penalty -- most relevance reduction occurs early, then flattens into a long tail approaching but never reaching zero. Models natural phenomena (radioactive decay, information staleness).
- **Depth Penalty Formula**: relevance(d) = base_relevance * e^(-lambda * d), where lambda controls decay steepness.

### Search Algorithms with Cost Bounds
- **IDA* (Iterative Deepening A*)**: Each iteration is depth-first with cost threshold f(n) = g(n) + h(n). Threshold starts at h(start), increases to minimum exceeded cost each iteration. Memory: O(m*b) linear in solution length. Optimal with admissible monotone heuristic.
- **Hierarchical IDA***: Computes coarse paths at high abstraction level before refining locally. Reduces search space in vast graphs.
- **IDA*_CR**: Reduces reexpansion overhead while maintaining admissibility.
- **IBEX (Iterative Budgeted Exponential Search, 2019)**: Avoids worst-case exponential reexpansion of IDA*.

### Knowledge Graph Specific Approaches
- **Distance-Based Propagation (TAGNet, EMNLP 2023)**: Uses distance constraints; aggregates nodes within k = 1 + delta hops.
- **ReMindRAG (2025)**: LLM-guided KG traversal with memory replay. Memorizes traversal experience in edge embeddings, reducing cost for subsequent queries.
- **DeepPath**: Reinforcement learning for KG reasoning paths.
- **SMORE**: Knowledge graph completion with multi-hop reasoning at scale.

### Practical Depth Penalty Strategies
1. **Hard cutoff**: No traversal beyond depth d_max.
2. **Linear decay**: relevance -= penalty_per_hop * d.
3. **Exponential decay**: relevance *= e^(-lambda * d). Most natural for knowledge networks.
4. **Adaptive decay**: lambda varies by edge type or node importance.
5. **Pruning + memoization**: Cache intermediate results to avoid redundant deep traversals.
6. **Heuristic-guided**: A* with hierarchical heuristics to estimate remaining cost.

### Relevance to Two-Layer Network
- Exponential decay naturally models the decreasing relevance of information further from the query focus.
- Inter-layer traversal (article -> sub-network) should carry a fixed penalty (lambda_inter) that is higher than intra-layer traversal.
- IDA* with layer-aware heuristics provides optimal search with linear memory.
- Memoization of sub-network traversal results prevents redundant deep exploration.
- Recommended: lambda_intra = 0.3-0.5 for within-layer hops, lambda_inter = 0.7-1.0 for cross-layer jumps (based on typical KG relevance decay patterns).

## 5. Subnet/Subgraph Management

### Subgraph Sampling Strategies

#### GraphSAINT (ICLR 2020)
- **Philosophy**: Sample subgraphs of the training graph (not layers). Build complete GNN on each subgraph.
- **Key advantage**: Computation per minibatch is LINEAR w.r.t. GNN depth (not exponential like layer sampling).
- **Scalability**: Subgraph size doesn't need to grow with training graph. Million-node graphs fit in GPU memory.
- **Samplers**: Node sampler, edge sampler, random walk sampler.
- **Implementation**: PyTorch Geometric GraphSAINTLoader.

#### ClusterGCN (2019)
- Uses METIS graph partitioning to create subgraphs.
- Trains on one cluster per batch.
- Nodes in each batch are tightly connected (locality preserving).
- **Implementation**: PyTorch Geometric ClusterLoader.

#### ShaDow-GNN (NeurIPS 2021, Facebook Research)
- **Core idea**: "Deep GNN, shallow sampler." Deep GNN operates only within shallow, localized subgraphs.
- **Decouples depth and scope**: GNN depth != receptive field depth.
- **Memory**: Supports batch size as small as 1. Handles 111M-node graphs on low-end hardware.
- **Isolation**: Subgraphs for different target nodes are treated as completely isolated.
- **Backend**: C++/OpenMP for subgraph extraction, PyTorch for propagation.
- **Integrated into**: DGL and PyTorch Geometric.

#### SIGN (Scalable Inception Graph Network)
- Up to 100x faster than ClusterGCN/GraphSAINT at inference.
- Uses standard mini-batch gradient descent (no graph sampling needed).
- Pre-computes multi-scale diffusion operators.

### Lazy Loading and Caching
- **Cache-Aside (Lazy Loading)**: Cache starts empty, populated on demand. Application fetches from source on cache miss, stores result.
- **GraphCache**: General-purpose graph query caching with PINC replacement policy (utility = cost_saved / age).
- **Connectivity-aware prefetching**: Predicts which neighboring subgraphs will be accessed next based on graph structure.
- **In-memory subgraph caching**: Identifies frequently accessed subgraph patterns; preloads high-availability subgraphs.
- **Minimal subgraph caching**: Stores minimal subgraphs of deep hierarchical relationships for fast leaf retrieval (avoids full-depth traversal).

### Memory-Efficient Representations
- **SpanGNN (2024)**: Spanning subgraph training from empty structure.
- **CSR format**: sizeof(int) * (V+E) total memory. Immutable but maximally compact.
- **Packed CSR (PCSR)**: Dynamic variant allowing insertions without full rebuild.
- **Memory-mapped I/O (GVEL)**: Maps CSR files directly to memory, outperforming Hornet, Gunrock, PIGO.

### Relevance to Two-Layer Network
- GraphSAINT's subgraph sampling philosophy maps perfectly to lazy-loading sub-networks: sample a subgraph around the query focus rather than loading the full Layer 2.
- ShaDow-GNN's "deep on shallow" principle aligns with using deep analysis on small, localized citation/entity subgraphs.
- Cache-aside pattern is the right fit: sub-network data loaded on-demand, cached for subsequent queries.
- PINC-style utility-based eviction ensures frequently traversed sub-networks stay cached.
- CSR + mmap provides the storage backbone for sub-networks that exceed RAM.

## 6. Heterogeneous Information Networks (HINs)

### Key Concepts
- **Heterogeneous Information Network**: Graph with multiple node types and/or edge types. Formally: G = (V, E, T_v, T_e) where T_v and T_e are type mapping functions.
- **Meta-path**: Sequence of node/edge types defining a semantic relation. E.g., Author-Paper-Venue (APV) captures "authors who published in the same venue."
- **Meta-graph**: Generalization of meta-path allowing branching structures.

### Meta-path Based Methods
- **metapath2vec** (KDD 2017): Meta-path-guided random walks + skip-gram embedding. Captures semantic relationships through typed random walks.
- **Spacey**: Heterogeneous spacey random walk unifying different meta-paths.
- **JUST**: Jump-and-Stay strategies without explicit meta-paths.

### Relation-Aware Message Passing
- **HAN** (Heterogeneous Graph Attention Network, WWW 2019): First GNN for heterogeneous graphs. Hierarchical attention: node-level (within meta-path) + semantic-level (across meta-paths). Projects all node types to unified feature space.
- **R-HGNN**: Relation-aware heterogeneous graph representation learning.
- **DHGNN** (Dynamic HetGNN, 2025): Combines relation-aware message passing with meta-path-guided multi-hop aggregation. Captures both local interactions and long-range semantic patterns.
- **MetaHGNIE** (2025): Hypergraph contrastive learning on heterogeneous KGs. Meta-path-induced typed hyperedges capture multi-entity relational contexts.
- **MSHGT** (2025): Decomposes multiple meta-path adjacency matrices for structural representation learning.

### HIN Embedding Methods
- **Random-walk-based**: metapath2vec, HIN2vec, HERec.
- **GNN-based**: HAN, HetGNN, MAGNN (aggregate embeddings of multiple meta-paths with attention).
- **Graph Transformer-based**: EHG (2025) -- linearized key-value interaction for O(n) complexity.
- **Contrastive Learning**: MetaHGNIE uses structural + semantic contrastive views.

### Knowledge Base Construction Applications
- Meta-path discovery: Given example pairs, automatically generate explanatory meta-paths.
- Schema-rich HINs: RDF Knowledge Graphs with thousands of types map to HIN framework.
- Top-down (ontology-first) vs. bottom-up (entity-first) KG construction.
- DKGBuilder: Domain KG from scratch using entity/relation extraction + representation learning.

### Relevance to Two-Layer Network
- The two-layer network IS a heterogeneous information network: articles, citations, sections, and entities are different node types.
- Meta-paths define traversal semantics: Article-Cites-Article (direct citation), Article-Contains-Entity-ContainedIn-Article (entity co-occurrence).
- HAN's hierarchical attention (node-level + semantic-level) maps to within-layer + across-layer attention.
- Relation-aware message passing handles the different edge types (citation vs. section-of vs. mentions-entity).
- Meta-path discovery can automatically find useful traversal patterns in the constructed network.

## 7. Practical Graph Storage Formats

### JSON vs Binary
| Aspect | JSON | Binary (Pickle/HDF5/CSR) |
|--------|------|--------------------------|
| Human readable | Yes | No |
| Interoperability | High (JS, Python, etc.) | Library-specific |
| Size | Large (text overhead) | Compact (2-10x smaller) |
| Load speed | Slow (parsing) | Fast (direct memory map) |
| Mutation | Easy (edit text) | Requires rebuild (CSR) |
| Best for | Small graphs (<100K nodes), APIs | Large graphs (>100K nodes) |

### Library Comparison for Million-Node Graphs

| Library | Language | Memory per Edge | Speed vs NetworkX | CSR Support | Parallelism |
|---------|----------|----------------|-------------------|-------------|-------------|
| **NetworkX** | Python | ~100 bytes | 1x (baseline) | No (dict-based) | None |
| **igraph** | C | ~32 bytes | 10-50x faster | Yes (via SciPy) | Limited |
| **graph-tool** | C++ | ~32 bytes | 40-250x faster | Internal | OpenMP |
| **NetworKit** | C++ | ~16 bytes | 50-300x faster | Internal | OpenMP |
| **rustworkx** | Rust | ~24 bytes | 20-100x faster | Via SciPy | Rust threads |

### CSR (Compressed Sparse Row) Format
- **Structure**: Three arrays -- values, row_offsets (size V+1), column_indices (size E).
- **Memory**: sizeof(int) * (V + E). For 1M nodes, 10M edges: ~40 MB (vs. ~1 GB in NetworkX).
- **Immutability**: Cannot add/remove vertices or edges. Must rebuild on modification.
- **Packed CSR (PCSR)**: Dynamic variant using packed memory arrays for insertions.
- **Distributed CSR (dCSR)**: Partition-based distribution across compute nodes. Each process owns its partition.

### Memory-Mapped Graph Files
- **GVEL**: Memory-mapped I/O for CSR loading. Outperforms Hornet, Gunrock, PIGO.
- **mmap()**: Maps file directly to virtual address space. OS handles paging.
- **Benefits**: Load graphs larger than RAM; pages loaded on demand by OS; shared across processes.
- **HDF5**: Hierarchical data format supporting chunked, compressed arrays. Good for random walks without loading full graph.

### Sharded Graph Storage
- **Distributed CSR (dCSR)**: Each shard is a CSR partition. Routing layer connects shards.
- **BACH (LSM-Tree hybrid)**: Bridges adjacency list (write-friendly) and CSR (read-friendly) via compaction.
- **Graph Databases**: Neo4j, Memgraph, Amazon Neptune -- handle sharding, transactions, and caching internally.

### Relevance to Two-Layer Network
- **Layer 1 (articles)**: Small enough for in-memory storage. igraph or graph-tool in CSR format. JSON export for API interoperability.
- **Layer 2 (sub-networks)**: Potentially very large. Use memory-mapped CSR files per sub-network shard.
- **Storage strategy**: Each article's sub-network stored as a separate CSR file on disk. Memory-mapped on access. LRU cache for recently accessed sub-networks.
- **Recommended stack**: graph-tool or igraph for graph operations + CSR/mmap for storage + JSON for API layer.
- **For million-node scale**: graph-tool with OpenMP provides best algorithmic performance; igraph provides easiest SciPy/CSR integration.

## Synthesis: Architecture Recommendations for Two-Layer Knowledge Network

### Recommended Architecture

```
Layer 1: Article Network (Main Graph)
  Node types: Article, Topic
  Edge types: Cites, RelatedTo, SharedTopic
  Storage: igraph/graph-tool in-memory (CSR)
  Size: ~100K-1M nodes
  Traversal: BFS/DFS with exponential decay lambda=0.3

    | Inter-layer edges (Article <-> SubNetwork)
    | Traversal penalty: lambda_inter = 0.8

Layer 2: Sub-Networks (Per-Article Detail Graphs)
  Node types: Section, Entity, Citation, Reference
  Edge types: ContainedIn, Mentions, CitedBy, SeeAlso
  Storage: CSR files on disk, memory-mapped on access
  Size: ~100-10K nodes per sub-network
  Cache: LRU with PINC-style utility eviction
  Traversal: Local search with lambda=0.5
```

### Key Design Decisions

1. **Graph formalism**: Multi-layer heterogeneous information network (not pure multiplex, since Layer 2 has different node types than Layer 1).

2. **Depth penalty**: Exponential decay with layer-aware lambda:
   - Within Layer 1: relevance *= e^(-0.3 * hops)
   - Layer 1 to Layer 2: relevance *= e^(-0.8) (one-time cross-layer penalty)
   - Within Layer 2: relevance *= e^(-0.5 * hops)
   - Maximum effective depth: ~5 total hops before relevance < 5%

3. **Sub-network loading**: GraphSAINT-inspired lazy sampling. Load sub-networks on demand, cache with utility-based eviction.

4. **Storage format**: CSR + memory-mapped files for Layer 2. In-memory graph-tool/igraph for Layer 1.

5. **Traversal algorithm**: Hierarchical IDA* with layer-aware heuristics. Linear memory usage, optimal with admissible heuristic.

6. **Embedding method**: HAN-style hierarchical attention for learning node/semantic importance across layers. Meta-path-guided aggregation for cross-layer patterns.

7. **Citation analysis**: Use bibliographic coupling and co-citation as derived edge types in Layer 1. WikiTextGraph or KGGen for initial extraction.

### Implementation Priorities
1. Define schema (node types, edge types, meta-paths) using HIN formalism
2. Build Layer 1 with igraph (CSR backend, SciPy integration)
3. Implement CSR + mmap storage for Layer 2 sub-networks
4. Add exponential decay scoring to traversal engine
5. Implement cache-aside pattern with PINC eviction for sub-networks
6. Add meta-path-based similarity search (article-entity-article paths)
7. Optional: Train HAN/DHGNN for learned representations

## Lessons Learned
- The practical depth limit for hierarchical GNNs (2-3 layers) validates the two-layer architecture choice.
- Exponential decay is the standard relevance penalty in production systems (Milvus, KG traversal engines).
- CSR format provides 10-30x memory savings over dictionary-based representations, critical for Layer 2 sub-networks.
- GraphSAINT's subgraph sampling philosophy (sample the graph, not the layers) is the right paradigm for on-demand sub-network loading.
- HAN's hierarchical attention mechanism directly models the two-level structure needed.
- The "Turning Citation Networks Inside Out" paper (2026) validates the approach of having both a citation layer and a content/entity layer.

## Recommendations
- Use igraph over NetworkX for any graph with >10K nodes (10-50x faster, 3x less memory).
- Prefer CSR + mmap over loading full graphs into memory for Layer 2.
- Set initial exponential decay parameters at lambda_intra=0.3, lambda_inter=0.8, then tune empirically.
- Use WikiTextGraph for Wikipedia article parsing and KGGen for entity extraction.
- Consider graph-tool if OpenMP parallelism is needed for batch operations.
- Start with simple TopKPool for identifying important nodes before exploring DiffPool/SAGPool.
