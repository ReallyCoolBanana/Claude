# TOCTOU Bug Fixes in Coordination System

## Context
KB-0035 identified rate limiter TOCTOU as one of top 3 weak links. A comprehensive audit (Archiver 3) found 22 TOCTOU/concurrency bugs across the coordination system — 2 Critical, 5 High, 9 Medium, 6 Low. This session fixed the 2 Critical and 2 highest High-severity bugs.

## Method
Applied two fix patterns based on Researcher 3's analysis:
1. **Single-statement UPDATE...WHERE** — eliminates TOCTOU entirely by combining check and action in one SQL statement. Used `cursor.rowcount` to detect precondition failure.
2. **BEGIN IMMEDIATE transaction** — acquires write lock immediately, serializing the read-modify-write cycle across processes. Added ROLLBACK in except blocks.

## Result
4 bugs fixed:

| Bug | Severity | File | Fix Pattern |
|-----|----------|------|-------------|
| TOCTOU-WS-001 | Critical | `work_stealing.py:complete_work` | Single-statement UPDATE...WHERE claimed_by=? |
| TOCTOU-HP-001 | Critical | `help_protocol.py:fulfill_help` | BEGIN IMMEDIATE wrapping SELECT + 2 UPDATEs |
| TOCTOU-DC-001 | High | `direct_channels.py:join_channel` | BEGIN IMMEDIATE for JSON participants RMW |
| TOCTOU-DC-002 | High | `direct_channels.py:leave_channel` | BEGIN IMMEDIATE for JSON participants RMW |

Stress tests written (`tests/test_toctou_fixes.py`) using threading.Barrier for maximum contention, 5 rounds each, separate DB connections per thread.

## Lessons Learned
1. **Single-statement UPDATE...WHERE is superior** to BEGIN IMMEDIATE when feasible — eliminates the race entirely vs serializing it
2. **threading.Lock + BEGIN IMMEDIATE serve different purposes**: Lock protects the Python connection object within a process; BEGIN IMMEDIATE protects across processes
3. **In WAL mode, BEGIN IMMEDIATE and BEGIN EXCLUSIVE behave identically** — use IMMEDIATE for convention consistency
4. The existing `@_retry_on_busy` decorator already handles SQLITE_BUSY from BEGIN IMMEDIATE contention
5. **18 bugs remain** (3 High, 9 Medium, 6 Low) — documented in `archiver_toctou_catalog.json`

## Recommendations
1. Next priority fixes: TOCTOU-WS-002 (start_stage), TOCTOU-HP-002 (request_help), TOCTOU-MTR-004 (double stop)
2. Use single-statement UPDATE...WHERE pattern wherever possible — it's the simplest and safest
3. Run `python -m pytest storage/coordination/tests/test_toctou_fixes.py` to verify fixes hold
4. Consider adding these stress tests to CI pipeline
