# Custom Model Design: Pointer Network Agent Model (PNAM)

## Context
Rather than running separate off-the-shelf models for each task in KB-0055, we can train a single
unified model purpose-built for the pointer network. The RTX 4070 Super (12GB VRAM) is well-suited
for training models up to ~300M parameters. The pointer network provides rich structured training
data: 4,809 edges, 310 nodes across 7 domains, 599 route logs across 24 task types, 31 tag
clusters, and millions of Wikipedia articles for the text encoder.

### Available Training Data
| Source | Count | What It Provides |
|--------|-------|------------------|
| Edges | 4,809 | Link prediction, weight prediction, strength classification |
| Nodes | 310 | Node features (domain, tags, pointer count) |
| Route logs | 599 | Sequential traversal decisions, outcome prediction |
| Tag clusters | 31 | Community structure, topic grouping |
| Wikipedia articles | ~6M | Text understanding, semantic grounding |
| Pathfinding benchmarks | 185+ | Strategy selection ground truth |

### Why a Custom Model Beats Off-the-Shelf
- **Domain-specific**: The pointer network has unique semantics (strength levels, reason types, domain taxonomy) that general models don't understand
- **Multi-task**: One model handles edge prediction, pathfinding, classification, and search instead of running 5 separate tools
- **Tiny and fast**: A 100-200M param model runs at >1000 inferences/sec on the 4070S, vs. seconds per query for a 7B LLM
- **Trainable on your data**: Route logs provide real agent behavior to learn from; no model in the world has been trained on pointer network traversals

### Component 1: Text Encoder (~110M params, mostly frozen)

**Base**: Start from `all-MiniLM-L6-v2` (22M params, 384-dim) or `bge-small-en-v1.5` (33M)
for efficiency, OR `nomic-embed-text-v1.5` (137M, 768-dim) for quality.

**Purpose**: Encodes Wikipedia article text, node titles, tag names, and query strings into
dense vectors. This is the semantic backbone.

**Training approach**: Freeze the base weights initially. Fine-tune only the last 2 layers
on pointer-network-specific contrastive pairs:
- **Positive pairs**: Nodes connected by primary/supporting edges
- **Hard negatives**: Nodes in the same domain but not connected
- **Cross-domain positives**: wiki→KB edges that exist in the network

**Output**: 384-dim or 768-dim text embedding per input

### Component 2: Graph Encoder (~8M params, trained from scratch)

**Architecture**: 3-layer GraphSAGE with attention (similar to GAT but with neighborhood sampling)

```
Layer 1: SAGEConv(input_dim, 256) + LayerNorm + ReLU
Layer 2: SAGEConv(256, 256) + LayerNorm + ReLU
Layer 3: SAGEConv(256, 128) + LayerNorm
```

**Node feature vector** (input_dim = ~430):
- Text embedding of node title/content (384-dim from text encoder)
- Domain one-hot (7-dim: kb, scr, sop, team, src, tool, wiki)
- Tag multi-hot (31-dim from the 31 known tags)
- Degree features (3-dim: in-degree, out-degree, avg edge weight)
- Strength profile (4-dim: % of edges that are primary/supporting/related/tangential)

**What it learns**: Structural patterns — which nodes are bridges, which clusters are
tightly connected, how domains relate to each other topologically.

**Output**: 128-dim structural embedding per node

### Component 3: Fusion Layer (~4M params)

```python
class FusionLayer(nn.Module):
    def __init__(self, text_dim=384, graph_dim=128, fused_dim=256):
        self.text_proj = nn.Linear(text_dim, fused_dim)
        self.graph_proj = nn.Linear(graph_dim, fused_dim)
        self.cross_attn = nn.MultiheadAttention(fused_dim, num_heads=8)
        self.ffn = nn.Sequential(
            nn.Linear(fused_dim, fused_dim * 2),
            nn.GELU(),
            nn.Linear(fused_dim * 2, fused_dim)
        )

    def forward(self, text_emb, graph_emb):
        t = self.text_proj(text_emb)
        g = self.graph_proj(graph_emb)
        # Cross-attention: text attends to graph structure
        fused, _ = self.cross_attn(t.unsqueeze(0), g.unsqueeze(0), g.unsqueeze(0))
        return self.ffn(fused.squeeze(0) + t)  # residual
```

**Output**: 256-dim fused node representation combining semantic meaning and graph structure

### Task Head 1: Link Prediction (~2M params)

**What it does**: Given two nodes, predict whether an edge should exist, its weight (1-10),
and its strength class (primary/supporting/related/tangential).

```python
class LinkPredHead(nn.Module):
    def __init__(self, fused_dim=256):
        self.edge_scorer = nn.Sequential(
            nn.Linear(fused_dim * 2, 256),
            nn.ReLU(),
            nn.Linear(256, 1),  # exists? (sigmoid)
        )
        self.weight_predictor = nn.Linear(fused_dim * 2, 10)  # weight 1-10 (softmax)
        self.strength_classifier = nn.Linear(fused_dim * 2, 4)  # 4 strength classes

    def forward(self, node_a, node_b):
        pair = torch.cat([node_a, node_b], dim=-1)
        return {
            'edge_prob': torch.sigmoid(self.edge_scorer(pair)),
            'weight_dist': F.softmax(self.weight_predictor(pair), dim=-1),
            'strength': F.softmax(self.strength_classifier(pair), dim=-1),
        }
```

**Training data**:
- Positive: 4,809 existing edges with known weight/strength
- Negative: Sample ~15,000 non-edges (node pairs with no connection)
- Total: ~20K training examples — plenty for this head

**This replaces**: KB-0055 Tasks 2 (semantic edges) and 5 (link prediction)

### Task Head 2: Pathfinder (~4M params)

**What it does**: Given a source node, target node, and strategy hint, predicts the best
next hop and estimated path quality. This is the key "agent assist" capability.

```python
class PathfinderHead(nn.Module):
    def __init__(self, fused_dim=256, num_strategies=8):
        self.strategy_embed = nn.Embedding(num_strategies, 64)
        self.next_hop_scorer = nn.Sequential(
            nn.Linear(fused_dim * 2 + 64, 512),
            nn.ReLU(),
            nn.Dropout(0.1),
            nn.Linear(512, 256),
            nn.ReLU(),
            nn.Linear(256, 1),  # score per candidate neighbor
        )
        self.path_quality = nn.Sequential(
            nn.Linear(fused_dim * 2 + 64, 128),
            nn.ReLU(),
            nn.Linear(128, 3),  # [predicted_hops, predicted_total_weight, success_prob]
        )

    def forward(self, source, target, neighbors, strategy_id):
        strat = self.strategy_embed(strategy_id)
        context = torch.cat([source, target, strat], dim=-1)
        # Score each neighbor as potential next hop
        scores = []
        for n in neighbors:
            pair = torch.cat([context, n], dim=-1)  # would actually batch this
            scores.append(self.next_hop_scorer(pair))
        return {
            'next_hop_scores': torch.cat(scores),
            'path_quality': self.path_quality(context),
        }
```

**Training data**:
- 599 route logs containing 4,667 individual hop decisions (avg 7.8 hops × 599 routes)
- Each hop is a training example: (current_node, target, strategy, chosen_next, outcome)
- Augment with the 185+ pathfinding benchmark results from SOP-030
- Total: ~5,000 hop-level training examples

**This replaces**: KB-0055 Task 4 (GPU pathfinding) and directly assists all 8 pathfinding strategies

### Task Head 3: Node Classifier (~2M params)

**What it does**: Predicts domain, category, tags, and community membership for any node —
including new Wikipedia articles being added to the network.

```python
class NodeClassifyHead(nn.Module):
    def __init__(self, fused_dim=256):
        self.domain_classifier = nn.Linear(fused_dim, 7)    # 7 domains
        self.category_classifier = nn.Linear(fused_dim, 6)  # 6 categories
        self.tag_predictor = nn.Linear(fused_dim, 31)       # 31 tags (multi-label sigmoid)
        self.community_predictor = nn.Linear(fused_dim, 16) # up to 16 communities

    def forward(self, node_emb):
        return {
            'domain': F.softmax(self.domain_classifier(node_emb), dim=-1),
            'category': F.softmax(self.category_classifier(node_emb), dim=-1),
            'tags': torch.sigmoid(self.tag_predictor(node_emb)),  # multi-label
            'community': F.softmax(self.community_predictor(node_emb), dim=-1),
        }
```

**Training data**:
- 310 nodes with known domains, 196 with known categories, 310 with known tags
- Augment by using tag cluster membership as community labels
- For Wikipedia expansion: train on the 114 existing wiki nodes, apply to millions

**This replaces**: KB-0055 Tasks 3 (topic classifier) and partially 7 (entity extraction)

## Training Pipeline

### Phase 1: Text Encoder Fine-tuning (Day 1, ~4 hours)

```bash
# Contrastive fine-tuning on pointer network pairs
python train_text_encoder.py \
  --base-model all-MiniLM-L6-v2 \
  --train-pairs pointer_network_pairs.jsonl \
  --epochs 10 \
  --batch-size 256 \
  --lr 2e-5 \
  --unfreeze-layers 2
```

**Data prep**: Generate contrastive pairs from the 4,809 edges:
- Each edge → positive pair (source title, target title)
- Sample 3 hard negatives per positive (same domain, no edge)
- Total: ~20K pairs, fits in memory trivially

**VRAM usage**: ~2GB for MiniLM, ~4GB for nomic-embed

### Phase 2: Graph Encoder Pre-training (Day 1, ~1 hour)

```bash
# Self-supervised graph learning (node property prediction)
python train_graph_encoder.py \
  --network pointer-network.json \
  --method node2vec+graphsage \
  --hidden-dim 256 \
  --num-layers 3 \
  --epochs 200 \
  --lr 1e-3
```

**Self-supervised objectives**:
1. **Masked node prediction**: Mask 15% of node features, predict from neighbors
2. **Edge reconstruction**: Predict masked edges from remaining structure
3. **Node2Vec alignment**: Align GNN embeddings with Node2Vec random walk embeddings

**VRAM usage**: <1GB (310 nodes is tiny for a GNN)

### Phase 3: Joint Training (Day 2, ~6 hours)

```bash
# Multi-task training with all heads
python train_pnam.py \
  --text-encoder checkpoints/text_encoder_phase1.pt \
  --graph-encoder checkpoints/graph_encoder_phase2.pt \
  --network pointer-network.json \
  --routes route_log.jsonl \
  --tasks link_pred,pathfinder,node_classify \
  --epochs 50 \
  --batch-size 64 \
  --lr 5e-4 \
  --loss-weights '{"link": 1.0, "path": 2.0, "classify": 0.5}'
```

**Multi-task loss**:
```
L = w1 * L_link + w2 * L_path + w3 * L_classify
```
Where:
- `L_link` = BCE(edge exists) + CE(weight class) + CE(strength class)
- `L_path` = CE(next hop selection) + MSE(hop count prediction) + BCE(success prediction)
- `L_classify` = CE(domain) + CE(category) + BCE(tags, multi-label) + CE(community)

**VRAM usage**: ~6-8GB total (model + optimizer states + batch data)

### Phase 4: Wikipedia Expansion Inference (Day 3, ~8 hours)

Once trained, run the model over all Wikipedia articles:

```bash
# Batch inference: embed + classify + link-predict for all Wikipedia
python pnam_expand.py \
  --model checkpoints/pnam_final.pt \
  --wikipedia-dump /path/to/wikipedia/ \
  --batch-size 512 \
  --output-embeddings storage/embeddings/wiki_pnam.index \
  --output-edges storage/pointer-routes/pnam_predicted_edges.jsonl \
  --output-classifications storage/pointer-routes/pnam_wiki_classes.json
```

### Phase 5: Continuous Learning (Ongoing)

The model improves as agents use the network:

```python
# After each agent session, fine-tune on new route data
new_routes = load_new_routes(since=last_training_timestamp)
if len(new_routes) >= 50:  # batch threshold
    model.train()
    for route in new_routes:
        loss = model.pathfinder_loss(route)
        loss.backward()
    optimizer.step()
    save_checkpoint(model)
```

## VRAM Budget (12GB RTX 4070 Super)

| Component | Training | Inference |
|-----------|----------|-----------|
| Text encoder (MiniLM) | 2.0 GB | 0.5 GB |
| Graph encoder (3-layer SAGE) | 0.3 GB | 0.1 GB |
| Fusion + task heads | 0.5 GB | 0.2 GB |
| Optimizer states (AdamW) | 2.0 GB | 0 GB |
| Batch data + activations | 3.0 GB | 0.5 GB |
| **Total** | **~8 GB** | **~1.3 GB** |
| **Headroom** | **4 GB free** | **10.7 GB free** |

The 4GB training headroom means you could upgrade to `nomic-embed-text` (137M) as the
text encoder and still fit comfortably. The 10.7GB inference headroom means you could
run the model alongside the FastAPI search server from KB-0055 Task 9 simultaneously.

## Result: What PNAM Replaces

| KB-0055 Task | PNAM Equivalent | Improvement |
|-------------|-----------------|-------------|
| Task 1 (embeddings) | Text encoder produces pointer-network-tuned embeddings | Better than generic embeddings — fine-tuned on actual edges |
| Task 2 (semantic edges) | Link prediction head | Predicts weight AND strength, not just similarity |
| Task 3 (topic classifier) | Node classification head | Multi-label tags + category + community in one pass |
| Task 4 (graph analytics) | Graph encoder learns centrality/communities implicitly | Learned representations capture structure without explicit algorithms |
| Task 5 (link prediction) | Link prediction head | Same, but integrated with text understanding |
| Task 9 (search server) | PNAM serves as the search backend | One model serves embeddings + classification + link prediction |
| Task 10 (rebuilder) | Continuous learning loop | Model updates incrementally with new routes |

**Tasks NOT replaced** (still use standalone tools):
- Task 6 (article summarization) — needs a generative LLM, PNAM is discriminative
- Task 7 (NER) — spaCy is more appropriate for entity extraction
- Task 8 (Wikidata) — data fetching, not a model task

## Lessons Learned
- 12GB VRAM is generous for a ~130M parameter multi-task model; training + inference both fit
- The pointer network's 4,809 edges and 599 routes provide enough signal for all three task heads
- GraphSAGE with neighborhood sampling handles the network's uneven degree distribution (2-38 edges per node)
- The text encoder dominates parameter count but most weights stay frozen
- Multi-task training with shared representations outperforms separate models because edge structure informs pathfinding which informs classification

## Recommendations
- Start with `all-MiniLM-L6-v2` (22M) as text encoder for fast iteration, upgrade to `nomic-embed` (137M) once the architecture is validated
- Use PyTorch Geometric for the GNN — best 4070S support and most active development
- Log all training runs to wandb for experiment tracking
- Export the final model to ONNX for ~3x inference speedup
- Store model checkpoints in `storage/models/pnam/` with version metadata
- The pathfinder head benefits most from more data — prioritize running more agent routes to generate training examples
