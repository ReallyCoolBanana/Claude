## How It Works

1. **Claude session** sends a request via MCP tool → hits FastAPI on localhost:8000
2. **Hub AI** receives the request, understands intent, decomposes into sub-tasks
3. **VRAM Manager** checks what's loaded, swaps models if needed (only 12GB to share)
4. **Hub AI** dispatches sub-tasks to the right sub-AI workers
5. **Sub-AIs** execute (embed, summarize, search, predict) and return results
6. **Hub AI** aggregates, formats, and returns the combined result to Claude
7. **Pointer Network Sync** pushes any new edges/nodes to the git repo

## Key Design Decisions

- **Hub AI is always loaded** (~4-6 GB) — it's the persistent brain
- **Sub-AIs are swapped in/out** based on demand — VRAM Manager ensures no OOM
- **Embedder is lightweight** (0.5 GB) and can co-exist with the Hub at all times
- **Summarizer is the heaviest** (4-6 GB) — loaded on demand, unloaded after batch
- **All communication is REST/JSON** — simple, debuggable, MCP-compatible
- **Task queue prevents overload** — Claude sessions don't block each other
