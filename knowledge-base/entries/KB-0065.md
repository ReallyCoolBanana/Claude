# Pointer Network JSON → Sharded Directory Migration Design

## Context
Design for migrating `storage/pointer-network.json` (310 nodes, 4,809 edges, 987 KB) to a sharded directory structure. Includes migration script with round-trip validation, facade adapter for backward compatibility with 34 consumer scripts, and a phased rollout plan.

## Current Structure

**Node format** (only 2 fields beyond ID key):
```json
{
  "domain": "knowledge-base",
  "pointers": [
    {"to": "TEAM-0008", "weight": 9, "reasons": ["shared_tags:benchmark,indexing,storage"], "strength": "primary"}
  ]
}
```

**Node prefixes**: KB (46), SCR (57), SOP (22), SRC (48), TEAM (22), TOOL (1), wiki (114) = 310 total.
**Edge types**: shared_tags (4426), explicit_reference (1093), category_affinity (708), backlink (33), tag_upgrade (6).

**34 consumer files** all follow the same pattern: `json.load()` → `data["nodes"]` → iterate `node.get("pointers", [])`.

## Target Structure

```
storage/pointer-network/
  meta.json                     # Schema, stats, tag_clusters, strength_levels
  nodes/
    KB/KB-0001.json             # {id, domain, outgoing_edge_count, incoming_edge_count}
    SCR/SCR-0001.json
    ...
  edges/
    by-source/
      KB-0001.edges.json        # {source, edges: [{to, weight, reasons, strength}]}
    by-type/
      shared_tags.jsonl          # One line per edge-reason pair (append-only)
      explicit_reference.jsonl
      ...
  cache/
    adjacency.msgpack            # Pre-built adjacency for fast traversal
```

## Field Separation

| Field | Goes In | Why |
|-------|---------|-----|
| `id`, `domain` | Node file | Identity/intrinsic properties |
| `outgoing_edge_count`, `incoming_edge_count` | Node file | Denormalized stats |
| `pointers` array | Edge file (by-source) | Exact same format, 1:1 mapping |
| `tag_clusters` | meta.json | Cross-cutting derived index |
| `strength_levels` | meta.json | Static schema/reference data |

## Migration Script

Full Python script with:
- `migrate()` — writes all sharded files
- `compute_checksums()` — canonical SHA-256 of sorted nodes+pointers
- `validate_roundtrip()` — reconstructs full graph from shards, compares to original
- `--dry-run` and `--keep-monolithic` flags
- Renames original to `.json.bak` only after validation passes

Key details:
- Edge files use exact same `{to, weight, reasons, strength}` format (zero-loss)
- JSONL by-type files: one line per edge-reason pair (an edge with 3 reasons = 3 lines)
- Adjacency cache stores `(to, weight, strength)` tuples (loses `reasons` for speed)

## Facade Adapter: `ShardedPointerNetwork`

Drop-in replacement that returns the exact same dict shape all 34 consumers expect:

```python
class ShardedPointerNetwork:
    @classmethod
    def load(cls) -> dict:
        """Auto-detect format. Returns same dict as json.load(pointer-network.json)."""
        if MONO_PATH.exists():
            return json.load(open(MONO_PATH))
        if SHARD_DIR.exists():
            return cls._load_sharded(SHARD_DIR)

    @classmethod
    def load_node(cls, node_id: str) -> dict:
        """Load single node without loading entire graph. Sharded-only optimization."""

    @classmethod
    def append_edge(cls, from_id, to_id, weight, reasons, strength):
        """O(1) edge addition: update edge file + append to JSONL + invalidate cache."""
```

## Backward Compatibility: Phased Rollout

1. **Phase 1**: Run migration, keep monolithic file, validate round-trip
2. **Phase 2**: Update `pointer_query.py` to use `ShardedPointerNetwork.load()` — returns same dict, nothing else changes
3. **Phase 3**: Update 5 coordination scripts (network_health, network_version, route_tracker, auto_classify, repair)
4. **Phase 4**: Batch-update ~28 pointer-routes scripts (search-and-replace load pattern)
5. **Phase 5**: Rename `pointer-network.json` → `.json.bak`, adapter auto-loads from shards

## Validation Checklist
1. Same set of node IDs
2. Same `domain` for every node
3. Same pointer set for every node (order-insensitive)
4. `tag_clusters` matches
5. `strength_levels` matches
6. JSONL by-type line count = total reason count
7. Canonical SHA-256 hash matches pre-migration
