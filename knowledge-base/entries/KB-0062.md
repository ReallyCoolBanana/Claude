# Nomic-Embed + FAISS GPU on Consumer Hardware (RTX 4070 Super, 12GB VRAM)

## Context
Practical deployment research for running nomic-embed-text-v1.5 embeddings with FAISS GPU indexing on consumer-grade hardware (RTX 4070 Super, 12GB VRAM). Covers model selection, Matryoshka dimensionality, FAISS GPU installation, integration gotchas, and the TEI serving alternative.

---

## 1. Model Versions: v1.5 vs v2-moe

### nomic-embed-text-v1.5
- **HuggingFace name**: `nomic-ai/nomic-embed-text-v1.5`
- **Parameters**: 137M (dense)
- **VRAM (fp16 inference)**: ~262 MB model weights + ~20% overhead = ~315 MB total
- **Max context**: 8192 tokens
- **Embedding dims**: 768 (native), truncatable to 512/256/128/64 via Matryoshka
- **Language**: English-focused
- **License**: Apache-2.0

### nomic-embed-text-v2-moe (released Feb 2025)
- **HuggingFace name**: `nomic-ai/nomic-embed-text-v2-moe`
- **Parameters**: 475M total, 305M active (MoE with 8 experts, top-2 routing)
- **VRAM (fp16 inference)**: ~950 MB model weights + overhead = ~1.1-1.2 GB
- **Max context**: 8192 tokens
- **Embedding dims**: 768 (native), truncatable to 256 via Matryoshka
- **Language**: ~100 languages (multilingual)
- **License**: Apache-2.0

**There is no "v2.0" -- the successor is v2-moe.** For English-only on constrained VRAM, v1.5 is the lighter choice. For multilingual or higher quality, v2-moe is viable on 12GB with plenty of room to spare.

## 2. Matryoshka Embedding: Using 384-dim Instead of 768-dim

**Yes, you can use 384-dim.** Matryoshka representation learning supports arbitrary truncation by taking the first N dimensions.

### Official MTEB benchmarks for v1.5:

| Dimensions | MTEB Score | Memory Savings vs 768 |
|-----------|-----------|----------------------|
| 768       | 62.28     | baseline             |
| 512       | 61.96     | 33%                  |
| 256       | 61.04     | 67%                  |
| 128       | 59.34     | 83%                  |
| 64        | 56.10     | 92%                  |

**384-dim is not an official benchmark point** but would interpolate to ~61.5 MTEB -- a loss of only ~0.8 points from full 768-dim. This is a good compromise: 50% memory savings with negligible quality loss.

### How to truncate properly:
```python
import torch.nn.functional as F
from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("nomic-ai/nomic-embed-text-v1.5", trust_remote_code=True)
embeddings = model.encode(["search_document: your text here"])

# Truncate to 384 dims
matryoshka_dim = 384
embeddings = embeddings[:, :matryoshka_dim]

# Apply layer norm then L2 normalize
import torch
embeddings = F.layer_norm(torch.tensor(embeddings), [matryoshka_dim]).numpy()
norms = np.linalg.norm(embeddings, axis=1, keepdims=True)
embeddings = embeddings / norms
```

**Important**: You must prefix inputs with task descriptors:
- Documents: `search_document: <text>`
- Queries: `search_query: <text>`
- Clustering: `clustering: <text>`
- Classification: `classification: <text>`

## 3. FAISS GPU Installation in 2026

### The old `pip install faiss-gpu` is DEAD
The original `faiss-gpu` package on PyPI has not been maintained. Do NOT use it.

### Current options (March 2026):

**Option A: `faiss-gpu-cu12` (pip, recommended for quick setup)**
```bash
# With pinned CUDA 12.1 (requires NVIDIA Driver >= R530)
pip install 'faiss-gpu-cu12[fix-cuda]'

# Or flexible CUDA 12.x
pip install faiss-gpu-cu12
```
- Latest version: 1.14.1.post1 (March 2026)
- **Unofficial** wheels by Di-Is (personal project, not Facebook/Meta)
- Supports Compute Capability 7.0-8.9 (Volta through Ada Lovelace)
- **RTX 4070 Super (CC 8.9) IS SUPPORTED**
- Requires: Linux x86_64, Python 3.9-3.12, glibc >= 2.17
- **Hopper/Blackwell (CC 9.0+) NOT supported** by current pip wheels

**Option B: conda (official Meta/Facebook)**
```bash
conda install -c pytorch -c nvidia -c conda-forge faiss-gpu=1.14.1
```
- Official builds for CUDA 11.4 and 12.1
- Linux x86_64 only
- More tested/stable than pip wheels

**Option C: Building from source**
- Only needed if you need Hopper/Blackwell support or custom CUDA
- See https://github.com/facebookresearch/faiss/blob/main/INSTALL.md

### Critical CUDA version conflict warning:
If PyTorch is in the same environment, both must link to the same CUDA version. When installing faiss-gpu-cu12 WITHOUT `[fix-cuda]`, pip may resolve to a newer CUDA than your driver supports. Using `[fix-cuda]` pins to CUDA 12.1.

## 5. Practical FAISS GPU Example

```python
import faiss
import numpy as np

dim = 384  # Matryoshka dimension
n_vectors = 100_000

# === Create GPU resources ===
res = faiss.StandardGpuResources()
# IMPORTANT: Default temp memory is ~1.5 GB! Reduce when sharing GPU:
res.setTempMemory(256 * 1024 * 1024)  # 256 MB

# === Create flat index on GPU ===
cpu_index = faiss.IndexFlatIP(dim)  # Inner Product (cosine sim when normalized)
gpu_index = faiss.index_cpu_to_gpu(res, 0, cpu_index)  # device 0

# === Add vectors ===
vectors = np.random.randn(n_vectors, dim).astype('float32')
faiss.normalize_L2(vectors)  # Normalize for cosine similarity
gpu_index.add(vectors)

# === Search ===
query = np.random.randn(1, dim).astype('float32')
faiss.normalize_L2(query)
distances, indices = gpu_index.search(query, k=10)

# === Add more vectors incrementally ===
new_vectors = np.random.randn(5000, dim).astype('float32')
faiss.normalize_L2(new_vectors)
gpu_index.add(new_vectors)  # Just call add() again

print(f"Total vectors: {gpu_index.ntotal}")  # 105000
```

### Incremental adds with ID tracking (IndexIDMap):
```python
base = faiss.IndexFlatIP(dim)
cpu_index = faiss.IndexIDMap(base)
gpu_index = faiss.index_cpu_to_gpu(res, 0, cpu_index)

# Add with explicit IDs
ids = np.arange(1000).astype('int64')
vecs = np.random.randn(1000, dim).astype('float32')
faiss.normalize_L2(vecs)
gpu_index.add_with_ids(vecs, ids)
```

## 6. Save/Load FAISS Index to/from Disk

### Critical rule: GPU indexes cannot be saved directly. Convert to CPU first.

```python
# === SAVE ===
cpu_index = faiss.index_gpu_to_cpu(gpu_index)
faiss.write_index(cpu_index, "my_index.faiss")

# === LOAD ===
cpu_index = faiss.read_index("my_index.faiss")
gpu_index = faiss.index_cpu_to_gpu(res, 0, cpu_index)

# === Memory-mapped loading (IVF indexes only, reduces RAM) ===
cpu_index = faiss.read_index("my_ivf_index.faiss",
                              faiss.IO_FLAG_MMAP | faiss.IO_FLAG_READ_ONLY)
```

### Workflow for incremental persistence:
1. Load from disk (CPU)
2. Transfer to GPU
3. Add new vectors
4. Transfer back to CPU
5. Write to disk

For flat indexes with 384-dim float32 at 1M vectors: index file ~= 1M * 384 * 4 bytes = ~1.5 GB.

## 7. FAISS + sentence-transformers Gotchas

### dtype: FAISS requires float32
```python
embeddings = model.encode(texts, normalize_embeddings=True)
embeddings = np.array(embeddings, dtype=np.float32)
```

### Normalization: The #1 source of bugs
- Use `IndexFlatIP` (Inner Product) with normalized vectors for cosine similarity
- Use `normalize_embeddings=True` in `model.encode()`
- **You MUST normalize BOTH corpus AND query embeddings**
- `faiss.normalize_L2()` modifies arrays in-place -- if working with HF Datasets, the dataset column may NOT be updated
- **Re-normalize after Matryoshka truncation**

### Inner Product vs L2:
- `IndexFlatIP`: Returns similarity scores (higher = more similar). With normalized vectors, scores are cosine similarity in [0, 1]
- `IndexFlatL2`: Returns squared L2 distances (lower = more similar)
- **Recommendation**: Use `IndexFlatIP` with `normalize_embeddings=True`

### Clean integration pattern:
```python
from sentence_transformers import SentenceTransformer
import faiss
import numpy as np

model = SentenceTransformer("nomic-ai/nomic-embed-text-v1.5", trust_remote_code=True)

# Encode with normalization
docs = ["search_document: " + t for t in texts]
embeddings = model.encode(docs, normalize_embeddings=True, batch_size=64)
embeddings = embeddings[:, :384].astype(np.float32)  # Matryoshka truncation
faiss.normalize_L2(embeddings)  # Re-normalize after truncation!

# Build index
index = faiss.IndexFlatIP(384)
index.add(embeddings)

# Query
q = model.encode(["search_query: my question"], normalize_embeddings=True)
q = q[:, :384].astype(np.float32)
faiss.normalize_L2(q)
D, I = index.search(q, k=10)
```

## 8. Running FAISS and sentence-transformers on the SAME GPU

### VRAM Budget for RTX 4070 Super (12 GB):

| Component | VRAM Usage |
|-----------|-----------|
| nomic-embed-text-v1.5 (fp16) | ~315 MB |
| FAISS StandardGpuResources (default temp) | ~1,500 MB |
| FAISS StandardGpuResources (reduced temp) | ~256 MB |
| FAISS flat index (1M vectors, 384-dim) | ~1,536 MB |
| PyTorch CUDA context overhead | ~300-500 MB |
| sentence-transformers batch encoding overhead | ~200-500 MB |
| **Total (1M vectors, reduced temp)** | **~2.8-3.1 GB** |
| **Remaining for OS/display** | **~8.9-9.2 GB** |

### Key findings:
- **It works fine on 12GB** for typical index sizes (up to several million vectors at 384-dim)
- `StandardGpuResources()` allocates ~1.5 GB of temp memory by DEFAULT -- **always call `res.setTempMemory(256 * 1024 * 1024)` when sharing GPU**
- sentence-transformers has a known VRAM leak: embeddings accumulate on GPU. Fix: move embeddings to CPU and call `torch.cuda.empty_cache()`
- PyTorch and FAISS share the same CUDA context, no double-allocation

### Practical advice:
1. Reduce FAISS temp memory with `setTempMemory()`
2. Use smaller batch sizes for encoding (32-64)
3. For very large indexes (>1M vectors), consider keeping FAISS on CPU
4. Monitor with `nvidia-smi` during development

## 9. Performance: Embedding Speed on Consumer GPUs

### Specific benchmarks are scarce, but estimates:

**nomic-embed-text-v1.5 (137M params) on RTX 4070 Super**:
- sentence-transformers with batch_size=64: likely ~2,000-5,000 sentences/sec (short sentences < 128 tokens)
- For 8192-token documents: ~50-200 docs/sec
- ONNX Runtime backend can provide 2-3x speedup over default PyTorch
- Flash Attention + SwiGLU provide ~25% speedup over GeLU-based models

**For reference, all-MiniLM-L6-v2 (22M params)**:
- CPU: 5,000-14,000 sentences/sec

### Speedup strategies:
1. Increase batch size: `model.encode(texts, batch_size=64)`
2. Try ONNX backend: `SentenceTransformer(..., backend="onnx")`
3. Use fp16 precision
4. For production throughput: use TEI (see section 10)

## 10. Alternative: Hugging Face Text Embeddings Inference (TEI)

### What is TEI?
A Rust-based inference server for embedding models by HuggingFace. Dramatically faster than in-process sentence-transformers for production/concurrent workloads.

### Key advantages over sentence-transformers:
- **Token-based dynamic batching**: 10x+ throughput improvement
- **Flash Attention + cuBLASLt**: Optimized CUDA kernels
- **No Python GIL**: Rust eliminates Python threading bottleneck
- **OpenAI-compatible API**: Drop-in replacement
- **Prometheus metrics + OpenTelemetry tracing**

### Running TEI with nomic-embed-text-v1.5:
```bash
docker run --gpus all -p 8080:80 \
  -v $PWD/data:/data \
  --pull always ghcr.io/huggingface/text-embeddings-inference:cuda-1.9 \
  --model-id nomic-ai/nomic-embed-text-v1.5
```

For RTX 4070 (Ada Lovelace, CC 8.9), use the `89` tagged image if available:
```bash
ghcr.io/huggingface/text-embeddings-inference:89-1.8.3
```

### Querying TEI:
```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8080/v1", api_key="dummy")
response = client.embeddings.create(
    input=["search_document: Hello world"],
    model="text-embeddings-inference"
)
embedding = response.data[0].embedding
```

### TEI vs sentence-transformers decision:

| Use Case | Recommendation |
|----------|---------------|
| Prototyping / notebooks | sentence-transformers |
| Batch processing (offline) | sentence-transformers or TEI |
| Production API serving | TEI |
| Concurrent users | TEI (handles batching) |
| Need Matryoshka truncation | sentence-transformers (more control) |

### Caveat:
Some models produce slightly different embeddings between TEI and sentence-transformers. For nomic-embed-text-v1.5 (BERT-based) this should be fine, but always verify with a cosine similarity check.

## Lessons Learned

1. **FAISS GPU installation is messy**: The official `faiss-gpu` pip package is abandoned. Use `faiss-gpu-cu12` (unofficial but actively maintained) or conda.
2. **Matryoshka 384-dim is a sweet spot**: 50% memory savings for ~0.8 MTEB points loss.
3. **StandardGpuResources defaults are aggressive**: 1.5 GB temp memory by default. Always reduce when sharing GPU.
4. **Normalization bugs are the #1 FAISS integration issue**: Use `normalize_embeddings=True` everywhere and use `IndexFlatIP`.
5. **12 GB VRAM is plenty** for nomic v1.5 + FAISS GPU with millions of 384-dim vectors.
6. **TEI is significantly faster** than sentence-transformers for serving, but sentence-transformers is simpler for development.
7. **v2-moe exists but is NOT called "v2.0"**: MoE model at ~1.9 GB, still fits 12 GB easily.

## Recommendations

1. Start with `pip install 'faiss-gpu-cu12[fix-cuda]'` for RTX 4070 Super
2. Use 384-dim Matryoshka embeddings for memory/quality tradeoff
3. Always call `res.setTempMemory(256 * 1024 * 1024)` when sharing GPU
4. Use `IndexFlatIP` with `normalize_embeddings=True` -- not `IndexFlatL2`
5. For production serving, deploy TEI in Docker
6. If you need multilingual, consider v2-moe
7. Re-normalize embeddings after Matryoshka truncation
