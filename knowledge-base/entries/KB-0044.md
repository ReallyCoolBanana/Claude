# System Health Audit Report

## Context
Think Tank Gamma performed a comprehensive system health audit covering data quality, remaining bugs, naming standards, and operational weaknesses. This updates findings from KB-0031 (which claimed the sources index was "catastrophically broken") and KB-0041 (which fixed 4 TOCTOU bugs).

## Method
Cross-referenced all indexes against the filesystem. Validated YAML frontmatter against index.json for every KB entry. Cataloged all TOCTOU bugs (fixed and remaining). Audited naming conventions against SOP-029. Checked SOP tool references against the scripts index.

## Result

### Overall Health: MODERATE
- 3 critical issues, 7 high, 6 medium, 3 low

### Sources Index: FIXED (Corrects KB-0031)
KB-0031 reported the sources index was catastrophically broken. **This is no longer true.** All 41 entries match their SRC-*.json files (names, URLs, data_types all consistent). One issue remains: SRC-0018 and SRC-0039 are duplicates (both FRED API).

### KB Drift: 83% of Entries Missing Titles
34 of 41 KB entries lack the `title` field in YAML frontmatter. Titles exist only in index.json, making the index the sole source of truth. If the index were regenerated from files, all titles would be lost. This is scriptable to fix (copy titles from index into each file's frontmatter).

### TOCTOU Bugs: 18 Remain
Of 22 cataloged TOCTOU bugs, 4 were fixed by TEAM-0032. **18 remain unfixed**, including 2 critical:
- **TOCTOU-WS-001** (critical): `complete_work` in work_stealing.py lacks BEGIN IMMEDIATE, allowing result overwrites between authorization check and completion update.
- **TOCTOU-HP-001** (critical): `fulfill_help` in help_protocol.py has two non-atomic UPDATEs; crash between them leaves inconsistent state.

Severity breakdown: 2 critical, 7 high, 9 medium-low.

### 15 Orphaned Scripts
15 scripts exist on disk but are not in storage/scripts/index.json. These include actively-used tools: mcp_kb_server.py, smart_read.py, smart_write.py, smart_search.py, query_kb.py, semantic_indexer.py, validate_naming.py. Teams discovering tools via the index will not find them.

### Naming Standard Violations
- 11 Python scripts use kebab-case instead of snake_case (violates SOP-029)
- 3 SOP files use non-standard filenames instead of sop_NNN_name.json pattern

### Other Issues
- TEAM-0032.md exists on disk but is not in teams/sessions/index.json (session_count shows 30, should be 31)
- Index.json tag_index has duplicate 'sqlite' key from different tag groups

## Lessons Learned
- Previous audit findings (KB-0031) can become stale. The sources index was fixed but the KB entry was never updated, causing teams to waste time on a non-problem.
- Data hygiene debt accumulates silently. 83% title drift and 15 orphaned scripts happened gradually across many sessions.
- TOCTOU bugs in coordination code are a real risk for multi-agent sessions. The 2 critical bugs can cause silent data loss.

## Recommendations
1. **Immediate (5 min):** Index the 15 orphaned scripts in storage/scripts/index.json.
2. **Immediate (2 min):** Add TEAM-0032 to teams/sessions/index.json.
3. **Quick win (10 min):** Backfill title field into all 34 KB entries from index.json (scriptable).
4. **Next bug-fix session (1 hr):** Fix TOCTOU-WS-001 and TOCTOU-HP-001 with BEGIN IMMEDIATE + WHERE guards.
5. **Maintenance:** Rename 11 kebab-case scripts to snake_case per SOP-029.
6. **Maintenance:** Merge duplicate FRED sources (SRC-0018 + SRC-0039).
