# Concurrent Work Distribution Patterns: Deep Research Survey

## Context
Comprehensive survey of concurrent work distribution patterns from systems research, production runtimes, distributed schedulers, and game engines. Focus on patterns applicable to SQLite WAL + JSONL bus coordination.

## Method
Research across academic papers, runtime implementations (Go, Tokio, Java ForkJoinPool), distributed frameworks (Spark, Ray, Dask, Celery), and game engine job systems. 30+ sources analyzed.

## Result

### 1. Classical Work-Stealing Algorithms

#### Chase-Lev Deque
- Owner pushes/pops from bottom (LIFO); thieves steal from top (FIFO)
- Contention ONLY when thief and owner race on last item
- **SQLite adaptation**: Per-agent partitioned queues with `WHERE owner_team = ? LIMIT N`

#### Go Scheduler (G-M-P Model)
- Each P has 256-slot local run queue + `runnext` single-slot fast path
- Empty P steals **half** of random victim's queue
- Global queue checked only 1/61 of scheduling rounds
- **SQLite adaptation**: Per-agent local queues, batch steal-half, global overflow checked infrequently

#### Tokio Runtime (Rust)
- LIFO slot: most recently spawned task runs immediately next (cache locality)
- LIFO disabled after 3 consecutive uses to prevent starvation
- **SQLite adaptation**: LIFO slot is just an in-process variable, never touches DB

#### Java ForkJoinPool
- Thieves steal from tail (FIFO) — get the **largest** chunks (coarse work)
- Provides `getStealCount()` for runtime tuning
- **SQLite adaptation**: `ORDER BY priority DESC, created_at ASC LIMIT N` — steal oldest/largest first

### 2. Multi-Agent Task Allocation Patterns

#### Contract Net Protocol
- Manager broadcasts task → contractors bid → manager awards
- No shared queue contention — communication is message-based
- Existing `help_protocol.py` is a simplified version
- Best for heterogeneous task types

#### Auction-Based (SSI, PSI, CBBA)
- Sequential/Parallel Single-Item auctions, or Consensus-Based Bundle Algorithm
- Within 1.5x of optimal allocation vs random stealing (arbitrarily bad)
- Too heavy for fine-grained tasks; best for coarse assignment (team→topic)

#### Market-Based / Token-Based
- Agents hold "tokens" as currency; task prices rise with demand
- Busy agents run out of tokens; idle agents accumulate them
- Self-balancing without explicit coordination

### 3. Lock-Free Queue Designs

#### LCRQ (Linked Concurrent Ring Queue)
- FAA (fetch-and-add) instead of CAS for slot allocation — never fails
- **Key insight for SQLite**: Separate "which slot?" (one counter update) from "what's in slot?" (no contention)
- Maps to: `UPDATE counters SET next_slot = next_slot + 1 RETURNING next_slot`

#### NBLFQ (Non-Blocking Lock-Free Queue, IPDPS 2025)
- Adaptive: simple fast path at low contention, complex sync at high contention
- **SQLite insight**: Detect contention via retry count from `_retry_on_busy`, switch strategy

### 4. Distributed Scheduler Patterns

#### Ray (Bottom-Up + Ownership)
- Tasks first try local scheduler; forward to global only if local is full
- **Ownership model**: Process that creates object manages its lifecycle
- **SQLite impact**: If 80% of tasks consumed by creator, DB traffic drops 80%

#### Dask (Centralized Dynamic)
- Single scheduler maintains full task graph, schedules where data lives
- Workers never contend with each other
- **SQLite adaptation**: Single "scheduler agent" reads queue, dispatches via JSONL

#### Celery (Broker-Based)
- Key patterns: named queues (routing by type), prefetch count (take N at once), visibility timeout (reclaim from dead workers)
- **Prefetch = batch claim**: `LIMIT N` in steal queries reduces round-trips by Nx

### 5. Batch Size Research

#### StealHalf
- **Provably better** load distribution than single-item stealing
- Expected load stays within constant of system average
- SQL: `LIMIT (SELECT COUNT(*)/2 FROM work_queue WHERE status = 'queued' AND owner_team = ?)`
- O(log P) steal operations total vs O(N) for single-item (P=processors)

#### Adaptive Batch Sizing (Work-Stealing Tree Scheduler)
- Optimal batch = minimum items where queue access cost is amortized by work
- Formula: `batch_size = max(1, steal_latency_ms / avg_task_duration_ms * 2)`
- Auto-tunes based on observed contention

#### Prefetch at Low-Water Mark (Latency-Hiding, CMU)
- Issue steal request **before** local queue is empty
- When queue drops below threshold (e.g., 2 items), fire async steal in background
- Eliminates idle time between "empty" and "stolen"

### 6. Game Engine Patterns

#### Job System with Dependency Counters
- Jobs have atomic dependency counters; completing a job decrements dependents
- When counter hits zero → auto-enqueue
- SQL: `UPDATE pipeline_stages SET remaining_deps = remaining_deps - 1 RETURNING *`
- Eliminates dependency polling

#### LIFO Slot (Naughty Dog Fiber Model)
- When waiting for dependency, pick up unrelated work instead of blocking
- Behavioral pattern: agents should never idle while dependencies resolve

#### Layered Independent Job Batches
- Pre-sort jobs into layers where everything in a layer is independent
- Zero contention within a layer
- SQL: `WHERE layer_id = ? AND status = 'queued' LIMIT N`

## Lessons Learned

1. **Local-first scheduling (Ray model) is the highest-impact pattern** — if 80% of tasks stay local, DB writes drop 80%
2. **StealHalf reduces total steals from O(N) to O(log P)** — provably optimal
3. **LIFO slot is free performance** — one in-process variable eliminates a DB round-trip for the most common case
4. **Prefetch at low-water mark eliminates idle gaps** — overlap computation with steal latency
5. **Counter-based dependency triggering** replaces polling with atomic decrements

## Recommendations (Ranked by Impact-to-Effort)

| Rank | Pattern | Impact | Effort | Key Change |
|------|---------|--------|--------|------------|
| 1 | **Batch stealing (StealHalf)** | High | Low | Change `LIMIT 1` to `LIMIT N` |
| 2 | **Local-first scheduling (Ray)** | High | Medium | Agents consume own output before posting to DB |
| 3 | **Prefetch with low-water mark** | High | Low | Steal before queue empty, not after |
| 4 | **Per-agent partitioned queues** | Medium | Medium | Each agent has "home" partition |
| 5 | **LIFO slot (Tokio)** | Medium | Low | In-process variable for most-recent task |
| 6 | **Adaptive batch sizing** | Medium | Medium | Track steal latency, auto-tune batch size |
| 7 | **Counter-based dependency triggering** | Medium | Low | `remaining_deps - 1` atomic update |
| 8 | **Global queue ratio (Go 1/61)** | Low | Low | Check global queue every N rounds |

**Highest-leverage combination**: Patterns 1+2+3+5 together reduce SQLite work-queue transactions by estimated **80-90%** vs single-item stealing.

# Token-Efficient I/O System & File Naming Standards

## Context
AI agents in this repository spend 96.7% of query tokens reading irrelevant data. A full knowledge-base index read costs 6,100 tokens to find entries matching a simple filter — only ~200 tokens are useful. Creating a new KB entry costs 12,711 tokens due to template overhead and full index read-modify-write cycles. 28 prior team sessions and 142 think tank ideas identified this as the #1 efficiency bottleneck.

## Method
Dual operation with 12+ agent teams across 5 phases:
- **Operation A1** (File Naming SOPs): Audited 295 files across 75 directories, found 10 divergent index schemas, mixed naming conventions, and duplicate entries. Designed unified naming conventions with controlled vocabulary. Drafted SOPs 029-031.
- **Operation B2** (Token-Efficient I/O): Measured token costs across 93 files (202K tokens total). Designed tiered indexing (Level 0-3), SQLite+FTS5 schema, and query protocol. Built 7 Python tools.

## Result
### Tools Built (all Python stdlib, zero dependencies)
1. `storage/scripts/validate_naming.py` — Naming convention linter (found 14 errors, 22 warnings)
2. `storage/scripts/auto_index.py` — Auto-regenerates all index.json files to unified schema
3. `storage/scripts/import_to_db.py` — Populates SQLite+FTS5 database from file-based data
4. `storage/scripts/query_kb.py` — Token-efficient CLI queries (summary, list, search, read, tags, related)
5. `storage/scripts/smart_read.py` — Field-level file reading (93-97% token reduction)
6. `storage/scripts/smart_write.py` — Minimal-overhead entry creation (99.2% token reduction)
7. `storage/scripts/smart_search.py` — Cross-resource search with token budget awareness (98.5% reduction)

### Database
- `storage/data/knowledge.db` — SQLite with FTS5, 173 entries, 497 tags, 125 relationships
- 5 tables, 12 views, 6 triggers, 14 indexes
- WAL mode for concurrent multi-agent access
- Tiered indexes: SUMMARY.json (~50 tokens) + INDEX_COMPACT.json (~500 tokens) per directory

### SOPs Created
- SOP-029: File Creation & Naming Standards
- SOP-030: Index Management & Maintenance
- SOP-031: AI-Efficient Language Guide

### Token Savings
| Operation | Old Tokens | New Tokens | Reduction |
|-----------|-----------|-----------|-----------|
| Browse KB | 6,100 | 50 | 99.2% |
| Search KB | 6,100 | 100 | 98.4% |
| Read entry fields | 2,000+ | 50-88 | 93-97% |
| Create entry | 12,711 | ~200 | 98.6% |
| Orientation | 12,000+ | 50 | 99.6% |

## Lessons Learned
1. Tiered indexing (L0 summary → L1 compact → L2 full → L3 file) is the single highest-impact pattern for token efficiency.
2. SQLite FTS5 with external-content mode provides sub-millisecond search with no data duplication.
3. Unified index schemas across directories eliminate confusion and reduce code complexity.
4. Field-level projection (reading only requested fields) delivers 93-97% savings on every read.
5. Think tank parallel ideation (142 ideas from 3 teams) provided high-quality design inputs worth the agent investment.

## Recommendations
1. **Adopt tiered indexes immediately**: Read SUMMARY.json first, INDEX_COMPACT.json second, full index only when needed.
2. **Use query_kb.py for all data lookups**: Replaces manual file reading with token-efficient queries.
3. **Use smart_write.py for all entry creation**: Auto-generates IDs, fills boilerplate, updates indexes.
4. **Run auto_index.py after any file changes**: Keeps all indexes consistent with unified schema.
5. **Run validate_naming.py before commits**: Catches naming violations early.
6. **Fix the 14 naming errors found**: Rename kebab-case scripts to snake_case, add SOP prefixes.
