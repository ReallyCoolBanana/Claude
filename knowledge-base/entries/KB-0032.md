# Token-Efficient I/O System & File Naming Standards

## Context
AI agents in this repository spend 96.7% of query tokens reading irrelevant data. A full knowledge-base index read costs 6,100 tokens to find entries matching a simple filter — only ~200 tokens are useful. Creating a new KB entry costs 12,711 tokens due to template overhead and full index read-modify-write cycles. 28 prior team sessions and 142 think tank ideas identified this as the #1 efficiency bottleneck.

## Method
Dual operation with 12+ agent teams across 5 phases:
- **Operation A1** (File Naming SOPs): Audited 295 files across 75 directories, found 10 divergent index schemas, mixed naming conventions, and duplicate entries. Designed unified naming conventions with controlled vocabulary. Drafted SOPs 029-031.
- **Operation B2** (Token-Efficient I/O): Measured token costs across 93 files (202K tokens total). Designed tiered indexing (Level 0-3), SQLite+FTS5 schema, and query protocol. Built 7 Python tools.

## Result
### Tools Built (all Python stdlib, zero dependencies)
1. `storage/scripts/validate_naming.py` — Naming convention linter (found 14 errors, 22 warnings)
2. `storage/scripts/auto_index.py` — Auto-regenerates all index.json files to unified schema
3. `storage/scripts/import_to_db.py` — Populates SQLite+FTS5 database from file-based data
4. `storage/scripts/query_kb.py` — Token-efficient CLI queries (summary, list, search, read, tags, related)
5. `storage/scripts/smart_read.py` — Field-level file reading (93-97% token reduction)
6. `storage/scripts/smart_write.py` — Minimal-overhead entry creation (99.2% token reduction)
7. `storage/scripts/smart_search.py` — Cross-resource search with token budget awareness (98.5% reduction)

### Database
- `storage/data/knowledge.db` — SQLite with FTS5, 173 entries, 497 tags, 125 relationships
- 5 tables, 12 views, 6 triggers, 14 indexes
- WAL mode for concurrent multi-agent access
- Tiered indexes: SUMMARY.json (~50 tokens) + INDEX_COMPACT.json (~500 tokens) per directory

### SOPs Created
- SOP-029: File Creation & Naming Standards
- SOP-030: Index Management & Maintenance
- SOP-031: AI-Efficient Language Guide

## Lessons Learned
1. Tiered indexing (L0 summary → L1 compact → L2 full → L3 file) is the single highest-impact pattern for token efficiency.
2. SQLite FTS5 with external-content mode provides sub-millisecond search with no data duplication.
3. Unified index schemas across directories eliminate confusion and reduce code complexity.
4. Field-level projection (reading only requested fields) delivers 93-97% savings on every read.
5. Think tank parallel ideation (142 ideas from 3 teams) provided high-quality design inputs worth the agent investment.

## Recommendations
1. **Adopt tiered indexes immediately**: Read SUMMARY.json first, INDEX_COMPACT.json second, full index only when needed.
2. **Use query_kb.py for all data lookups**: Replaces manual file reading with token-efficient queries.
3. **Use smart_write.py for all entry creation**: Auto-generates IDs, fills boilerplate, updates indexes.
4. **Run auto_index.py after any file changes**: Keeps all indexes consistent with unified schema.
5. **Run validate_naming.py before commits**: Catches naming violations early.
6. **Fix the 14 naming errors found**: Rename kebab-case scripts to snake_case, add SOP prefixes.
