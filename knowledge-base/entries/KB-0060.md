# Local GPU AI Inference Frameworks: Comprehensive Guide for RTX 4070 Super (12GB VRAM)

## Context
Deep research into all major local LLM inference frameworks relevant to running models on an RTX 4070 Super (12GB VRAM). Covers architecture, performance, compatibility, and best practices as of March 2026.

## Frameworks Compared

### 1. vLLM (v0.17.1, March 2026)
- **What**: High-performance serving with PagedAttention and continuous batching
- **Performance**: 60-80 tok/s on 7B AWQ-4bit models on RTX 4070 class GPUs
- **VRAM**: 7B FP16 needs ~14GB (too big), 7B INT4/AWQ needs ~4-5GB (fits)
- **Best for**: Production serving with high concurrency, multi-user API endpoints
- **RTX 4070 Super**: Fully compatible (CUDA SM 8.9, Ada Lovelace). Stick to 7B-8B at 4-bit.
- **Gotchas**: V1 engine now default, requires PyTorch 2.9+/CUDA 12.9. Overkill for single-user.

### 2. llama.cpp / GGUF (b8303)
- **What**: C/C++ inference engine, most portable option with full quantization support
- **Performance**: 40-58 tok/s on 7B Q4_K_M; varies by quantization level
- **Quantization levels**: Q2_K (2.6bpw), Q3_K_M (3.3bpw), Q4_K_M (4.8bpw), Q5_K_M (5.7bpw), Q6_K (6.6bpw), Q8_0 (8.5bpw)
- **VRAM at Q4_K_M**: 7B=4.1GB, 13B=7.4GB, 34B=too large for 12GB
- **Best for**: Local single-user inference, maximum model compatibility
- **RTX 4070 Super**: Excellent. CUDA backend fully optimized for Ada Lovelace.

### 3. Ollama (v0.17.5)
- **What**: Wrapper around llama.cpp with Docker-like model management
- **Performance**: 40-62 tok/s (matches llama.cpp backend)
- **Best for**: Easiest setup, single-user, model management
- **RTX 4070 Super**: Pull and run. `ollama run llama3.1:8b-instruct-q4_K_M` just works.
- **Gotchas**: Single-user only, no batching, overhead vs raw llama.cpp

### 4. ExLlamaV2 (v0.3.2)
- **What**: Fastest consumer GPU inference engine, GPTQ/EXL2 quantization
- **Performance**: 50+ tok/s on 7B EXL2 4bpw — fastest option for consumer GPUs
- **Best for**: Maximum throughput on single consumer GPU
- **RTX 4070 Super**: Sweet spot hardware. EXL2 format gives fine-grained bpw control (3.0-8.0).
- **Gotchas**: Smaller ecosystem than llama.cpp, EXL2 models less common than GGUF

### 5. TensorRT-LLM (25.09 NGC)
- **What**: NVIDIA's optimized inference engine
- **Performance**: ~30% faster than llama.cpp on same models
- **Best for**: Maximum performance if willing to deal with complex setup
- **RTX 4070 Super**: Supported but many features optimized for Hopper/Blackwell. FP8 works but not all kernels validated.
- **Gotchas**: Complex build process, NVIDIA account required, frequent breaking changes

### 6. SGLang (v0.4.3)
- **What**: Structured generation language with RadixAttention
- **Performance**: 29% faster than vLLM for standard serving, 3x faster JSON decoding
- **Best for**: Structured output (JSON, function calling), constrained generation
- **RTX 4070 Super**: Good fit for schema-constrained inference tasks

### 7. LocalAI
- **What**: OpenAI-compatible API supporting multiple backends (llama.cpp, whisper, etc.)
- **Performance**: Matches underlying engine
- **Best for**: Drop-in OpenAI API replacement with local models

### 8. TGI (HuggingFace)
- **Status**: IN MAINTENANCE MODE since Dec 2025. Do not use for new projects.
- **Replacement**: Migrate to vLLM or SGLang

### 9. ONNX Runtime GPU (v1.24.1)
- **What**: Cross-platform inference runtime
- **Performance**: ~14% over PyTorch on GPU for non-LLM models
- **Best for**: Custom models (like PNAM), not for LLM serving
- **RTX 4070 Super**: Good for serving PNAM, embedding models, classifiers

### 10. torch.compile (PyTorch 2.9+)
- **What**: JIT compilation with CUDA graphs
- **Performance**: 1.2-2x speedup over eager mode
- **Best for**: Custom model training and inference optimization
- **RTX 4070 Super**: Use for PNAM training. Free speedup.

## Multi-Model Serving on 12GB

- **Model swapping**: Load one model at a time, swap on demand (~2-5s per swap)
- **Small + large**: Run a small model (1-3B always loaded, ~2GB) + swap larger models
- **Ollama**: Handles model swapping automatically, keeps recent model in memory
- **Dedicated split**: PNAM (~1.3GB) + FAISS (~1.5GB PQ) + 7B Q4 (~4.1GB) = 6.9GB total, fits!

## Lessons Learned
- ExLlamaV2 is fastest for raw throughput on consumer GPUs but llama.cpp/GGUF has the broadest model support
- SGLang's structured output is compelling for schema-constrained tasks (JSON graph data)
- TGI is dead — migrate away
- torch.compile gives free 1.2-2x speedup for custom models like PNAM
- 12GB VRAM comfortably runs 7-8B models at Q4 with room for PNAM and FAISS alongside

## Recommendations
- Use **Ollama** for easy model management and the OpenAI-compatible API
- Use **ExLlamaV2** when you need maximum throughput for batch processing
- Use **torch.compile** for PNAM training and inference
- Use **ONNX Runtime** for deploying the trained PNAM model in production
- Budget VRAM as: PNAM (1.3GB) + FAISS (1.5GB) + LLM (4-5GB) + headroom (4-5GB)
