# PyKEEN Link Prediction on Custom Knowledge Graphs (1K-80K Nodes)

## Context
Practical research on using PyKEEN for link prediction on the pointer network (currently ~37K edges, targeting 1M). Covers conversion from adjacency lists, model selection, hyperparameter tuning, GPU training times, and incremental updates.

## 1. Converting Pointer Network to PyKEEN Triples

PyKEEN requires `(head, relation, tail)` string arrays:

```python
import numpy as np, json, glob
from pykeen.triples import TriplesFactory

triples = []
for f in glob.glob("storage/pointer-network/edges/by-source/*.edges.json"):
    source = f.split("/")[-1].replace(".edges.json", "")
    for edge in json.load(open(f)):
        triples.append([source, edge.get("type", "related"), edge["to"]])

tf = TriplesFactory.from_labeled_triples(np.array(triples, dtype=str))
training, testing, validation = tf.split([0.8, 0.1, 0.1], random_state=42)
```

From NetworkX:
```python
triples = np.array([
    [str(u), data['relation'], str(v)]
    for u, v, data in G.edges(data=True)
], dtype=str)
```

## 2. Model Selection: RotatE Wins

| Property | TransE | ComplEx | RotatE |
|---|---|---|---|
| Symmetry (shared_tags) | Cannot model | Can model | Can model |
| Antisymmetry (explicit_reference) | Can model | Can model | Can model |
| Inversion (backlink) | Can model | Can model | Can model |
| Composition patterns | Can model | Cannot infer | Can model |
| 1-to-N / N-to-N relations | Poor | Good | Good |

**RotatE handles all four relation pattern types.** TransE fails on symmetric relations like `shared_tags`. ComplEx cannot handle composition. A 2025 drug discovery study confirmed RotatE as "often the best performing model" across diverse datasets.

## 3. Hyperparameters for Small-to-Medium Graphs

| Parameter | 1K-10K nodes | 10K-50K nodes | 50K-80K nodes |
|---|---|---|---|
| embedding_dim | 32-128 | 64-256 | 128-512 |
| num_epochs | 200-500 | 100-300 | 100-300 |
| batch_size | 128-512 | 256-1024 | 512-2048 |
| learning_rate | 1e-3 to 1e-2 | 1e-4 to 1e-3 | 1e-4 to 1e-3 |
| num_negs_per_pos | 16-64 | 32-128 | 32-128 |

Use PyKEEN's built-in Optuna HPO:
```python
from pykeen.hpo import hpo_pipeline
hpo_result = hpo_pipeline(
    n_trials=30, training=training, testing=testing, validation=validation,
    model='RotatE',
    model_kwargs_ranges=dict(embedding_dim=dict(type=int, low=64, high=256, q=64)),
    training_kwargs=dict(num_epochs=200, batch_size=256),
    stopper='early', stopper_kwargs=dict(frequency=10, patience=5, relative_delta=0.002),
    device='gpu',
)
```

**Critical: smaller graphs need smaller embedding_dim to avoid overfitting. Always use early stopping.**

## 4. Training Time Estimates (RTX 4070 Super)

RotatE, embedding_dim=128, 200 epochs, sLCWA:

| Nodes | Edges | Time/Epoch | Total |
|---|---|---|---|
| 10K | 100K | ~1-3 sec | 5-10 min |
| 50K | 500K | ~5-15 sec | 20-50 min |
| 80K | 1M | ~10-30 sec | 35-100 min |

12GB VRAM is never a bottleneck under 80K nodes with embedding_dim <= 256.

## 5. Extracting Top-K Predicted Edges

```python
from pykeen.predict import predict_target

# Predict missing tails for a specific (head, relation)
pred = predict_target(
    model=result.model, head="KB-0001", relation="semantic_similarity",
    triples_factory=result.training,
)
pred_filtered = pred.filter_triples(result.training)  # remove known edges
top_20 = pred_filtered.df.head(20)
# Columns: head_label, relation_label, tail_label, score
```

**Warning: `predict_all()` without `k` parameter is prohibitively expensive. Always use `k` or `predict_target`.**

## 6. Evaluation: What's "Good"

- MRR > 0.20: Model is learning meaningful patterns
- MRR > 0.35: Good performance
- Hits@10 > 0.40: Practically useful for recommendations
- Hits@10 > 0.60: Strong predictive power

Absolute scores are not comparable across different graphs. Always compare models against each other on YOUR data.

## 7. Incremental Training

**PyKEEN does NOT support built-in incremental training.** For graphs under 80K nodes, full retraining takes under 2 hours on RTX 4070 Super — just retrain.

Workaround for existing entities only: save model checkpoint, create new TriplesFactory with same `entity_to_id` / `relation_to_id` mappings, resume training for 50 more epochs.

## 8. PyKEEN vs Alternatives

| Feature | PyKEEN | DGL-KE | TorchKGE |
|---|---|---|---|
| Models | 40+ | ~10 | ~10 |
| Built-in HPO | Yes (Optuna) | No | No |
| Auto memory optimization | Yes | No | No |
| Prediction API | Rich | Basic | Basic |
| Active (2025-26) | Yes | Minimal | Minimal |

**PyKEEN is the clear winner for custom KGs at this scale.**

## 9. Full Pipeline Example

```python
from pykeen.pipeline import pipeline
from pykeen.predict import predict_target
import numpy as np

# Train
result = pipeline(
    training=training, testing=testing, validation=validation,
    model='RotatE', model_kwargs=dict(embedding_dim=128),
    training_kwargs=dict(num_epochs=200, batch_size=256),
    stopper='early', stopper_kwargs=dict(frequency=10, patience=5, relative_delta=0.002),
    device='gpu',
)
result.save_to_directory('model_checkpoint/')

# Predict missing edges for a node
pred = predict_target(model=result.model, head="KB-0001",
                       relation="semantic_similarity", triples_factory=result.training)
top_predictions = pred.filter_triples(result.training).df.head(10)

# Add back to NetworkX graph
for _, row in top_predictions.iterrows():
    G.add_edge(row['head_label'], row['tail_label'],
               relation=row['relation_label'], predicted=True, score=float(row['score']))
```
