# Research Team Configuration Testing & System Improvements

## Context
Following the data gathering improvement loop (KB-0004, KB-0005), we needed to determine optimal agent team configurations and address system inefficiencies. This operation tested 4 research team configurations with varying agent counts, then used the findings to drive two coding teams that built archive tools and fixed efficiency issues.

## Method

### Phase 1: Research Configuration Comparison
Four configurations researched the same two topics (system inefficiencies + archive tools) in parallel:

| Config | Structure | Total Agents | Duration |
|--------|-----------|-------------|----------|
| Config 1 (Solo) | 1 lead, 0 subs | 1 | 84s |
| Config 2 (Paired) | 2 leads, 1 sub each | 4 | 56s |
| Config 3 (Triad) | 3 leads, 2 subs each | 9 | 48s |
| Config 4 (Quad) | 4 leads, 2 subs each | 12 | 102s |

### Phase 2: Coding Teams (2 teams of 3 agents)
- **Coding Team A**: Built 3 archive tools (kb_validator, index_rebuilder, cross_ref_checker)
- **Coding Team B**: Fixed 3 efficiency issues (DDG deduplication, request caching, arXiv HTTPS + error handling)

### Phase 3: Archive Team Verification
Ran all tools and verified all changes. 10/10 files passed verification.

## Result

### Research Configuration Findings

| Metric | Config 1 | Config 2 | Config 3 | Config 4 |
|--------|----------|----------|----------|----------|
| Inefficiencies found | 15 | 10 | 19 | 25 |
| Archive tools proposed | 10 | 8 | 6 | 9 |
| Self-assessed coverage | 92 | 88 | 88 | 92 |
| Duration (s) | 84 | 56 | 48 | 102 |

**Optimal configuration**: Config 3 (Triad — 3 leads + 2 subs each) provided the best efficiency ratio: 19 findings in 48s. Config 4 found 25 issues but took 102s (diminishing returns). Config 1 (Solo) was surprisingly effective at 15 findings.

### Consensus Findings (flagged by all 4 configs)
1. DuckDuckGoParser class duplicated across 4 files
2. No result caching layer
3. Manual index.json maintenance
4. Silent error handling / bare except clauses

### Tools Built
- **kb_validator.py** (SCR-0012): Found 2 real index inconsistencies on first run
- **index_rebuilder.py** (SCR-0013): Auto-rebuilds index.json from directory scans with --dry-run/--fix modes
- **cross_ref_checker.py** (SCR-0014): Validates all cross-references, detects cycles, found 8 orphan scripts

### Efficiency Fixes Applied
- **ddg_utils.py**: Shared DDG module replacing 4 copies, added rate limiting
- **request_cache.py**: File-based HTTP cache with TTL, SHA-256 keys
- **method_arxiv.py**: Fixed HTTP→HTTPS, specific exception types, removed hardcoded ML bias
- **method_wikidata.py**: Specific exception types, structured error reporting

## Lessons Learned

1. **3 agents with 2 subagents each is optimal** for research tasks of this scope. It provides enough specialization without coordination overhead. Solo agents are viable for smaller tasks.
2. **Diminishing returns above 4 agents**: Config 4 (12 agents) found only 6 more issues than Config 3 (9 agents) at 2x the duration.
3. **Solo agents find unique things**: Config 1 found stress-test artifact issues that multi-agent configs missed — different perspectives are valuable.
4. **Archive tools pay for themselves immediately**: The validator found real bugs on first run, proving the investment worthwhile.
5. **Code duplication is the most visible inefficiency**: All 4 configs independently identified the same #1 issue (DDG parser duplication).

## Recommendations

1. Use 3-agent teams with 2 subagents each for research tasks
2. Run archive tools (validator, cross-ref checker) before committing KB changes
3. Use index_rebuilder --fix to maintain index.json automatically
4. Apply the same specific-exception pattern to method_wikipedia.py
5. Consider adding archive tools to a pre-commit hook
6. Register or remove the 8 orphan stress-test scripts
