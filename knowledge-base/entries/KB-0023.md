# Dynamic Team Coordination: Help Protocol, Work Stealing, Direct Channels

## Context
TEAM-0022's 18-agent deployment revealed that teams finishing early sit idle while slower teams (Beta-1) continue working alone. This wastes capacity. Three coordination features were designed by think tanks (V2 and V3) and implemented by three parallel coding teams to solve this.

## Method
Deployed 7 teams (~20 agents) simultaneously:
- **Think Tank V2** (4 agents): Designed help request/idle reassignment features
- **Think Tank V3** (4 agents): Designed advanced features (work stealing, pipelines, load balancing)
- **Research Team** (4 agents): Collected external data on coordination algorithms from public APIs
- **Coding Team 1** (2 agents): Implemented `help_protocol.py` + `bus_cli.py` updates
- **Coding Team 2** (2 agents): Implemented `direct_channels.py`
- **Coding Team 3** (2 agents): Implemented `work_stealing.py` (includes PipelineManager + Scratchpad)
- **Standby Coding Team** (2 agents): Reserved for additional implementation

## Result
**SUCCESS** — All three modules implemented and tested. 80/80 tests pass.

### help_protocol.py (698 lines)
- Team status management (idle/working/needs_help/helping/complete)
- Work item tracking with capability requirements
- Help request/offer/accept flow with atomic `BEGIN IMMEDIATE` claims
- Idle team detection and auto-assignment with capability matching
- Bus notifications on all state transitions

### direct_channels.py (589 lines)
- Named channels: direct (peer-to-peer), topic, team, broadcast
- Team presence tracking (available/busy/helping/away)
- Progress broadcasting with bottleneck detection
- Slowest-team identification for orchestrator intervention
- Channel lifecycle: create, join, leave, archive

### work_stealing.py (677 lines)
- **WorkStealing**: Shared work queue with atomic steal via `BEGIN IMMEDIATE`
- **PipelineManager**: Multi-stage DAG pipelines with dependency tracking and auto-trigger
- **Scratchpad**: Namespaced key-value store with TTL for sharing intermediate results

### Test Coverage
- `test_help_protocol.py`: 16 tests (registration, work items, help flow, concurrency, auto-assign, bus messages)
- `test_direct_channels.py`: 33 tests (channels, messaging, presence, progress, bus events)
- `test_work_stealing.py`: 31 tests (work queue, steal concurrency, pipelines, scratchpad)

## Lessons Learned
1. **Think tank -> coding team pipeline works** — V2 design doc fed directly into coding teams' implementation.
2. **BEGIN IMMEDIATE is the concurrency primitive** — All three modules use the same atomic claim pattern for race-free assignment.
3. **Module boundaries are clean** — help_protocol (who needs help), direct_channels (how to communicate), work_stealing (what work to do) are orthogonal.
4. **80 tests in 2.8 seconds** — SQLite WAL mode handles concurrent test fixtures well.
5. **bus_cli.py as integration point** — CLI commands added for all help protocol operations, keeping the agent interface consistent.

## Recommendations
1. Integrate all three modules into `multi_team_runner.py` for automatic idle-team reassignment
2. Add bus_cli.py commands for direct_channels and work_stealing operations
3. Run a live deployment with dynamic reassignment enabled to measure throughput improvement
4. Implement the Think Tank V3 advanced features: team merging, load balancing formulas, inter-operation memory
5. Add integration tests that exercise all three modules together in a multi-process scenario
