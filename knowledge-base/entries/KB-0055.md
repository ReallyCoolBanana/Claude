# Local GPU Tasks for Pointer Network Acceleration (RTX 4070 Super)

## Context
The pointer network has grown to 310+ nodes with 4,809 edges spanning 7 domains, and the Wikipedia collection has been expanded to cover all of Wikipedia on a home PC with an RTX 4070 Super (12 GB VRAM, 7168 CUDA cores). This entry identifies concrete tasks where a local GPU can accelerate and extend the pointer network beyond what cloud-only Claude sessions can do.

## GPU-Accelerated Tasks

### 1. Local Embedding Generation for All Wikipedia Articles
**What:** Run a local embedding model (e.g., `sentence-transformers/all-MiniLM-L12-v2` or `nomic-embed-text-v1.5`) on your full Wikipedia corpus to produce dense vector embeddings for every article.
**Why:** The pointer network currently uses tag-based and explicit-reference edges. Dense embeddings enable *semantic similarity* edges — discovering connections that share no tags but are conceptually related.
**How:**
- Use `sentence-transformers` with CUDA backend
- Batch-embed all article text-cache files (GPU processes ~5000 articles/min on 4070S)
- Store as `.npy` or in a local Qdrant/ChromaDB instance
- Export top-k similarity pairs as new `semantic_similarity` edges in pointer-network.json
**VRAM fit:** MiniLM-L12 uses ~500 MB; even `bge-large-en-v1.5` fits easily in 12 GB

### 2. Pointer Network Edge Weight Optimization via Graph Neural Network
**What:** Train a lightweight GNN (e.g., GraphSAGE or GAT) on the pointer network to learn optimal edge weights from traversal patterns.
**Why:** Current weights are heuristic (tag overlap counts). A GNN can learn which edges are actually useful for pathfinding by training on the 90+ route logs from Run-006.
**How:**
- Convert pointer-network.json to PyTorch Geometric `Data` object
- Use Run-006 route logs as training signal (successful paths = positive, dead ends = negative)
- Train 2-layer GraphSAGE on 4070S (~seconds per epoch for this graph size)
- Export learned weights back to pointer-network.json
**VRAM fit:** Trivial — graph is tiny for GNN standards

### 3. Semantic Search Index for Claude Sessions
**What:** Run a local vector search server (Qdrant or FAISS GPU) that Claude can query via a local API to find relevant knowledge base entries, scripts, and Wikipedia articles by semantic meaning.
**How:**
- Embed all KB entries, scripts (docstrings), SOPs, and Wikipedia articles
- Serve via FastAPI + FAISS-GPU or Qdrant on localhost
- Claude sessions query `http://localhost:8000/search?q=...` via MCP tool
- Returns ranked results with pointer-network node IDs for graph traversal
**Benefit:** Replaces linear grep-based search with O(1) approximate nearest neighbor lookup

### 4. Wikipedia Article Summarization Pipeline
**What:** Run a local LLM (e.g., Mistral 7B, Phi-3, or Llama 3.1 8B quantized) to generate structured summaries of all Wikipedia articles for faster ingestion by Claude.
**Why:** Full Wikipedia articles are too long for pointer network metadata. GPU-generated summaries (200-300 words each) let Claude quickly understand article content without reading full text.
**How:**
- Run `llama.cpp` or `vllm` with Q4_K_M quantized 8B model (~6 GB VRAM)
- Batch process articles with structured prompt: extract key concepts, relationships, and relevance to AI/ML
- Store summaries in `text-cache/summaries/` alongside full text
- Add summary field to pointer network node metadata

### 5. Cluster Discovery and Community Detection
**What:** Run GPU-accelerated community detection (Louvain/Leiden algorithm via cuGraph or PyTorch) on the full pointer network + expanded Wikipedia graph.
**Why:** With all of Wikipedia added, the network could have 100,000+ nodes. CPU-based cluster detection becomes slow. GPU finds natural topic communities that can become new tag clusters.
**How:**
- Use NVIDIA cuGraph (part of RAPIDS) for GPU-accelerated graph analytics
- Detect communities, compute PageRank, find bridge nodes
- Export discovered clusters as new `tag_clusters` entries
- Identify "gateway" articles that connect disparate knowledge domains

### 6. Image/Diagram Embedding for Multimodal Pointer Network
**What:** Use a local vision model (CLIP, SigLIP) to embed images and diagrams from Wikipedia articles, enabling visual similarity search.
**Why:** Many Wikipedia articles contain diagrams, architecture charts, and visualizations that carry information not in the text.
**How:**
- Run `open_clip` with ViT-L/14 on 4070S (~2 GB VRAM)
- Extract and embed images from Wikipedia articles
- Create cross-modal edges: text nodes linked to visually similar image nodes
- Enable queries like "find articles with diagrams similar to this architecture"

### 7. Continuous Background Indexing Daemon
**What:** A persistent GPU service that watches for new files/articles added to the repository and automatically generates embeddings, updates the pointer network, and suggests new edges.
**How:**
- Python watchdog + FastAPI service running on the home PC
- On file change: embed new content, find nearest neighbors, suggest edges
- Expose REST API for Claude sessions to push new content and pull suggestions
- Runs 24/7 with minimal GPU utilization (~5% idle, bursts on new content)

### 8. Knowledge Graph Completion (Link Prediction)
**What:** Train a knowledge graph embedding model (TransE, RotatE, or ComplEx) to predict missing edges in the pointer network.
**Why:** With 310 nodes and 4,809 edges, there are likely thousands of valid connections not yet discovered. Link prediction finds them automatically.
**How:**
- Use PyKEEN or DGL-KE with CUDA backend
- Train on existing edges, predict top-k missing edges with confidence scores
- Human-in-the-loop: Claude reviews predicted edges before adding them
- Particularly useful after Wikipedia expansion (find which Wikipedia articles should link to existing KB entries)

## Recommended Implementation Order

| Priority | Task | Impact | Effort | VRAM |
|----------|------|--------|--------|------|
| 1 | Local Embedding Generation (#1) | High — enables all other semantic tasks | Low | 0.5-2 GB |
| 2 | Semantic Search Index (#3) | High — immediate Claude productivity boost | Medium | 1-2 GB |
| 3 | Link Prediction (#8) | High — auto-discovers missing connections | Medium | 1-2 GB |
| 4 | Article Summarization (#4) | Medium — speeds up article ingestion | Medium | 6 GB |
| 5 | Background Indexing (#7) | Medium — keeps network fresh | Medium | 0.5 GB |
| 6 | GNN Weight Optimization (#2) | Medium — improves pathfinding quality | Low | <1 GB |
| 7 | Cluster Discovery (#5) | Medium — needed at scale | Low | 2-4 GB |
| 8 | Multimodal Embeddings (#6) | Lower — nice-to-have | Medium | 2 GB |

## Lessons Learned
- The RTX 4070 Super's 12 GB VRAM comfortably runs any single task above; some can run concurrently
- The pointer network's JSON format is a bottleneck at scale — consider SQLite or a proper graph DB (Neo4j) if Wikipedia pushes past 50K nodes
- Local GPU compute is the missing piece that transforms the pointer network from a static graph into a living, self-updating knowledge system

## Recommendations
1. **Start with embeddings** (#1) — everything else builds on them
2. **Expose as MCP tool** — let Claude sessions query local GPU services directly
3. **Use quantized models** for summarization to leave VRAM headroom for embeddings
4. **Version the embedding index** alongside pointer-network.json so Claude sessions know what's available
5. **Set up the background daemon** (#7) early so new Wikipedia articles are automatically indexed
