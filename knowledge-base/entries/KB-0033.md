# Benchmark Data Collection, Analysis, and Index Consolidation

## Context
After 29 team sessions producing 32 knowledge base entries, 54 scripts, 20 SOPs, 44 data sources, and extensive benchmark data, several indexing gaps existed. The storage/data/ directory contained 6 data files (knowledge.db, unified_benchmarks.json, empirical_benchmarks.json, final_analysis.json, INDEX_COMPACT.json, SUMMARY.json) with no dedicated index. The meta-index (INDEX_COMPACT.json) was missing recently added entries. Resource type counts in SUMMARY.json were stale.

## Method
1. Audited all index files against their source data: knowledge-base/index.json, storage/scripts/index.json, storage/coordination/sops/index.json, storage/data/INDEX_COMPACT.json, and storage/data/SUMMARY.json.
2. Identified specific gaps: KB-0032 missing from INDEX_COMPACT, SCR-0051 through SCR-0054 missing, SOP-026/027/028 missing, SOP-029/030/031 missing from sops/index.json.
3. Created storage/data/index.json as a proper full index for all 6 data files with id, filename, format, size_estimate, description, date_created, category, tags, and cross_references.
4. Updated INDEX_COMPACT.json with all missing entries to achieve full coverage.
5. Updated SUMMARY.json with accurate counts derived from actual index file contents.
6. Updated sops/index.json to include SOP-029, SOP-030, SOP-031, and SOP-032.

## Result
- **storage/data/index.json**: New file created indexing all 6 data files with full metadata.
- **INDEX_COMPACT.json**: Updated from 171 to 186 entries, adding KB-0032, KB-0033, SCR-0051 through SCR-0054, SOP-026, SOP-027, SOP-028, SOP-032, and DATA-0001 through DATA-0006.
- **SUMMARY.json**: Counts corrected to match actual data (KB: 33, SCR: 54, SOP: 24, SRC: 41, TEAM: 29, TOOL: 2, DATA: 6).
- **sops/index.json**: Updated from 20 to 24 entries, adding SOP-029, SOP-030, SOP-031, SOP-032.
- All cross-references validated for consistency.

## Key Data Collected
- **unified_benchmarks.json** (27KB): 17 sources, 36 synthetic benchmark runs comparing Proto A/B/baseline, 3 live deployment tests, 2880 coordination measurements, 146 data-gathering data points.
- **empirical_benchmarks.json** (17KB): 7 benchmark suites testing team sizing (1-50 agents), SQLite contention (1-32 threads), pipeline throughput, and tool correctness (45 tests).
- **final_analysis.json** (23KB): Cross-analysis of 3247 data points yielding optimal team size (5-8 agents), power law model E=4.0*N^(-0.75), and infrastructure priority map.
- **knowledge.db** (432KB): SQLite FTS5 database enabling sub-millisecond full-text search across all repository content.

## Lessons Learned
- Index drift is inevitable in a rapidly growing repository. Every new entry must be registered in all relevant indexes at creation time.
- The meta-index (INDEX_COMPACT.json) serves as the single source of truth for cross-cutting queries but requires active maintenance.
- Data files need their own index just like code and documentation do. Without storage/data/index.json, the benchmark datasets were discoverable only by listing the directory.
- SOP files with non-standard naming (efficiency_guide.json, tool_sops.json) are harder to track and should follow the sop_NNN_name.json convention.

## Recommendations
- Always update INDEX_COMPACT.json, SUMMARY.json, and the relevant section index when adding any new entry.
- Run periodic audits (see SOP-015, SOP-030) to catch indexing drift before it accumulates.
- New data files should be registered in storage/data/index.json immediately upon creation.
- Consider automating index updates via pre-commit hooks or a dedicated indexing script.
