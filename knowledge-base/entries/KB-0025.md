# Bug Fixes, Coordinator Hub, and Central Commander SOPs

## Context
TEAM-0024 delivered 96 stress tests, 10 SOPs, and a research dossier covering the coordination system. The stress tests and think tank analyses from that session identified 31 failure modes and 20 error protection gaps across 3 modules (help_protocol.py, direct_channels.py, work_stealing.py). TEAM-0025 was tasked with: (1) deep bug analysis and fix planning for all 3 modules, (2) designing and implementing a coordinator hub for real-time agent monitoring, and (3) creating SOPs to enforce parallel execution and eliminate the sequential-wave anti-pattern observed in previous sessions.

## Method
Multiple think tanks and SOP teams operated simultaneously:

- **Think Tank Bugs (3 analysts)**: Deep bug analysis of help_protocol.py (14 bugs), direct_channels.py (14 bugs), and work_stealing.py (13 bugs). Each bug documented with reproduction steps, severity, impact, and proposed fix code.
- **Think Tank Bugs-1**: Focused fix proposals for help_protocol.py -- 8 prioritized fixes with complete code patches plus 5 chokepoint analyses with optimization strategies.
- **Think Tank Hub**: Analyzed hub-and-spoke architecture for real-time agent monitoring, compared topologies (hub-spoke vs. full-mesh vs. fire-and-forget), produced a layered coexistence model and implementation blueprint.
- **Coding Team (Hub)**: Built `coordinator_hub.py` -- a SQLite-backed hub-and-spoke module with AgentReporter and CoordinatorDashboard classes (607 lines).
- **SOP Teams (3)**: Created SOP-011 (Central Commander Launch Protocol), SOP-012 (Real-Time Monitoring and Intervention), SOP-013 (Agent Prompt Engineering and Context Distribution).

## Result
**SUCCESS** -- All objectives met.

### Bug Analysis: 41 Bugs Identified Across 3 Modules

| Module | Bugs Found | Critical | High | Medium | Low |

**Critical bugs discovered:**
1. **BUG-HP-001**: Bus write failures crash callers after DB commit succeeds -- state divergence between DB and caller perception
2. **BUG-HP-002/003**: TOCTOU race in auto_assign_idle_teams -- helper team status not verified inside transaction, enabling double-assignment
3. **BUG-DC-001**: In-memory read offsets lost on restart -- causes full message replay and duplicate processing
4. **BUG-DC-002**: JSONL writes at PIPE_BUF boundary risk torn writes corrupting channel files
5. **BUG-WS-001**: No circular dependency detection in PipelineManager -- causes silent infinite wait
6. **BUG-WS-003**: Abandoned claimed work items never return to queue -- permanent zombie work

**Top fix proposals (with complete code):**
- FIX-HP-001: Zombie work item reaper with configurable timeout (reap_stale_work method)
- FIX-HP-002: Input validation on update_status and add_work_item (VALID_STATUSES/VALID_PRIORITIES enforcement)
- FIX-HP-004: Authorization checks on fulfill_help (only accepted team can fulfill)
- FIX-HP-005: TOCTOU guard in auto_assign_idle_teams (verify helper status inside BEGIN IMMEDIATE)

**Chokepoints identified:**
- CP-HP-001: auto_assign_idle_teams is O(N*M) DB queries -- should prefetch and match in Python
- CP-HP-002: update_status runs 2 unnecessary COUNT(*) queries per call -- 50% throughput loss
- BUG-WS-010: No secondary indexes on work_queue, pipeline_stages, scratchpad tables

### Coordinator Hub: coordinator_hub.py (607 lines)

New module implementing hub-and-spoke architecture with two classes:
- **AgentReporter**: Agents register, update status, report errors/completion, and poll for instructions. Status validated against a whitelist (initializing, working, blocked, complete, error).
- **CoordinatorDashboard**: Coordinator reads all agent statuses, queries active/blocked/completed agents, sends typed instructions (redirect, pause, priority_change), and gets aggregate summaries.

Key design decisions:
- SQLite WAL mode with BEGIN IMMEDIATE for atomic operations (consistent with Proto A patterns)
- `_retry_on_busy` decorator with exponential backoff for lock contention
- Fire-and-forget bus notifications via `_bus_notify` helper -- failures logged but never propagated (learned from BUG-HP-001)
- `_closed` state tracking on both classes with `_check_closed()` guards (learned from BUG-HP-006/BUG-DC-008)
- Context manager support (__enter__/__exit__) on both classes
- Two tables: `agent_status` (agent writes, coordinator reads) and `coordinator_instructions` (coordinator writes, agent reads)
- Agents CANNOT see each other's entries -- the coordinator mediates all cross-agent communication

- Hard Dependency Test: "Does Task B require a specific computed artifact that only Task A can produce, AND that artifact does not exist yet?"
- 10 Anti-Sequential Rules (ASR-001 through ASR-010) with evidence from TEAM-0022/0023/0024

### Think Tank Hub Analysis: Layered Architecture Recommendation

The hub analysis produced a comprehensive comparison:
- **Hub-spoke** (recommended primary): Maximum visibility, simple agent implementation, dead agent detection via stale timestamps. Weakness: coordinator becomes communication bottleneck for agent-to-agent data.
- **Full mesh** (supplementary): Lowest latency for peer communication. Weakness: O(n^2) channels, coordination explosion.
- **Fire-and-forget** (trivial tasks only): Zero overhead. Weakness: zero visibility, encourages sequential waves.

**Recommended layered coexistence model:**
1. Layer 1 (Hub-spoke): Always on. All agents report status. Coordinator monitors.
2. Layer 2 (Direct channels): On demand. Specific agent pairs collaborate.
3. Layer 3 (Scratchpad): On demand. Shared data store for intermediate results.
4. Layer 4 (Fire-and-forget): Trivial sub-tasks under 2 minutes.

**Anti-sequential analysis identified 6 root causes of wave patterns:**
- Risk aversion without visibility (SEQ-001)
- Causal dependency assumption -- conflating "benefits from" with "requires" (SEQ-002)
- Simpler mental model -- sequential is easier to reason about (SEQ-003)
- Past experience with merge conflicts (SEQ-004)
- Completion dependency illusion -- slowest member blocks entire next phase (SEQ-005)
- No partial result consumption -- all-or-nothing output forces all-or-nothing sequencing (SEQ-006)

## Lessons Learned

1. **Bus notifications must be fire-and-forget** -- BUG-HP-001 and BUG-WS-007 showed that bus write failures crash callers even after DB commits succeed. coordinator_hub.py implements this correctly from the start with try/except in `_bus_notify`.

2. **Close-state tracking is essential** -- BUG-HP-006 and BUG-DC-008 showed that calling methods after close() produces opaque sqlite3.ProgrammingError instead of clear RuntimeError. coordinator_hub.py includes `_closed` flags and `_check_closed()` guards on all public methods.

3. **Input validation prevents invisible bugs** -- BUG-HP-004, BUG-DC-009, and BUG-WS-005 showed that missing validation (status strings, progress values, stage names) causes silent data corruption. coordinator_hub.py validates against VALID_AGENT_STATUSES.

4. **TOCTOU races in BEGIN IMMEDIATE blocks** -- BUG-HP-002/003, BUG-WS-009, and BUG-WS-011 showed that reading data outside the transaction and acting on it inside creates race windows. Fix: verify assumptions inside the transaction with WHERE guards.

5. **The sequential-wave anti-pattern costs 2x execution time** -- Evidence from TEAM-0024: the coordinator initially planned waves but was corrected to parallel. All 7 teams ran in 1 wave. SOP-011 now enforces this as the default.

6. **Coordinator visibility enables parallel confidence** -- The think tank hub analysis identified that fear of parallelism stems from lack of visibility. The hub-and-spoke model solves this by giving the coordinator a real-time dashboard of all agent progress, making simultaneous launches safe.

## Recommendations

1. **Implement the 8 critical/high fixes** -- Priorities: zombie reaper (FIX-HP-001), TOCTOU guard (FIX-HP-005), input validation (FIX-HP-002), fulfill_help authorization (FIX-HP-004), offset persistence (BUG-DC-001), cycle detection (BUG-WS-001), abandoned work recovery (BUG-WS-003), complete_work authorization (BUG-WS-002).

2. **Add database indexes** -- BUG-WS-010 identified missing indexes on work_queue(status, priority), pipeline_stages(pipeline_id, status), and scratchpad(namespace, expires_at). Expected 5-10x query speedup at scale.

3. **Write unit tests for all bug fixes** -- Each bug analysis includes specific test_needed descriptions. Estimated 40-50 new tests.

4. **Integrate coordinator_hub.py into multi_team_runner.py** -- Use CoordinatorDashboard in the monitoring loop. Replace ad-hoc filesystem polling with structured status queries.

5. **Use SOP-011 for all future launches** -- Every coordinator should run through the pre-launch checklist and apply the Hard Dependency Test before sequencing any teams.

6. **Use SOP-013 prompt templates** -- Standardize agent prompts using the canonical 6-part template with QA-01 through QA-12 validation.

7. **Adopt the layered architecture** -- Hub-spoke for visibility (always on), direct channels for peer collaboration (on demand), scratchpad for shared data, fire-and-forget for trivial tasks.
