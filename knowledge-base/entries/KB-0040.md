# LanceDB Semantic Search Integration

## Context
KB-0034 identified LanceDB as "SQLite for AI" — the ideal embedded vector database for semantic search. Keyword search (FTS5) misses conceptually related content when exact terms don't match. The repo's 38 KB entries needed semantic discoverability.

## Method
Built two scripts:
- `semantic_indexer.py` — parses KB entries (YAML frontmatter + Markdown), creates LanceDB table with auto-generated embeddings via `all-MiniLM-L6-v2` (384 dims)
- `semantic_search.py` — query API with vector, hybrid (vector + BM25), and FTS modes, plus CLI interface

Used LanceDB's Pydantic schema with `SourceField()` and `VectorField()` for automatic embedding generation on insert and query.

## Result
- 38 KB entries indexed in `/storage/data/lance_db/`
- Total storage: <5 MB
- Hybrid search combines vector similarity + BM25 full-text in one query
- CLI: `python semantic_search.py "agent communication"` returns ranked results
- Integrated into MCP server as 6th tool (`kb_semantic_search`)
- Incremental updates supported via `table.add()` for new entries

## Lessons Learned
1. `all-MiniLM-L6-v2` (384 dims) is sufficient for ~40 documents — no need for larger models
2. LanceDB's native hybrid search eliminates the need to maintain separate FTS5 for search
3. Manual query embedding (via SentenceTransformer directly) avoids schema registration conflicts between indexer and searcher
4. First run downloads ~90MB model — document this for new users
5. Storage is negligible (<5 MB) even with embeddings

## Recommendations
1. Run `python semantic_indexer.py` after adding new KB entries to update the index
2. Phase 2: expand indexing to team logs, SOPs, and script docstrings (~511 total records)
3. Keep SQLite for coordination/structured data, LanceDB for search
4. Consider adding incremental update via git hook (post-commit)
