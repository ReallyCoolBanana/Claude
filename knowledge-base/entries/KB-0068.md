# Local AI Services as Persistent systemd Services on Linux (RTX 4070 Super)

## Context
Setting up a home AI server running Ubuntu/Pop!_OS with an NVIDIA RTX 4070 Super (12GB VRAM). The goal is to run llama-server (llama.cpp) and a FastAPI hub as persistent, auto-restarting systemd services with proper GPU dependency management, resource limits, gaming coexistence, and monitoring.

## 1. llama-server (llama.cpp) Systemd Service File

File: `/etc/systemd/system/llama-server.service`

```ini
[Unit]
Description=llama.cpp Inference Server
After=network.target nvidia-persistenced.service
Wants=nvidia-persistenced.service
After=dev-nvidia0.device
Wants=dev-nvidia0.device

[Service]
Type=simple
User=ai-server
Group=ai-server
WorkingDirectory=/opt/llama-server

Environment="CUDA_VISIBLE_DEVICES=0"
Environment="GGML_CUDA_NO_PINNED=1"
EnvironmentFile=-/etc/default/llama-server

ExecStart=/opt/llama-server/bin/llama-server \
    --model /opt/models/current-model.gguf \
    --host 127.0.0.1 \
    --port 8081 \
    --ctx-size 8192 \
    -ngl 999 \
    --threads 8 \
    --parallel 2

Restart=on-failure
RestartSec=2s
RestartSteps=5
RestartMaxDelaySec=60s
StartLimitIntervalSec=300
StartLimitBurst=10

MemoryHigh=14G
MemoryMax=16G
MemorySwapMax=0
CPUQuota=400%
OOMPolicy=stop
OOMScoreAdjust=500

ProtectSystem=strict
ProtectHome=yes
ReadWritePaths=/opt/llama-server/logs
ReadOnlyPaths=/opt/models
PrivateTmp=yes
NoNewPrivileges=yes

StandardOutput=journal
StandardError=journal
SyslogIdentifier=llama-server

[Install]
WantedBy=multi-user.target
```

### Environment file: `/etc/default/llama-server`

```bash
CUDA_VISIBLE_DEVICES=0
# LLAMA_FLASH_ATTN=1
```

## 2. FastAPI/Uvicorn Hub Systemd Service File

File: `/etc/systemd/system/ai-hub.service`

```ini

Description=AI Hub - FastAPI Gateway
```

## 3. GPU Dependency Handling

```ini
# In [Unit] section of any GPU-dependent service:
After=nvidia-persistenced.service
Wants=nvidia-persistenced.service
After=dev-nvidia0.device dev-nvidiactl.device dev-nvidia-uvm.device
Wants=dev-nvidia0.device
```

Enable nvidia-persistenced:
```bash
sudo systemctl enable nvidia-persistenced
```

If GPU device nodes are not recognized by systemd, create udev rules.
File: `/etc/udev/rules.d/99-nvidia-systemd.rules`
```
KERNEL=="nvidia[0-9]*", TAG+="systemd"
KERNEL=="nvidiactl", TAG+="systemd"
KERNEL=="nvidia-uvm", TAG+="systemd"
```
Reload: `sudo udevadm control --reload-rules && sudo udevadm trigger`

## 4. Auto-Restart with Exponential Backoff

### systemd 254+ (Ubuntu 24.04+):
```ini
[Service]
Restart=on-failure
RestartSec=2s
RestartSteps=5
RestartMaxDelaySec=60s
StartLimitIntervalSec=300
StartLimitBurst=10
```

### Older systemd (pre-254):
```ini
[Service]
Restart=on-failure
RestartSec=5s
StartLimitIntervalSec=0
```

## 8. User Services vs System Services

System services with `User=` are recommended for GPU workloads. User services cannot depend on device units like `dev-nvidia0.device`.

```bash
sudo useradd -r -s /usr/sbin/nologin -d /opt/ai-server ai-server
sudo usermod -aG video ai-server
sudo usermod -aG render ai-server
```

## 9. Gaming Coexistence

### Script: `/usr/local/bin/gaming-mode`
```bash
#!/bin/bash
case "$1" in
    on)
        echo "Stopping AI services for gaming..."
        sudo systemctl stop ai-stack.target
        sleep 2
        nvidia-smi
        echo "GPU is free. Game on."
        ;;
    off)
        echo "Resuming AI services..."
        sudo systemctl start ai-stack.target
        echo "AI services restarted."
        systemctl status ai-stack.target --no-pager
        ;;
    status)
        systemctl is-active llama-server.service ai-hub.service
        nvidia-smi
        ;;
    *)
        echo "Usage: gaming-mode {on|off|status}"
        exit 1
        ;;
esac
```

### Sudoers: `/etc/sudoers.d/gaming-mode`
```
youruser ALL=(ALL) NOPASSWD: /usr/bin/systemctl stop ai-stack.target
youruser ALL=(ALL) NOPASSWD: /usr/bin/systemctl start ai-stack.target
```

### Target approach: `/etc/systemd/system/gaming.target`
```ini
[Unit]
Description=Gaming Mode - AI services stopped
Conflicts=llama-server.service ai-hub.service
```

## 10. Socket Activation

### `/etc/systemd/system/llama-api.socket`
```ini
[Socket]
ListenStream=8000

[Install]
WantedBy=sockets.target
```

### `/etc/systemd/system/llama-api.service`
```ini
[Unit]
Description=llama-server Socket Proxy
Requires=llama-server.service
After=llama-server.service

[Service]
Type=notify
ExecStartPre=/bin/bash -c 'until curl -sf http://127.0.0.1:8081/health | grep -q "ok"; do sleep 1; done'
ExecStart=/usr/lib/systemd/systemd-socket-proxyd --exit-idle-time=15m 127.0.0.1:8081
TimeoutStartSec=120s
```

### Modified llama-server for on-demand:
```ini
[Unit]
Description=llama.cpp Inference Server (on-demand)
After=nvidia-persistenced.service

[Service]
```

## 12. Health Checks

### Watchdog wrapper: `/opt/ai-server/watchdog-wrapper.sh`
```bash
#!/bin/bash
HEALTH_URL="http://127.0.0.1:8081/health"
"$@" &
SERVER_PID=$!
for i in $(seq 1 60); do
    if curl -sf "$HEALTH_URL" > /dev/null 2>&1; then
        systemd-notify --ready
        break
    fi
    sleep 1
done
WATCHDOG_USEC=${WATCHDOG_USEC:-60000000}
INTERVAL=$(( WATCHDOG_USEC / 2000000 ))
while kill -0 $SERVER_PID 2>/dev/null; do
    if curl -sf --max-time 5 "$HEALTH_URL" > /dev/null 2>&1; then
        systemd-notify WATCHDOG=1
    fi
    sleep $INTERVAL
done
wait $SERVER_PID
```

```ini
[Service]
Type=notify
ExecStart=/opt/ai-server/watchdog-wrapper.sh /opt/llama-server/bin/llama-server --model ... --port 8081
WatchdogSec=60s
Restart=on-failure
NotifyAccess=all
```

## 13. Complete Multi-Service Setup

Three services (llama-server, ai-hub, ai-daemon) grouped under ai-stack.target.
See sections 1, 2, and the ai-daemon service below.

### `/etc/systemd/system/ai-daemon.service`
```ini
[Unit]
Description=AI Background Daemon
After=network.target llama-server.service
Wants=llama-server.service

[Service]
Type=simple
User=ai-server
Group=ai-server
WorkingDirectory=/opt/ai-daemon
Environment="PYTHONUNBUFFERED=1"
Environment="LLAMA_SERVER_URL=http://127.0.0.1:8081"
ExecStart=/opt/ai-daemon/venv/bin/python -m ai_daemon.main
Restart=on-failure
RestartSec=5s
RestartSteps=4
RestartMaxDelaySec=120s
MemoryHigh=2G
MemoryMax=4G
MemorySwapMax=0
CPUQuota=200%

StandardError=journal
SyslogIdentifier=ai-daemon

[Install]

```

### Deployment:
```bash
sudo useradd -r -s /usr/sbin/nologin -d /opt/ai-server ai-server
sudo usermod -aG video,render ai-server
sudo cp *.service *.target /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable llama-server.service ai-hub.service ai-daemon.service ai-stack.target
sudo systemctl start ai-stack.target
```

## Lessons Learned

1. System services with `User=` beat user services for GPU workloads.
2. `nvidia-persistenced` is essential for avoiding cold-start CUDA penalties.
3. `MemorySwapMax=0` is critical for inference latency.
4. Socket activation gives zero VRAM when idle with transparent startup (~10-30s cold start).
5. `Conflicts=` in a gaming target is the cleanest GPU-sharing pattern.
6. Exponential backoff is native in systemd 254+ via `RestartSteps`/`RestartMaxDelaySec`.
7. The watchdog wrapper pattern works for any HTTP health endpoint.
8. `OOMPolicy=stop` + `Restart=on-failure` is better than `OOMPolicy=kill`.
