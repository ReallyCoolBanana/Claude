# Wikipedia Crawl Method Efficiency Testing: Egress-Restricted Environments

## Context

With 234 Wikipedia AI category articles indexed (category-pages.json), we needed to determine the most efficient method to extract internal wiki links and external citation links from each article. The environment blocks direct access to en.wikipedia.org via egress policy (403/blocked on all endpoints).

## Method

12 methods tested in parallel across 4 agent teams:

### Blocked Methods (8/12)
1. **Direct WebFetch** to en.wikipedia.org — HTTP 403
2. **Wikipedia mobile** (en.m.wikipedia.org) — HTTP 403
3. **Wikipedia REST API** (/api/rest_v1/) — HTTP 403 (3 endpoints tested)
4. **curl + User-Agent** to wikipedia.org — Blocked by egress policy
5. **MediaWiki API** (action=parse, action=query) — Blocked by egress policy
6. **Wikimedia dumps API** — Blocked by egress policy
7. **Wikidata API** — Blocked by egress policy
8. **Mirrors** (Google Cache, Wikiwand, wiki2.org, Internet Archive) — All blocked (403/captcha/denied)

### Working Methods (3/12)

#### Method A: DBpedia SPARQL (curl) — BEST FOR STRUCTURED LINKS
- **Endpoint**: `https://dbpedia.org/sparql` with JSON output format
- **Internal wiki links**: `wikiPageWikiLink` predicate — 136/234 articles found
- **External citation links**: `wikiPageExternalLink` predicate — variable (200 for major, 0-15 for small)
- **Batch queries**: 50 articles per SPARQL VALUES clause, all 234 in ~9 seconds (5 batches)
- **Limitation**: 98/234 articles missing (newer/obscure articles not yet in DBpedia)

#### Method B: DBpedia Page (WebFetch) — GOOD FOR DETAILED EXTRACTION
- **URL pattern**: `https://dbpedia.org/page/{Article_Title}`
- Returns external links matching Wikipedia's "External links" and some references
- Slower (1 WebFetch per article), but richer context per link
- **Limitation**: Only captures "External links" section, not all inline citation refs

#### Method C: WebSearch — BEST FOR ARTICLE TEXT + DISCOVERY
- Search `"{article title} wikipedia"` for each article
- Returns article text summaries and related Wikipedia article URLs
- Does NOT return actual citation URLs from references section
- Rate: ~1-2 seconds per search

## Results

### Recommended Strategy: Combined 3-Pass Approach

**Pass 1 — DBpedia SPARQL batch (9 seconds for all 234 articles)**
```
SPARQL query pattern:
SELECT ?article ?link WHERE {
  VALUES ?article { <resource/Title1> <resource/Title2> ... }
  ?article <ontology/wikiPageWikiLink> ?link
}
```
- Retrieves internal wiki links for 136 articles (11,682 total links)
- Same pattern with `wikiPageExternalLink` for citation links

**Pass 2 — WebSearch for 98 missing articles (~3-5 min with parallel agents)**
- Fill gaps for articles not in DBpedia
- Get article content and related wiki links

**Pass 3 — Targeted deep-dive on high-priority articles**
- WebSearch + WebFetch on DBpedia pages for articles needing more citations
- Cross-reference with KB-0044 academic paper catalog

### Performance Benchmarks

| Metric | Value |
|--------|-------|
| DBpedia SPARQL batch (234 articles, internal links) | 9 seconds |
| DBpedia SPARQL batch (234 articles, external links) | ~9 seconds |
| DBpedia coverage rate | 58% (136/234 articles) |
| WebSearch per article | ~1-2 seconds |
| Total estimated crawl time (all 234, combined method) | 15-20 minutes |
| Internal links available via DBpedia | 11,682 |
| External links (major articles like AI) | 200+ per article |
| External links (typical small article) | 0-15 per article |

### Critical Discovery: DBpedia Predicate Matters

- `ontology/wikiPageExternalLink` — Returns citation/reference URLs (the ones we want)
- `property/wikiPageExternalLink` — Returns NOTHING (different predicate, empty results)
- `ontology/wikiPageWikiLink` — Returns internal Wikipedia cross-links (also valuable)

### DBpedia Data Quality Notes

- External links include wiki markup artifacts (e.g., `%7C` pipe characters) — need URL cleanup
- Some articles redirect silently (AI_safety → AI_alignment)
- External link counts are inconsistent: AI=200, Machine_learning=12, ChatGPT=0, Deep_learning=2
- Internal links are more reliable and consistent across articles
- DBpedia lags Wikipedia by several months; very new articles absent

## Lessons Learned

1. **DBpedia SPARQL is the single most powerful tool** for Wikipedia link extraction in egress-restricted environments — batch queries for 234 articles complete in under 10 seconds
2. **Use `ontology/` not `property/` predicates** — this was a critical discovery that turned 0 results into 200 results
3. **Batch SPARQL with VALUES clause** is dramatically more efficient than per-article queries (9s vs ~4 minutes)
4. **WebSearch complements DBpedia** — covers the 42% of articles missing from DBpedia
5. **No single method gets everything** — combining DBpedia (structured links) + WebSearch (content/discovery) covers the most ground

## Recommendations

1. **For Step 2 data system**: Design storage around the 3-pass output structure — DBpedia links (structured), WebSearch content (text), and deep-dive citations (PDFs)
2. **URL cleanup pipeline needed**: Strip wiki markup artifacts from DBpedia external links before storage
3. **Handle redirects**: Map DBpedia redirect targets back to canonical article titles
4. **Prioritize articles by link richness**: Major articles (AI, Ethics, Game Theory) have 200+ links; start there for maximum data yield
5. **Rate limiting**: DBpedia SPARQL has no documented rate limit but be respectful — 1-2 second delay between batch queries
