# Sonnet Research API — Multi-Agent Research System

## Context
The agentic team needed a way to dispatch research tasks to Claude Sonnet from within Claude Code. Required: variable sub-agent count, request queuing, result sorting, and automated import of findings into the repo's storage structure.

## Method
Two parallel teams (4 sub-agents total) built the system:
- **Team A:** Core API client (Anthropic SDK wrapper), thread-safe priority queue with rate limiting, and iterative-depth researcher agent
- **Team B:** Mission orchestrator (variable sub-agent spawning), result sorter (relevance/topic/category), data importer (KB entries, sources, API tools), and documentation

## Result
7-module Python system in `storage/api-tools/sonnet-research-api/`:

| Module | Purpose |
|--------|---------|
| `config.py` | API key, model, rate limits, retry settings |
| `client.py` | Anthropic SDK wrapper with retry + token tracking |
| `queue_manager.py` | Thread-safe priority queue, rate limiting, status tracking |
| `researcher.py` | Quick/standard/deep research with iterative refinement |
| `orchestrator.py` | Main entry point — spawns N researchers, runs missions |
| `sorter.py` | Sort by relevance, topic, depth; categorize; filter |
| `data_importer.py` | Import results into KB, sources, and api-tools indexes |

### Usage
```python
from orchestrator import ResearchOrchestrator

orch = ResearchOrchestrator()  # reads ANTHROPIC_API_KEY from env
result = orch.run_research_mission({
    "objective": "Analyze emerging AI trends",
    "sub_tasks": [
        {"topic": "multimodal models", "depth": "deep", "priority": 1},
        {"topic": "agent frameworks", "depth": "standard", "priority": 0},
    ],
    "max_concurrent": 3
})
```

## Lessons Learned
1. **Cross-team import consistency matters** — Team B had to fix Team A's orchestrator draft because it used wrong constructor signatures and non-existent attributes
2. **Absolute imports only** — relative imports (from .module) break when running from different working directories inside Claude Code
3. **Thread-safe queuing is essential** — multiple researchers writing results concurrently requires proper locking
4. **Rate limiting must be built in** — Anthropic API has rate limits; the queue handles this transparently

## Recommendations
1. Set `ANTHROPIC_API_KEY` environment variable before use
2. Start with `depth="standard"` (3 queries) — `"deep"` uses up to 6 queries per topic
3. Use `max_concurrent=3` as default — increase only if your API tier allows higher rate limits
4. Always run `DataImporter.update_indexes()` after importing results to keep indexes current
5. Use `ResultSorter.categorize()` before importing to ensure proper categorization
