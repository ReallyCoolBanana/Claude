# PNAM v2: Scaled to 1M Edges on RTX 4070 Super (12GB)

## Context
KB-0056 designed PNAM for the repo's 310-node/4,809-edge network. The actual home PC network
has already grown to **37,000 edges** and the target is **1,000,000+ edges**. This changes
the architecture in three critical ways:

1. **Graph encoder can't see the full graph at once** — must use mini-batch neighborhood sampling
2. **Training data jumps from ~5K to 1M+ examples** — enables deeper models and prevents overfitting
3. **Full-Wikipedia FAISS index at 768-dim (18GB) won't fit in 12GB** — must use 256-dim or quantized

### Scale Comparison

| Metric | Repo (KB-0056) | Home Now | Target |
|--------|---------------|----------|--------|
| Edges | 4,809 | 37,000 | 1,000,000 |
| Est. nodes (avg_deg=30) | 310 | ~2,500 | ~66,000 |
| Est. nodes (avg_deg=15) | 641 | ~5,000 | ~133,000 |
| Route logs | 599 | grows with use | 10,000+ target |
| Graph VRAM (train) | 4 MB | 40 MB | 400 MB - 1.6 GB |
| FAISS index (256-dim) | 0.3 MB | 5 MB | 17-34 MB |
| Full Wikipedia FAISS (256d) | — | — | 6.0 GB |

## Method: PNAM v2 Architecture

### Key Design Changes from v1

| Component | v1 (KB-0056) | v2 (This Entry) | Why |
|-----------|-------------|------------------|-----|
| Graph encoder | Full-graph forward pass | **Mini-batch NeighborLoader** | Full graph won't fit at 1M edges during backprop |
| Text encoder | MiniLM 384-dim | **256-dim output projection** | 768-dim FAISS for 6M articles = 18GB, doesn't fit. 256-dim = 6GB, fits. |
| Training | 50 epochs, single pass | **Streaming DataLoader + gradient accumulation** | 1M edges = can't load all pairs into memory |
| Pathfinder head | Score all neighbors | **Top-K candidate pruning** | At avg_degree=30, scoring all neighbors is fine. At 100+, need pruning. |
| Inference | Single model on GPU | **Graph on GPU, FAISS on GPU, share VRAM** | Must budget carefully |
| Storage | In-memory | **Memory-mapped + sharded** | 1M-edge graph + 6M embeddings need disk-backed structures |

### Component 1: Text Encoder (256-dim output)

**Base**: `nomic-embed-text-v1.5` (137M, native 768-dim) with a learned projection:

```python
class TextEncoder(nn.Module):
    def __init__(self):
        self.backbone = AutoModel.from_pretrained("nomic-ai/nomic-embed-text-v1.5")
        self.backbone.requires_grad_(False)  # freeze
        # Project 768 → 256 to halve FAISS memory
        self.proj = nn.Sequential(
            nn.Linear(768, 512),
            nn.GELU(),
            nn.Linear(512, 256),
            nn.LayerNorm(256),
        )
        # Unfreeze last 2 transformer layers for domain adaptation
        for layer in self.backbone.encoder.layer[-2:]:
            layer.requires_grad_(True)

    def forward(self, input_ids, attention_mask):
        with torch.cuda.amp.autocast():  # mixed precision
            hidden = self.backbone(input_ids, attention_mask).last_hidden_state
            pooled = hidden[:, 0]  # CLS token
            return self.proj(pooled)  # 256-dim
```

**Why 256-dim**: Full Wikipedia (6M articles) at 768-dim = 18GB, doesn't fit on 12GB GPU.
At 256-dim = **6.0GB**, leaving 6GB for model + graph + serving. Empirically, 256-dim
retains ~95% of retrieval quality vs 768-dim for domain-specific tasks after fine-tuning.

**FAISS index strategy for full Wikipedia**:
```python
# 6M vectors × 256-dim × float32 = 6.0 GB (fits in VRAM)
# Use IVF for faster search:
index = faiss.index_factory(256, "IVF4096,PQ32")  # PQ compresses to ~1.5 GB
# Or flat for exact search when VRAM allows:
index = faiss.IndexFlatIP(256)  # 6.0 GB, exact cosine similarity
# Hybrid: PQ index on GPU (1.5GB) + flat on disk via mmap for reranking
```

### Component 2: Graph Encoder (Scaled for 1M edges)

**Architecture**: 4-layer GraphSAGE with **NeighborLoader** for mini-batch training.
The critical change: at 1M edges, you cannot do a full-graph forward pass during training.

```python
import torch_geometric
from torch_geometric.nn import SAGEConv
from torch_geometric.loader import NeighborLoader

class ScaledGraphEncoder(nn.Module):
    def __init__(self, in_dim=290, hidden=256, out_dim=256):
        # 4 layers: captures 4-hop neighborhoods (matches network diameter)
        self.conv1 = SAGEConv(in_dim, hidden)
        self.conv2 = SAGEConv(hidden, hidden)
        self.conv3 = SAGEConv(hidden, hidden)
        self.conv4 = SAGEConv(hidden, out_dim)
        self.norms = nn.ModuleList([nn.LayerNorm(hidden) for _ in range(3)])
        self.norm_out = nn.LayerNorm(out_dim)
        self.dropout = nn.Dropout(0.1)

    def forward(self, x, edge_index):
        for i, conv in enumerate([self.conv1, self.conv2, self.conv3]):
            x_res = x if x.size(-1) == conv.out_channels else None
            x = conv(x, edge_index)
            x = self.norms[i](x)
            x = F.relu(x)
            if x_res is not None:
                x = x + x_res  # residual
            x = self.dropout(x)
        x = self.conv4(x, edge_index)
        return self.norm_out(x)
```

- Layer 1: 25 neighbors → 25 nodes
- Layer 2: 15 neighbors → 375 nodes
- Layer 3: 10 neighbors → 3,750 nodes
- Layer 4: 5 neighbors → 18,750 nodes
- Per-batch (1024 targets): ~24K unique nodes loaded → ~24K × 290 × 4 bytes = **28 MB**
- This is very manageable. Can increase batch_size to 4096 and still fit.

### Component 3: Gated Fusion (~6M params)

Upgraded from v1's simple cross-attention to a **gated fusion** that handles the case where
one signal is much stronger than the other (e.g., a new Wikipedia article has rich text
embedding but no graph structure yet):

```python
class GatedFusion(nn.Module):
    def __init__(self, dim=256):
        self.gate = nn.Sequential(
            nn.Linear(dim * 2, dim),
            nn.Sigmoid(),
        )
        self.transform = nn.Sequential(
            nn.Linear(dim * 2, dim * 2),
            nn.GELU(),
            nn.Dropout(0.1),
            nn.Linear(dim * 2, dim),
            nn.LayerNorm(dim),
        )

    def forward(self, text_emb, graph_emb):
        combined = torch.cat([text_emb, graph_emb], dim=-1)
        g = self.gate(combined)  # learn how much to trust each signal
        fused = self.transform(combined)
        return g * text_emb + (1 - g) * graph_emb + fused  # residual
```

**Why gated**: When onboarding a new Wikipedia article (no graph edges yet), `graph_emb`
is a zero vector. The gate learns to rely entirely on `text_emb` in this case, and
gradually shift toward graph structure as the node accumulates edges.

### Task Head 1: Link Prediction (Scaled)

At 1M edges, we have abundant positive examples. The challenge shifts to **efficient negative
sampling** and **handling class imbalance** (50% of edges are weight-1 tangential):


### Task Head 2: Pathfinder (Scaled)

With 1M edges, the pathfinder needs **candidate pruning** — can't score every neighbor when
some nodes might have 100+ edges:

```python
class ScaledPathfinderHead(nn.Module):
    def __init__(self, dim=256, num_strategies=8, max_candidates=32):
        self.max_candidates = max_candidates
        self.strategy_embed = nn.Embedding(num_strategies, 64)

        # Fast candidate pruner (lightweight)
        self.pruner = nn.Sequential(
            nn.Linear(dim * 2 + 64, 128),
            nn.ReLU(),
            nn.Linear(128, 1),
        )

        # Detailed scorer (heavier, only runs on top-K)
        self.scorer = nn.Sequential(
            nn.Linear(dim * 3 + 64, 512),  # +target embedding
            nn.ReLU(),
            nn.Dropout(0.1),
            nn.Linear(512, 256),
            nn.ReLU(),
            nn.Linear(256, 1),
        )

        # Path quality estimator
        self.quality = nn.Sequential(
            nn.Linear(dim * 2 + 64, 256),
            nn.ReLU(),
            nn.Linear(256, 4),  # [est_hops, est_weight, success_prob, est_time]
        )

    def forward(self, source, target, neighbor_embs, strategy_id):
        strat = self.strategy_embed(strategy_id)
        context = torch.cat([source, target, strat], dim=-1)

        # Phase 1: Fast prune to top-K candidates
        prune_scores = []
        for n in neighbor_embs:
            s = self.pruner(torch.cat([source, n, strat], dim=-1))
            prune_scores.append(s)
        prune_scores = torch.cat(prune_scores)
        top_k = torch.topk(prune_scores.squeeze(), min(self.max_candidates, len(neighbor_embs)))

        # Phase 2: Detailed scoring of top-K only
        detailed_scores = []
        for idx in top_k.indices:
            n = neighbor_embs[idx]
            s = self.scorer(torch.cat([source, n, target, strat], dim=-1))
            detailed_scores.append(s)

        return {
            'candidate_indices': top_k.indices,
            'scores': torch.cat(detailed_scores),
            'quality': self.quality(torch.cat([source, target, strat], dim=-1)),
        }
```

**Two-phase scoring rationale**: At avg_degree=30, v1's "score all neighbors" takes 30
forward passes per step. At degree=200 (some hub nodes in a 1M-edge network), that's
200 passes. The pruner uses a tiny 2-layer MLP to cut to 32 candidates, then the full
scorer evaluates those. Reduces compute ~6x for high-degree nodes.

**Training data scaling**:
- Target 10,000+ route logs (vs 599 in repo) → ~80K hop decisions
- Augment with synthetic routes from running PF-01 through PF-08 on the 1M-edge graph
- Curriculum learning: train on short routes first (2-4 hops), then extend to longer paths

### Task Head 3: Node Classifier (Scaled)

At 1M edges the tag vocabulary will grow well beyond 31. Use a **hashing trick** for
tags and predict into a dynamic tag space:

```python
class ScaledNodeClassifyHead(nn.Module):
    def __init__(self, dim=256, num_domains=7, num_categories=6,
                 tag_hash_dim=256, max_communities=64):
        self.domain_cls = nn.Linear(dim, num_domains)
        self.category_cls = nn.Linear(dim, num_categories)

        # Hashed tag prediction: handles growing tag vocabulary
        # Instead of fixed 31-dim output, predict into a hash space
        self.tag_predictor = nn.Sequential(
            nn.Linear(dim, 512),
            nn.ReLU(),
            nn.Linear(512, tag_hash_dim),  # each bin maps to 1+ tags
        )

        # More communities at scale (Louvain will find more)
        self.community_cls = nn.Linear(dim, max_communities)

        # NEW at v2: Importance scorer (which nodes are bridges/hubs?)
        self.importance = nn.Sequential(
            nn.Linear(dim, 128),
            nn.ReLU(),
            nn.Linear(128, 3),  # [hub_score, bridge_score, authority_score]
        )

    def forward(self, node_emb):
        return {
            'domain': self.domain_cls(node_emb),
            'category': self.category_cls(node_emb),
            'tags': torch.sigmoid(self.tag_predictor(node_emb)),
            'community': self.community_cls(node_emb),
            'importance': torch.sigmoid(self.importance(node_emb)),
        }
```

## VRAM Budget (12GB, Revised for 1M Edges)

### Training Mode

| Component | VRAM | Notes |
|-----------|------|-------|
| Text encoder (nomic, frozen) | 1.5 GB | INT8 quantized backbone, only proj layer in FP16 |
| Graph encoder (4-layer SAGE) | 0.2 GB | Model weights only |
| Fusion + 3 task heads | 0.3 GB | ~30M trainable params in FP16 |
| Optimizer (AdamW) | 0.6 GB | States for 30M trainable params |
| Mini-batch data (4096 targets) | 0.5 GB | NeighborLoader subgraph per batch |
| Activations + gradients | 1.5 GB | With gradient checkpointing |
| **Training total** | **~4.6 GB** | |
| **Headroom** | **7.4 GB** | Room for larger batches or bigger model |

Training is comfortably under budget. The key savings vs v1: **mixed precision** (FP16 for
forward/backward, FP32 only for optimizer states) and **gradient checkpointing** (recompute
activations instead of storing them).

| Component | VRAM | Notes |
|-----------|------|-------|
| Full model (INT8) | 0.8 GB | Post-training quantization |

### Hybrid Strategy (Recommended)

Run PQ index on GPU (1.5GB) for fast top-100 retrieval, keep flat index on disk via
memory-mapped file for exact reranking of top-100. Best of both worlds:

```python
# GPU: fast approximate search
gpu_index = faiss.index_factory(256, "IVF4096,PQ32")
gpu_index = faiss.index_cpu_to_gpu(res, 0, gpu_index)

# CPU/disk: exact reranking (mmap, no RAM cost)
flat_index = faiss.read_index("wiki_flat.index", faiss.IO_FLAG_MMAP)

def search(query_vec, k=10):
    # Step 1: GPU approximate top-100 (~1ms)
    _, approx_ids = gpu_index.search(query_vec, 100)
    # Step 2: CPU exact rerank top-100 → top-10 (~0.5ms)
    candidates = flat_index.reconstruct_batch(approx_ids[0])
    scores = np.dot(candidates, query_vec.T)
    top_k = np.argsort(scores.squeeze())[-k:]
    return approx_ids[0][top_k]
```

## Continuous Learning System

At 1M edges, the model should improve itself as the network grows:

```python
class PNAMContinuousLearner:
    """
    Watches for network changes and new route logs.
    Triggers incremental training when enough new data accumulates.
    """
    def __init__(self, model, config):
        self.model = model
        self.new_edges_buffer = []
        self.new_routes_buffer = []
        self.retrain_threshold_edges = 5000   # retrain after 5K new edges
        self.retrain_threshold_routes = 200   # or 200 new routes
        self.replay_buffer = ReplayBuffer(max_size=50000)

    def on_new_edge(self, edge):
        self.new_edges_buffer.append(edge)
        self.replay_buffer.add(edge)
        if len(self.new_edges_buffer) >= self.retrain_threshold_edges:
            self.incremental_train()

    def on_new_route(self, route):
        self.new_routes_buffer.append(route)
        if len(self.new_routes_buffer) >= self.retrain_threshold_routes:
            self.incremental_train()

    def incremental_train(self):
        # Mix new data with replay buffer to prevent catastrophic forgetting
        train_data = self.new_edges_buffer + self.replay_buffer.sample(10000)
        # Short training run (3-5 epochs, low LR)
        train_pnam(self.model, train_data, epochs=5, lr=1e-5)
        # Rebuild FAISS index for affected nodes
        self.update_faiss_index(affected_nodes)
        # Clear buffers
        self.new_edges_buffer = []
        self.new_routes_buffer = []
        # Save checkpoint
        save_checkpoint(self.model, version=self.version + 1)
```

## Lessons Learned
- At 1M edges, mini-batch graph training with NeighborLoader is mandatory — full-graph forward passes would need ~50GB+ VRAM for backprop
- 256-dim embeddings are the sweet spot for 12GB VRAM: 6M vectors fit in 6GB flat or 1.5GB compressed
- Gated fusion handles the cold-start problem (new nodes with no edges) gracefully
- The pathfinder's two-phase scoring (prune then rank) scales to high-degree hub nodes
- Incremental training with replay buffers means you don't need full retrains as the network grows
- The 4070 Super's 12GB is genuinely sufficient for this entire pipeline — training and inference combined

## Recommendations
- Start training at 37K edges now — don't wait for 1M. The model architecture handles scaling.
- Use `torch.compile()` (PyTorch 2.x) for ~30% training speedup on 4070S
- Set up wandb early for experiment tracking across scaling milestones
- Keep flat FAISS on SSD (NVMe preferred) for the hybrid search strategy — mmap performance depends on disk speed
- Export to ONNX + TensorRT for inference: ~3-5x speedup, reduces inference VRAM to ~0.4GB for the model
- Generate synthetic training routes by running pathfinding algorithms on the 37K graph — don't wait for human-generated routes
