# DGX Spark Memory Budget Feasibility Report: Day/Night Dual-Mode Architecture

## Context

Evaluating whether the Nemo-Maxxing Memory Architecture v3 can run on a single NVIDIA DGX Spark (128GB unified memory, 4TB NVMe, Blackwell GB10 GPU) with a day/night RAM scheduling pattern.

## Method

Researched DGX Spark hardware specs, unified memory architecture, thermal characteristics, and real-world model loading benchmarks. Cross-referenced against the architecture's memory budget assumptions.

## Result

### Hardware Specs Confirmed
- 128 GB LPDDR5x unified memory: **correct**
- 4 TB NVMe PCIe Gen5: **correct**, 12.1 GiB/s sequential read
- GB10 Blackwell GPU: 48 SMs, 6,144 CUDA cores, 1 PFLOP sparse FP4
- Memory bandwidth: 273 GB/s shared between CPU and GPU
- True unified memory — no partition. GPU has no dedicated framebuffer.

### Critical Finding 1: Nemotron 120B Memory Estimate Too Low (HIGH RISK)

The architecture budgets 64-72 GB for Nemotron 3 Super 120B-A12B in NVFP4. Real-world measurements show **77-87 GB** for the native NVFP4 checkpoint (vLLM, no MTP). The discrepancy comes from:
- Mixed-precision layers (BF16/MXFP8 for embeddings, attention projections, MTP layers)
- KV cache allocation
- CUDA runtime overhead

This shrinks nighttime headroom from ~50 GB to ~16 GB. MTP/speculative decoding would cause OOM (requires >96 GB). The 64-72 GB figure is only correct for a further-quantized GGUF Q4_K_M variant.

### Critical Finding 2: Thermal Throttling (HIGH RISK)

Multiple users including John Carmack have reported thermal throttling at ~100W (below the 140W SoC TDP), spontaneous reboots, and cascading thermal effects in the 1.13L chassis. The Acer OEM variant runs 10-14°C cooler than others. External cooling and burst scheduling (45 min on / 15 min cool) are strongly recommended for 24/7 operation.

### Critical Finding 3: GPU Bandwidth Contention (MEDIUM RISK)

When the GPU pulls ~231 GB/s for model inference, CPU memory latency degrades beyond 351 ns. Neo4j page cache hits still work, but any cache miss competes with GPU traffic. Neo4j page cache should be dynamically reduced to 8-12 GB at night (from 14 GB daytime) to free memory for the model.

### Daytime Memory Budget (Revised)

| Component | Memory (GB) |
|-----------|------------|
| OS + services | 5-8 |
| Neo4j JVM heap | 6-8 |
| Neo4j page cache | 12-16 |
| Controller model (Nano 4B Q4) | 2-3 |
| Embedding model | 1-4 |
| Reranker | 1-2 |
| **Available for OS page cache** | **87-101** |

### Nighttime Memory Budget (Revised)

| Component | Memory (GB) |
|-----------|------------|
| OS + services | 5-8 |
| Neo4j JVM heap | 6-8 |
| Neo4j page cache (reduced) | 8-12 |
| Controller model | 2-3 |
| **Nemotron 120B NVFP4 (actual)** | **77-87** |
| **Remaining headroom** | **10-20** |

### NVMe Performance
- 12.1 GiB/s sequential read (Gen5)
- 4TB sufficient for LanceDB disk-first operation
- Model load from NVMe: ~30-90 seconds for 77-87GB

## Lessons Learned

1. Always validate quantized model memory footprints with real-world benchmarks, not theoretical calculations. Mixed-precision layers and runtime overhead add 15-25% over naive parameter-count estimates.
2. Small-form-factor AI workstations have significant thermal constraints that limit sustained workloads.
3. Unified memory architectures create bandwidth contention between CPU and GPU workloads.

## Recommendations

1. **Consider Nemotron-3-Nano-30B-A3B-NVFP4 as nightly analyzer** — uses ~20 GB memory, achieves ~70 tok/s on DGX Spark (vs ~14 tok/s for 120B), eliminates nearly all memory pressure. Only use 120B if its reasoning quality is specifically required for causal inference tasks.
2. **If using 120B**: Use GGUF Q4_K_M variant (~64GB) instead of native NVFP4 (~77-87GB) to fit within budget. Accept minor quality trade-off.
3. **Thermal mitigation**: Use external cooling solution (e.g., Acer OEM chassis), implement burst scheduling with cool-down periods, monitor thermals programmatically.
4. **Dynamic Neo4j page cache**: Reduce from 14GB to 8-12GB during nighttime inference to free headroom.
5. **Validate embedding model name**: "llama-embed-nemotron-reasoning-3b" does not match any known NVIDIA model. Use llama-nemotron-embed-1b-v2 or omni-embed-nemotron-3b.
