# Think Tank Debate: 7 Coordination Strategies Benchmarked (External Research)

## Context
KB-0027 identified hierarchical lead-distribute as the practical winner (10.4x) among 8 internally-designed strategies. This experiment brought in 5 additional strategies inspired by external CS research literature to determine if better approaches exist. Five think tank teams (Theory, Systems, Challenger, Synthesis, Validation) debated proposals before benchmarking.

## Method
5 think tank teams with specialized roles:
- **TT-A (Theory, 3 agents)**: Proposed Chase-Lev deques and Contract Net Protocol
- **TT-B (Systems, 3 agents)**: Proposed Go-style local queues, Two-Level scheduling, Backoff+Jitter
- **TT-C (Challenger, 2 agents)**: Challenged each proposal with counterarguments
- **TT-D (Synthesis, 2 agents)**: Identified cross-cutting insights and recommended hybrids
- **TT-E (Validation, 3 agents)**: Ran benchmarks (500 items, 10 workers, 1ms/item)

### New Strategies from External Research

| # | Strategy | Source | Description |
|---|----------|--------|-------------|
| 1 | Chase-Lev Deques | Chase & Lev 2005, Cilk-5 | Per-worker deques, round-robin init, random victim stealing |
| 2 | Contract Net Protocol | Smith 1980, FIPA | Coordinator announces batches, workers bid on capacity |
| 3 | Go-Style Local Queues | Go GMP model, Vyukov 2013 | Local queue → global fallback → peer stealing |
| 4 | Two-Level Scheduling | Spark, Dask schedulers | Sub-team partitioning with locality-aware stealing |
| 5 | Backoff+Jitter+Batch | AWS Architecture, Brooker 2015 | Batch steal + exponential backoff + random jitter |

### Key Debate Points

1. **TT-C challenged Chase-Lev**: Requires all work known upfront; can't handle dynamic work injection. Valid concern for real AI agent workloads.
2. **TT-C endorsed Go-Style**: Handles dynamic work via global queue while keeping hot path lock-free. Battle-tested at Google scale.
3. **TT-C questioned Two-Level**: Without NUMA nodes or data locality, "sub-teams" are just pre-partitioning with extra steps.
4. **TT-D synthesis**: The key insight is **separating WORK STORAGE (SQLite, durable) from WORK DISTRIBUTION (in-memory, fast)**. All top strategies avoid SQLite in the hot path.

### TT-D Recommended Hybrid Architecture

1. Keep SQLite as durable work store (persistence, crash recovery)
2. Add LeadDistributor that batch-steals into in-memory Go-style multi-queue dispatcher
3. Workers pull from local queue (O(1), no contention)
4. Empty workers steal from peers before going back to lead
5. Dynamic work goes to lead's buffer, not directly to SQLite

## Lessons Learned

1. **Top 4 strategies are statistically tied** (8,400-8,800/s). The differentiator is not raw throughput but dynamic work handling and fault tolerance.

2. **The universal principle**: Move the hot path out of SQLite. Whether you use hierarchical lead, Chase-Lev, Go-style, or two-level, the key is that workers never touch SQLite directly. The ~10x improvement ceiling is the cost of SQLite serialization.

3. **Contract Net Protocol is viable but slower** (8.1x). The bidding mechanism adds latency but provides heterogeneous worker support. Useful when agents have different capabilities.

4. **Backoff+Jitter alone is insufficient** (2.4x). Reducing contention on SQLite helps, but you can't patch around the fundamental bottleneck—you must eliminate it from the hot path.

5. **Dynamic work is the real differentiator**. Chase-Lev and pre-partition are fastest but can't handle work discovered mid-execution. Go-style and hierarchical handle dynamic work gracefully.

## Recommendations

### Implementation Priority

1. **Implement hierarchical lead + in-memory dispatch** (KB-0027's winner, confirmed here at 9.4x). It's the simplest architecture that handles dynamic work.

2. **Add batch steal method** to `WorkStealing` class as an immediate improvement (no architecture change needed, ~5x improvement).

3. **For future work**: Consider Go-style local queues if sub-millisecond scheduling latency becomes important. The three-tier approach (local → global → steal) is the most robust for production.

### What NOT to Implement

4. **Skip pure Chase-Lev** for production. It's marginally faster but can't handle dynamic work injection, which is fundamental to AI agent coordination.

5. **Skip Contract Net** unless heterogeneous agents are needed. The bidding overhead is unnecessary for identical workers.

6. **Skip Backoff+Jitter as standalone**. It should be a component of other strategies (add jitter to the lead's SQLite batch-steal), not a strategy itself.
