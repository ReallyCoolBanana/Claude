# Vulkan API Libraries: Comprehensive Catalog

## Context
Building on KB-0029's Vulkan architecture research, this entry catalogs the essential libraries in the Vulkan ecosystem — initialization, memory, math, windowing, shader compilation, asset loading, and debugging.

## Method
Web research across GitHub repos, Khronos documentation, vkguide.dev, and vulkan-tutorial.com. Libraries evaluated for maturity, license, and adoption.

## Result

### Tier 1: Essential Libraries (use in every project)

#### vk-bootstrap
- **Purpose**: Automates Vulkan instance, physical device, logical device, and swapchain creation
- **Language**: C++14
- **License**: MIT
- **GitHub**: [charles-lunarg/vk-bootstrap](https://github.com/charles-lunarg/vk-bootstrap)
- **Integration**: Header-only option or CMake subdirectory
- **Key Features**: Auto-enables validation layers in debug, selects best physical device, handles extension negotiation
- **Usage**: Eliminates ~300 lines of boilerplate initialization code

#### VMA (Vulkan Memory Allocator)
- **Purpose**: GPU memory allocation with sub-allocation, defragmentation, and budget tracking
- **Author**: AMD GPUOpen
- **Language**: C/C++ (header-only, single file)
- **License**: MIT
- **GitHub**: [GPUOpen-LibrariesAndSDKs/VulkanMemoryAllocator](https://github.com/GPUOpen-LibrariesAndSDKs/VulkanMemoryAllocator)
- **Key Features**: `VMA_MEMORY_USAGE_AUTO` for optimal memory type selection, dedicated allocations for large resources, memory budget via `VK_EXT_memory_budget`
- **Usage**: Used by most Vulkan game titles. Call `vmaCreateAllocator()` once, then `vmaCreateBuffer()`/`vmaCreateImage()` instead of raw Vulkan calls

#### GLM (OpenGL Mathematics)
- **Purpose**: Linear algebra — vectors, matrices, quaternions, transforms
- **Language**: C++17 (header-only)
- **License**: MIT / Happy Bunny
- **GitHub**: [g-truc/glm](https://github.com/g-truc/glm)
- **Key Features**: GLSL-compatible types (`glm::mat4` ↔ `mat4`), SIMD via `GLM_FORCE_INTRINSICS`, depth range config via `GLM_FORCE_DEPTH_ZERO_TO_ONE` (required for Vulkan)
- **Vulkan Setup**:
  ```cpp
  #define GLM_FORCE_RADIANS
  #define GLM_FORCE_DEPTH_ZERO_TO_ONE
  #include <glm/glm.hpp>
  #include <glm/gtc/matrix_transform.hpp>
  ```

#### Volk
- **Purpose**: Meta-loader for Vulkan function pointers (avoids linking to Vulkan loader)
- **Language**: C (single header + source)
- **License**: MIT
- **GitHub**: [zeux/volk](https://github.com/zeux/volk)
- **Usage**: Call `volkInitialize()` at startup, then use Vulkan functions directly. Bundled in LunarG SDK

### Tier 2: Windowing & Input

#### GLFW
- **Purpose**: Window creation, input handling, Vulkan surface creation
- **Language**: C
- **License**: zlib/libpng
- **GitHub**: [glfw/glfw](https://github.com/glfw/glfw)
- **Platforms**: Windows, Linux, macOS
- **Vulkan**: `glfwCreateWindowSurface()` creates VkSurfaceKHR. `glfwVulkanSupported()` checks availability
- **Key Features**: Keyboard/mouse/gamepad input, multiple monitors, fullscreen

#### SDL3 (Simple DirectMedia Layer)
- **Purpose**: Window, input, audio, gamepad, haptic, networking
- **Language**: C
- **License**: zlib
- **GitHub**: [libsdl-org/SDL](https://github.com/libsdl-org/SDL)
- **Platforms**: Windows, Linux, macOS, Android, iOS, and more (broadest support)
- **Vulkan**: `SDL_Vulkan_CreateSurface()` creates VkSurfaceKHR
- **Key Features**: Broader platform support than GLFW, built-in audio, gamepad database

**Recommendation**: GLFW for simple rendering demos; SDL for full applications needing audio/gamepad/mobile.

### Tier 3: Shader Compilation

#### glslc (via Shaderc)
- **Purpose**: GLSL → SPIR-V compiler (Google)
- **Language**: C++
- **License**: Apache 2.0
- **GitHub**: [google/shaderc](https://github.com/google/shaderc)
- **Usage**: `glslc shader.vert -o shader.vert.spv`
- **Key Features**: GCC-like CLI flags, `#include` support, bundled in Vulkan SDK and Android NDK
- **Runtime API**: `shaderc` library enables runtime shader compilation

#### SPIRV-Cross
- **Purpose**: SPIR-V reflection and cross-compilation (SPIR-V → GLSL/MSL/HLSL)
- **Language**: C++
- **License**: Apache 2.0
- **GitHub**: [KhronosGroup/SPIRV-Cross](https://github.com/KhronosGroup/SPIRV-Cross)
- **Key Features**: Produces human-readable output, used by MoltenVK for SPIR-V → MSL conversion

#### DXC (DirectX Shader Compiler)
- **Purpose**: HLSL → SPIR-V compiler (Microsoft)
- **Usage**: `dxc -spirv -T vs_6_0 -E main shader.hlsl -Fo shader.spv`
- **Key Features**: Supports HLSL Shader Model 6.x, `-spirv` flag enables Vulkan output

### Tier 4: Asset Loading

#### stb_image
- **Purpose**: Image loading (PNG, JPG, BMP, TGA, HDR)
- **Language**: C (single header)
- **License**: Public domain / MIT
- **GitHub**: [nothings/stb](https://github.com/nothings/stb)
- **Usage**: `stbi_load("texture.png", &w, &h, &channels, STBI_rgb_alpha)` → upload to VkImage via staging buffer
- **Note**: Always use `STBI_rgb_alpha` for Vulkan compatibility (4-channel RGBA)

#### tinyobjloader
- **Purpose**: OBJ/MTL mesh loading
- **Language**: C++ (single header)
- **License**: MIT
- **GitHub**: [tinyobjloader/tinyobjloader](https://github.com/tinyobjloader/tinyobjloader)
- **Key Features**: Auto-triangulation, materials support, fast parsing
- **Caveat**: Use `uint32_t` indices for models with >65K vertices

#### tinygltf
- **Purpose**: glTF 2.0 model loading (modern alternative to OBJ)
- **Language**: C++ (header-only)
- **License**: MIT
- **Key Features**: PBR materials, skeletal animation, multiple meshes, binary glTF (GLB)

### Tier 5: Higher-Level Frameworks

| Framework | Description | License |
|-----------|-------------|---------|
| **The-Forge** | Cross-renderer (Vulkan/DX12/Metal) | Apache 2.0 |
| **Tephra** | C++17 Vulkan abstraction layer | MIT |
| **Vulkan Launchpad** | Educational Vulkan framework | MIT |
| **VKFS** | Quick Vulkan environment setup | MIT |

### Recommended Stack for a New Vulkan Project

```
Initialization:  vk-bootstrap + volk
Memory:          VMA
Math:            GLM (with GLM_FORCE_DEPTH_ZERO_TO_ONE)
Windowing:       GLFW (desktop) or SDL3 (cross-platform)
Shaders:         glslc (offline) or shaderc (runtime)
Textures:        stb_image
Models:          tinyobjloader (simple) or tinygltf (complex)
Debugging:       Validation layers + RenderDoc
```

All libraries above are header-only or single-file, MIT/Apache licensed, and compatible with CMake via `add_subdirectory()` or FetchContent.

## Lessons Learned

1. **Header-only libraries dominate** the Vulkan ecosystem — integration is as simple as copying a header file
2. **VMA is non-negotiable** — raw Vulkan memory management hits the 4096-allocation limit quickly
3. **GLM requires Vulkan-specific defines** — `GLM_FORCE_DEPTH_ZERO_TO_ONE` is essential (Vulkan uses [0,1] depth, not [-1,1])
4. **glslc is the standard shader compiler** — bundled in SDK, NDK, and shaderc; GCC-like flags make build integration easy
5. **GLFW vs SDL**: GLFW is lighter (just window+input), SDL is heavier but includes audio/gamepad/networking

## Recommendations

1. For any new Vulkan project, install the LunarG Vulkan SDK (includes glslc, validation layers, volk, GLM, VMA, SDL3)
2. Use vk-bootstrap for initialization — it saves ~300 lines and handles device selection correctly
3. Integrate VMA from day one — retrofitting memory management is painful
4. Pre-compile shaders with glslc in the build system (CMake custom commands or Makefile rules)
5. For 3D models, prefer glTF over OBJ for new projects (better material/animation support)
