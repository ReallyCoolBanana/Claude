# Multi-Agent Communication Prototype: Dual Implementation & Test Results

## Executive Summary

Two competing prototypes were built, tested, and hardened through 3 fix iterations:

- **Prototype A** (JSONL + SQLite WAL): 1,437 lines, durability-first design
- **Prototype B** (Named pipes + mmap): 1,855 lines, speed-first design

Both pass all 113 tests after fixes. Prototype A proved more robust out-of-the-box (0 new bugs in deep stress testing). Prototype B had 7 integration bugs requiring fixes.

## Architecture Comparison

| Aspect | Prototype A | Prototype B |
|--------|-------------|-------------|
| **Message Bus** | JSONL append-only files, O_APPEND atomic | Named pipes (FIFOs) + spillover files |
| **Shared State** | SQLite WAL, BEGIN IMMEDIATE | mmap'd fixed-size struct + fcntl.flock |
| **Coordinator** | Thread-per-concern, polling loops | select()-based event loop on FIFOs |
| **Thread Safety** | `check_same_thread=False` + `threading.Lock` | `threading.Lock` + `fcntl.flock` combo |
| **Crash Recovery** | SQLite WAL auto-recovery | mmap file persists, but no journal |
| **Max Agents** | Unlimited (SQLite rows) | 32 (fixed mmap slots) |

## Bugs Found and Fixed

### Prototype A — 3 bugs, 2 fix iterations
1. SQLite `check_same_thread=True` blocks cross-thread use → added Lock + disabled check
2. /tmp path not rejected during validation → fixed `_check_no_tmp()`
3. Root user perm check bypasses `os.access()` → check `st_mode & 0o200`

### Prototype B — 7 bugs, 1 fix iteration
1. PB-001/002: `register()` vs `register_agent()` API mismatch
2. PB-003: AgentSlotView treated as dict instead of dataclass
3. PB-004: Missing `get_heartbeat()` method
4. PB-005: No-op lock in `_init_header()`
5. PB-006: Tautological canonical path check
6. PB-007: `fcntl.flock` ineffective for threads

## Test Results: 113/113 PASSED

- 28 regression tests (all 26 KB-0017 failure modes)
- 23 deep stress tests (flood, contention, churn, multi-channel)
- 62 Prototype B functional + integration tests

## Key Findings

1. **SQLite > mmap for correctness**: BEGIN IMMEDIATE transaction isolation is fundamentally more robust than manual mmap locking
2. **Parallel development creates integration bugs**: API mismatches between modules built concurrently
3. **POSIX atomic writes are reliable**: Zero message corruption under concurrent stress (under 4096 bytes)
4. **Thread safety requires explicit attention**: Both prototypes needed fixes for cross-thread access

## Recommendation

**Prototype A (JSONL + SQLite) for production.** More correct, better tested, simpler to reason about, more extensible. Reserve mmap approach for 50+ agent optimization.
