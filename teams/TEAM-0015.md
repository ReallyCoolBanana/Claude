# Team Session Log

## Objective
Research and document the technical foundations for using JSONL (JSON Lines) files as a message bus for live inter-agent communication, covering POSIX guarantees, file watching, schema design, concurrency, performance, and practical usage patterns.

## Approach
1. Conducted web research on six core topics: POSIX atomic writes, file watching patterns, JSONL best practices, concurrency edge cases, performance characteristics, and agent usage patterns.
2. Consulted primary sources including POSIX specifications, Linux man pages, empirical testing blogs, and library documentation.
3. Synthesized findings into a single comprehensive knowledge base entry with code examples ready for implementation.

## Decisions Made
- Recommended polling (100-200ms) over inotify for simplicity and zero dependencies in agent systems.
- Set 4096-byte message limit as the safe atomic write threshold (PIPE_BUF on Linux).
- Recommended `os.open()` + `os.write()` over buffered I/O to ensure single-syscall writes.
- Recommended epoch-based file rotation over rename-based rotation to avoid race conditions.
- Recommended no fsync for ephemeral agent messages (page cache durability is sufficient).
- Designed channel organization: global, per-team, and per-topic JSONL files.
