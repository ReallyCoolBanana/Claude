## Proto A Components Used
- **JSONL Bus**: 6 channels (global, research-findings, think-tank-findings, dev-progress, archive-status, phase-signals)
- **SQLite WAL**: AgentReporter (16 agents), CoordinatorDashboard, WorkStealing, PipelineManager, Scratchpad, HelpProtocol, DirectChannels
- **PipelineManager**: 2 pipelines (one per iteration), 5 stages each with dependency enforcement
- **WorkStealing**: Atomic work item claiming across teams, priority-ordered queue
- **Scratchpad**: Cross-team data sharing (implementations, test results, bugs, fixes, archive)
- **DirectChannels**: 4 topic channels, 6 direct channels, presence tracking, progress broadcasting
- **HelpProtocol**: Capability registration for all 8 teams, idle detection

## Approach
1. Created SOP-025 defining the 5-stage pipeline (research_and_plan → programming → testing → bug_fixing → convergence_and_archive)
2. Built TEAM-0022-pipeline.py — a coordinator that initializes all Proto A primitives and runs 8 teams through the pipeline
3. Ran 2 complete iterations

## Results per Iteration

- **Stage 4 (Bug Fixing)**: dev-fix resolved all 3 bugs. Research-ext-2 provided fix strategies. Think Tank Beta re-verified.

### Iteration 2

- Final recommendation: pipeline_complete.

## Decisions Made
1. **SOP-025 defines pipeline stages with dependency gates** — PipelineManager enforces stage ordering, preventing premature advancement.
2. **Work items categorized by stage** — programming vs testing vs bug-fix, allowing teams to steal only relevant work.
3. **Scratchpad for cross-stage data flow** — implementations from Stage 2 available to Stage 3 testers without bus message size limits.
4. **Safety limits on work stealing loops** — max 20 steals per stage to prevent infinite re-enqueue cycles.
5. **get_ready_stages() called before start_stage()** — necessary to promote "waiting" stages to "ready" status.

## Bugs Found in Proto A Usage
1. **Scratchpad API signature** (key, value, namespace, ttl) — different from what KB-0027 documented as (namespace, key, value, ttl_seconds).
2. **DirectChannels.set_presence** not `update_presence` — API name mismatch in documentation.
3. **DirectChannels.update_progress** not `broadcast_progress` — API name mismatch.
4. **PipelineManager requires team+agent_id** in constructor — not documented in initial exploration.
5. **Stage promotion requires explicit get_ready_stages() call** — complete_stage() does NOT auto-promote downstream stages.
