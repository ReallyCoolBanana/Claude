## Decisions Made
1. **Hub-and-spoke architecture for agent monitoring** — AgentReporter (spoke) writes status to shared SQLite table; CoordinatorDashboard (hub) reads all statuses and sends instructions. Agents cannot see each other's entries; coordinator mediates all cross-agent communication.
2. **SQLite over per-agent JSON files** — Think tank recommended per-agent JSON files, but implementation chose SQLite with WAL mode for consistency with existing Proto A patterns (help_protocol, direct_channels, work_stealing all use SQLite).
3. **Anti-sequential as default** — All teams run simultaneously by default. Sequential execution requires proven hard data dependency (SOP-011 ASR rules). User had to correct the coordinator's initial wave-based plan.
4. **Reassign completed teams** — User directive: when a team finishes early, reassign it to help remaining teams rather than letting it sit idle.
5. **Input validation added across all modules** — Status fields, priority fields, and authorization checks added based on think tank bug analysis.
6. **Bus notifications made fire-and-forget** — Bus write failures no longer crash callers after DB commit succeeds (BUG-HP-001 fix pattern applied to coordinator_hub.py as well).

### New Module: coordinator_hub.py
- **AgentReporter** — Used by agents to post status to shared hub. Methods: `update_status()`, `report_error()`, `report_complete()`, `check_instructions()`. Validates status against frozenset. Includes fire-and-forget bus notifications.
- **CoordinatorDashboard** — Used by coordinator to monitor all agents. Methods: `get_all_status()`, `get_active_agents()`, `get_blocked_agents()`, `get_completed_agents()`, `get_agent_status()`, `send_instruction()`, `get_summary()`. Returns aggregate metrics (total, active, blocked, complete, error, avg_progress).
- Schema: `agent_status` table (12 columns) + `coordinator_instructions` table (7 columns) with indexes.
- Follows Proto A patterns: SQLite WAL mode, BEGIN IMMEDIATE, threading.Lock, _retry_on_busy decorator.

## Critical Findings

### From Think Tank Hub:
1. **Layered architecture recommended** — Hub-spoke (Layer 1) for coordinator visibility + direct channels (Layer 2) for agent collaboration + scratchpad (Layer 3) for shared data + fire-and-forget (Layer 4) for trivial tasks. Not mutually exclusive.
2. **Anti-sequential root causes identified** — 6 causes: risk aversion without visibility (SEQ-001), causal dependency assumption (SEQ-002), simpler mental model (SEQ-003), past merge conflicts (SEQ-004), completion dependency illusion (SEQ-005), no partial result consumption (SEQ-006).
3. **Hub-spoke enables parallel execution** — Visibility into agent progress eliminates the need for sequential waves as a safety measure. The coordinator can launch all agents simultaneously and intervene when issues arise.

### From Think Tank Bugs (help_protocol.py):
1. **3 critical bugs**: Bus crashes callers (BUG-HP-001), TOCTOU race in auto_assign (BUG-HP-002), double-assignment of same helper (BUG-HP-003)
2. **5 high-severity issues**: No status validation (BUG-HP-004), no authorization on fulfill_help (BUG-HP-005), no closed-state tracking (BUG-HP-006), self-help allowed (BUG-HP-007), no zombie work item recovery (BUG-HP-008)
3. **5 medium issues**: Empty list falsy evaluation (BUG-HP-009), no work_item_id validation (BUG-HP-010), no ownership check on complete_work_item (BUG-HP-011), no priority validation (BUG-HP-012), capability fallback too permissive (BUG-HP-013)

### From SOPs:
1. **Hard Dependency Test** (SOP-011) — "Does Task B require a specific computed artifact that only Task A can produce, AND that artifact does not exist yet?" If no, run in parallel.
2. **Anti-Sequential Rules** — 10 explicit rules (ASR-001 through ASR-010) with violation examples and correct behavior patterns.
3. **5-Checkpoint Polling** (SOP-012) — Post-launch (30-60s), early progress (5-10min), mid-session (30-50%), completion wave (first finish), final gathering (all done).
